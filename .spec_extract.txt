## 26. Executive Architecture Summary

### Current state (verified)

| Aspect | Today |
|--------|-------|
| Primitives | Single file: `src/components/ui/Modal.tsx` exports `Modal` + `Drawer` |
| Portal | **None** — all overlays render in-place |
| Layout | Modal: `overflow-hidden`, no `max-height`, no scroll body; Drawer: `flex-1 overflow-y-auto` |
| A11y | Focus trap on Modal only; Drawer/custom modals lack it |
| Implementations | **3 parallel patterns**: shared Modal, shared Drawer, 4 inline custom modals |
| Reference impl | `PhoneInput` CountryPicker — grid scroll, `dvh`, `useFocusTrap` (local, not shared) |
| Draft | Config studio only (`useConfigurationDraft`); dialog forms use ephemeral `useState` |
| Tests/Storybook | **0** Storybook stories; **1** RTL modal test (`StaffInviteModal`) |

### Target state

A **layered overlay platform** under `src/components/ui/overlay/` with:

- One provider stack at app root
- Composable primitives (`Modal`, `Drawer`, `BottomSheet`, `WizardShell`, `ConfirmDialog`)
- Shared managers (focus, scroll lock, stack, portal, animation)
- Feature teams build **forms inside shells**, never custom `fixed inset-0` markup
- Draft and unsaved-guard as opt-in hooks, not per-page reinvention

### What gets removed

- Inline `PromotionModal`, `RewardModal`, `ReplyModal`, `VendorFormModal` in page files
- Dead `NotificationDrawer.tsx` (zero app imports)
- Layout hacks: `FoodDetailModal` `!p-0` + partial `max-h`; CommandPalette `-m-6`
- Duplicate focus/scroll logic in `Modal.tsx` vs `PhoneInput.tsx`

### What stays (refactored)

- `Modal` and `Drawer` names and import paths (via re-exports for backward compatibility)
- Feature-specific form components (`MenuItemFormFields`, `StaffRoleBranchFields`, etc.)
- React Query mutation hooks — unchanged contract

## 1. Target Architecture Overview

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Application Root                                 │
│  <OverlayProvider>                                                       │
│    <DraftProvider>          ← optional, scoped to long forms             │
│      {children}                                                          │
│    </DraftProvider>                                                      │
│  </OverlayProvider>                                                      │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
  PortalManager              OverlayStackManager           AnimationProvider
  (document.body)            (z-index, ESC routing)        (tokens, reduced motion)
        │                           │
        └───────────┬───────────────┘
                    ▼
         ┌──────────────────────────────────────┐
         │         Shell Components              │
         │  Modal │ Drawer │ BottomSheet        │
         │  FullscreenDialog │ ConfirmDialog     │
         │  AlertDialog │ WizardShell            │
         └──────────────────────────────────────┘
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
   Layout Slots           Feature Content
   Header/Body/Footer     Forms, lists, custom UI
         │
         ▼
   Managers (via hooks)
   FocusManager │ ScrollLockManager │ KeyboardManager
```

**Design principle:** Shells own **presentation + interaction**; features own **data + validation + mutations**.

## 4. Component Responsibility Matrix

| Component | Purpose | Owns | Does NOT own |
|-----------|---------|------|--------------|
| **OverlayProvider** | App-level overlay context | Portal root, stack registration, reduced-motion preference | Form state, API calls |
| **PortalManager** | Render overlays at `document.body` | DOM mount point, SSR guard | Layout, animations |
| **OverlayStackManager** | LIFO stack of open overlays | z-index assignment, top-only ESC | Focus logic (delegates) |
| **Modal** | Centered/bottom-sheet dialog shell | Open/close, backdrop, surface, layout slots | Validation, mutations |
| **Drawer** | Side panel shell | Slide animation, full-height scroll | Business content |
| **BottomSheet** | Mobile sheet variant | `dvh`, drag handle, keyboard safe area | Desktop layout (delegates to Modal) |
| **FullscreenDialog** | Full viewport takeover | `100dvh` surface, sticky chrome | Wizard step logic |
| **ConfirmDialog** | Destructive/neutral confirm | Preset copy, two-button footer, `closeOnOverlay=false` | Custom forms |
| **AlertDialog** | Info/alert | Single action | Form inputs |
| **WizardShell** | Multi-step orchestration | Step index, nav, progress, per-step validation gate | Field definitions |
| **WizardStep** | Step content wrapper | Step id, title, optional description | Submit logic |
| **ProgressIndicator** | Step progress UI | Visual only | State |
| **ModalHeader/Body/Footer** | Layout slots | Sticky regions, padding tokens | Content |
| **FocusManager** | Focus trap + restore | Tab cycling, initial focus, restore target | Rendering |
| **ScrollLockManager** | Body scroll lock | Ref-counted `overflow: hidden` | Overlay scroll |
| **KeyboardManager** | Global shortcut routing | ESC to top overlay only | Feature shortcuts |
| **AccessibilityLayer** | ARIA wiring | `role`, `aria-modal`, `aria-labelledby`, live regions | — |
| **DraftManager** | Client draft persistence | sessionStorage read/write, TTL, keys | Server sync |
| **AnimationProvider** | Motion config | Springs, durations, reduced-motion overrides | — |
| **ResponsiveLayout** | Breakpoint strategy | Modal vs BottomSheet vs Fullscreen selection | — |

## 6. Overlay Lifecycle Specification

```
CREATE (React mount, open=false)
  │  Responsibility: Provider assigns overlayId; no portal render yet
  ▼
OPEN (open=true)
  │  OverlayStackManager.push(id)
  │  ScrollLockManager.acquire()
  │  PortalManager renders surface
  ▼
ENTER ANIMATION
  │  AnimationProvider applies enter tokens (or skip if reduced motion)
  ▼
FOCUS
  │  FocusManager: save document.activeElement
  │  FocusManager: focus first focusable (or initialFocusRef)
  │  AccessibilityLayer: aria-modal=true, label wiring
  ▼
INTERACTION
  │  User edits form / navigates wizard steps
  │  KeyboardManager: Tab trap, ESC → onClose (if allowed)
  │  ScrollLockManager: body locked; ONLY OverlayBody scrolls
  │  DraftManager: optional persist on change (debounced)
  ▼
VALIDATION (on step next or submit)
  │  Feature layer: Zod/manual validate
  │  Errors rendered in OverlayBody; focus first invalid field
  ▼
SUBMIT (optional)
  │  Feature: React Query mutation
  │  Footer: loading state, disable actions
  │  On error: keep open, show inline/toast error
  ▼
CLOSE REQUEST (success / cancel / ESC / overlay)
  │  useUnsavedChanges: confirm if dirty (forms/wizards)
  ▼
EXIT ANIMATION
  │  AnimatePresence exit
  ▼
CLEANUP
  │  FocusManager.restore()
  │  ScrollLockManager.release()
  │  OverlayStackManager.pop(id)
  │  DraftManager.clear() on success only
  ▼
UNMOUNT (open=false after exit)
```

| Stage | Owner |
|-------|-------|
| Stack push/pop | OverlayStackManager |
| Body scroll | ScrollLockManager |
| Trap/release focus | FocusManager |
| ESC routing | KeyboardManager → top of stack only |
| Dirty guard | useUnsavedChanges (feature opts in) |
| Mutation | Feature hooks (unchanged) |

## 7. State Architecture

| State type | Owner | Storage | Lifetime |
|------------|-------|---------|----------|
| Open/closed | Feature page or `useOverlay` | `useState` | Per dialog instance |
| Form field values | Feature form | `useState` / RHF / `useFormDraft` | Until submit or discard |
| Wizard step index | WizardShell context | React context inside shell | Until close |
| Wizard form aggregate | WizardShell | `useState` + optional `useFormDraft` | Until submit |
| Overlay stack | OverlayStackManager | React context (provider) | App session |
| z-index | OverlayStackManager | Computed from stack position | Per open cycle |
| Focus restore target | FocusManager | Ref in hook closure | Per open cycle |
| Scroll lock count | ScrollLockManager | Module ref counter | Per open overlay |
| Draft persistence | DraftManager | sessionStorage | TTL-based |
| Server data | React Query | Query cache | Invalidated on mutation success |
| Cart | Zustand | `useCartStore` | Unchanged |

**Rules:**
- Overlay shells hold **zero business data**
- WizardShell holds **orchestration state only** (step, aggregate data pointer)
- Never put form state in OverlayProvider
- React Query cache is **not** used for drafts

```

    └── FeatureForm                      ← max ~200 lines
        └── FormSection[]                ← logical groups
```

## 10. Draft Architecture

### Storage

| Layer | Technology | Scope |
|-------|------------|-------|
| Client draft | `sessionStorage` via `draft-storage.ts` | Per-tab, per-user session |
| Server state | React Query | Authoritative after save |
| Config studio | `useConfigurationDraft` (existing) | In-memory only; **not** merged into overlay draft system in v1 |

### Keys

```
samoon:draft:{version}:{feature}:{scope}:{id?}
```

Examples:
- `samoon:draft:1:menu-item:create:branch-abc123`
- `samoon:draft:1:menu-item:edit:item-xyz789`
- `samoon:draft:1:branch:create:tenant-abc`

**Scope** = tenantId + branchId where applicable (prevent cross-tenant leakage).

### Envelope format

```typescript
interface DraftEnvelope<T> {
  version: number
  key: string
  data: T
  createdAt: number
  updatedAt: number
  expiresAt: number
}
```

### Expiration

- Default TTL: **7 days** (`expiresAt = updatedAt + 7d`)
- On read: discard if `Date.now() > expiresAt`
- Cleanup on app init: sweep keys matching `samoon:draft:*`

### Recovery

1. User opens create/edit overlay
2. `useFormDraft` finds valid envelope
3. `ConfirmDialog`: "You have unsaved changes from [date]. Resume or start fresh?"
4. Resume → hydrate form; Fresh → `clearDraft()`

### Versioning

- `version` in envelope; on mismatch, discard draft (no auto-migrate in v1)
- Bump version when form shape changes

### Conflict resolution

- **Client-only drafts:** Last write wins within tab
- **Edit entity while draft exists:** Draft keyed by entity id; server data loaded separately; user chooses resume vs server state
- **No multi-tab sync** in v1 (sessionStorage is per-tab)

### Security

- Never store auth tokens, PII beyond form fields, or payment data in drafts
- Keys scoped by tenant/branch id
- Clear all drafts on logout (`authStore` listener)

### Ownership

| Owner | Responsibility |
|-------|----------------|
| `lib/overlay/draft-storage.ts` | Read/write/clear/TTL |
| `hooks/overlay/useFormDraft.ts` | React binding, debounced persist |
| Feature form | Defines `T` shape and key |
| WizardShell | Optional `onDraftChange` callback |

## 11. Shared Layout Specification

### Standard shell anatomy

```
┌─────────────────────────────────────┐
│ ModalHeader (sticky, shrink-0)      │  px-6 pt-6 pb-4
├─────────────────────────────────────┤
│ ModalBody (flex-1, overflow-y-auto) │  px-6 py-4
│   ... scrollable content ...        │
├─────────────────────────────────────┤
│ ModalFooter (sticky, shrink-0)      │  px-6 pb-6 pt-4, border-t
│   [Cancel]              [Save]      │
└─────────────────────────────────────┘
```

### Tokens (see Section 15)

| Region | Padding | Border |
|--------|---------|--------|
| Header | `px-6 pt-6 pb-4` | `border-b border-[var(--border)]` when footer exists |
| Body | `px-6 py-4` | — |
| Footer | `px-6 pb-6 pt-4` | `border-t border-[var(--border)]` |

### Grid

- Default form grid: `grid grid-cols-1 sm:grid-cols-2 gap-4`
- Full-width fields: `sm:col-span-2`
- Dense tables inside modal: single column on mobile

### States

| State | Location | Pattern |
|-------|----------|---------|
| Loading | Body center or skeleton | `Loader2` + `aria-busy` |
| Empty | Body center | Reuse `EmptyState` |
| Error (field) | Below field | `text-destructive text-sm` |
| Error (submit) | Footer top or Alert in body | Inline banner, focus on error |
| Success | Toast (sonner/existing) + close overlay | — |

### Sticky regions

- Header and Footer: `shrink-0` inside `flex flex-col max-h-[var(--overlay-max-h)]`
- Body: `flex-1 min-h-0 overflow-y-auto` (critical — fixes current `Modal.tsx` defect)

### Scroll containers

- **Exactly one** vertical scroll region per overlay: `ModalBody`
- Forbidden: nested `overflow-y-auto` inside body without explicit design reason

## 12. Responsive Specification

### Breakpoints (align with Tailwind defaults)

| Name | Min width | Overlay behavior |
|------|-----------|------------------|
| Mobile | `< 640px` | BottomSheet or full-width centered modal |
| Tablet | `640–1024px` | Centered modal, `max-w-*` |
| Laptop | `1024–1280px` | Centered modal |
| Desktop | `≥ 1280px` | Centered modal, larger max-width |

### Per-component rules

| Component | Mobile | Tablet+ |
|-----------|--------|---------|
| Modal `sm/md` | BottomSheet `max-h-[90dvh]` | Centered |
| Modal `lg/xl` | Fullscreen or `95dvh` bottom sheet | Centered |
| Drawer | Bottom sheet (`side=bottom`) | Side drawer (`left`/`right`) |
| CartDrawer | Bottom (existing) | Right (existing) |
| FoodDetailModal | Fullscreen bottom sheet | Centered `xl` |
| Wizard | Fullscreen | `xl` or `fullscreen` |

### Viewport units

- Use **`dvh`** not `vh` for max-height (keyboard-safe; proven in `PhoneInput.tsx`)
- `--overlay-max-h: min(90dvh, calc(100dvh - env(safe-area-inset-top) - env(safe-area-inset-bottom) - 2rem))`

### Keyboard safe areas

- `useVisualViewport` hook (extracted from PhoneInput) adjusts bottom sheet when virtual keyboard opens
- Footer actions remain visible or scroll into view

### Landscape / short viewports

- If `visualViewport.height < 500px`: force fullscreen layout
- Reduce header padding; compact progress indicator

### Fullscreen rules

- Checkout, tenant wizard, branch wizard: full-page routes — not modal shells
- Mobile food detail: `FullscreenDialog` or BottomSheet at `95dvh`

## 13. Accessibility Specification

### Mandatory (all overlays)

| Requirement | Standard |
|-------------|----------|
| Focus trap | Tab cycles within overlay; implemented via shared `useFocusTrap` |
| Focus restore | Return focus to trigger element on close |
| ESC | Close top overlay only if `closeOnEscape` |
| `role` | `role="dialog"` on surface |
| `aria-modal` | `aria-modal="true"` |
| Labeling | `aria-labelledby` → header id; `aria-describedby` → description |
| Initial focus | First input or close button (configurable `initialFocusRef`) |
| Scroll lock | Body `overflow: hidden` while open |
| Touch targets | Minimum **44×44px** for interactive elements |

### Keyboard navigation

| Key | Action |
|-----|--------|
| Tab / Shift+Tab | Cycle focus within trap |
| ESC | Close (top overlay) |
| Enter | Submit primary action in ConfirmDialog only |

### Screen readers

- Step changes in wizard: `aria-live="polite"` region announces "Step 2 of 6: Pricing"
- Loading: `aria-busy="true"` on form during submit
- Errors: `role="alert"` on submit error banner

### Reduced motion

- Respect `prefers-reduced-motion: reduce`
- Skip scale/spring; use opacity-only ≤150ms
- `AnimationProvider` reads preference once at provider mount

### High contrast

- Borders use `var(--border)`; focus rings use `ring-2 ring-[var(--ring)]`
- Destructive actions: `variant="destructive"` with sufficient contrast

### Tab order

- Header → body fields (DOM order) → footer actions
- No positive `tabIndex` except trap sentinels (`tabIndex={0}` on container only if needed)

### Testing requirement

- Every primitive: RTL test for focus trap, ESC, aria attributes
- Storybook: a11y addon on all overlay stories

## 14. Animation Specification

### Tokens (`src/lib/overlay/tokens.ts` + CSS vars)

| Token | Value | Usage |
|-------|-------|-------|
| `--overlay-duration-enter` | `200ms` | Fade/scale enter |
| `--overlay-duration-exit` | `150ms` | Faster exit |
| `--overlay-ease` | `cubic-bezier(0.16, 1, 0.3, 1)` | Enter |
| `--overlay-ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | Exit |
| Spring (modal) | `{ stiffness: 300, damping: 30 }` | Match current Modal.tsx |
| Spring (drawer) | `{ stiffness: 300, damping: 30 }` | Match current Drawer.tsx |

### Per-variant motion

| Variant | Enter | Exit |
|---------|-------|------|
| Modal (centered) | `opacity 0→1`, `scale 0.95→1`, `y 20→0` | Reverse |
| Drawer (side) | `x ±100%→0` | Reverse |
| BottomSheet | `y 100%→0` | `y 0→100%` |
| Backdrop | `opacity 0→1` | `opacity 1→0` |
| ConfirmDialog | Same as Modal, no scale on mobile |

### Reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  --overlay-duration-enter: 0ms;
  --overlay-duration-exit: 0ms;
}
```

### Interruptions

- Rapid open/close: `AnimatePresence mode="wait"` on stack layer
- Nested overlay: child animates independently; parent backdrop darkens incrementally (`--overlay-backdrop-opacity-step: 0.1`)

### Nested animations

- Only shell animates on open/close
- Inner content (lists, accordions) uses CSS transitions, not competing Framer springs

## 16. Error Handling Specification

| Error type | Where shown | Recovery |
|------------|-------------|----------|
| Field validation | Below field + summary at top | Fix fields; focus first error |
| Step validation (wizard) | Step-level banner | Block Next; scroll to error |
| Submission error (4xx) | Footer banner `role="alert"` | User corrects and retries |
| Network error (5xx/offline) | Banner + Retry button | `mutation.retry()` |
| Timeout | Toast + inline message | Retry or cancel |
| Conflict (409) | AlertDialog with server message | Reload entity or overwrite |
| Unsaved close | ConfirmDialog | Discard or stay |
| Draft corrupt | Silent clear + toast | Start fresh |

### Patterns

```typescript
// Feature layer — unchanged React Query pattern
const mutation = useCreateMenuItem()
mutation.mutate(payload, {
  onSuccess: () => { clearDraft(); onClose() },
  onError: (err) => setSubmitError(mapApiError(err)),
})
```

### Cancel behavior

- Cancel in footer → `useUnsavedChanges` guard if dirty
- ESC → same guard
- Overlay click → only if `closeOnOverlay=true` (never on destructive forms)

### Offline

- Detect `navigator.onLine`; disable submit with tooltip
- Queue not in v1 (out of scope)

## 18. Hook Architecture

| Hook | Responsibility | Used by |
|------|----------------|---------|
| `useFocusTrap` | Tab cycle, sentinel nodes, initial focus | Modal, Drawer, BottomSheet, ConfirmDialog |
| `useScrollLock` | Ref-counted body overflow lock | All shells |
| `useOverlay` | `open`, `openOverlay`, `closeOverlay`, `overlayId` | Feature pages |
| `useModal` | Thin wrapper over `useOverlay` + Modal defaults | CRUD pages |
| `useDrawer` | Side/bottom defaults | Cart, Config |
| `useWizard` | Step nav, validate, aggregate data | WizardShell internals + features |
| `useFormDraft` | sessionStorage bind, TTL, recovery | Wizards, long forms |
| `useUnsavedChanges` | `beforeunload` + close guard | Forms with dirty state |
| `useOverlayStack` | Register/unregister, isTop, zIndex | Shell internals |
| `useResponsiveOverlay` | Returns `'modal' \| 'bottom-sheet' \| 'fullscreen'` for breakpoint | Modal, FoodDetail |
| `useVisualViewport` | Keyboard height offset | BottomSheet, PhoneInput |
| `useReducedMotion` | Boolean preference | AnimationProvider |

### Non-responsibilities (hooks must NOT)

- Call APIs
- Own React Query cache
- Render UI

## 19. Provider Architecture

```mermaid
flowchart TD
    Root[App Layout]
    OP[OverlayProvider]
    PM[PortalManager internal]
    OSM[OverlayStackManager internal]
    AP[AnimationProvider internal]
    Children[App Routes]

    Root --> OP
    OP --> PM
    OP --> OSM
    OP --> AP
    OP --> Children
```

| Provider | Scope | Mount location | Dependencies |
|----------|-------|----------------|--------------|
| **OverlayProvider** | App-wide | `src/app/layout.tsx` or `AppShell` | None |
| **PortalManager** | Internal to OverlayProvider | Creates `#overlay-root` div | DOM |
| **AnimationProvider** | Internal | Reads `prefers-reduced-motion` | None |
| **DraftProvider** | **Not required v1** | — | `useFormDraft` is hook-only |
| **FocusProvider** | **Not required v1** | — | Per-overlay `useFocusTrap` |

### OverlayProvider public API

```typescript
// Context (internal)
interface OverlayContextValue {
  register(overlay: RegisteredOverlay): void
  unregister(id: string): void
  getStackIndex(id: string): number
  isTop(id: string): boolean
  reducedMotion: boolean
}
```

Feature developers **never** consume OverlayContext directly — use shell components.

## 21. Coding Standards

### Naming

- Shells: PascalCase (`Modal`, `WizardShell`)
- Hooks: `use` prefix (`useFormDraft`)
- Types: `ModalProps`, `WizardStepDefinition`
- Files: match export name (`Modal.tsx`)

### Folder structure

- One component per folder when >1 file (types, subcomponents)
- Barrel `index.ts` at `overlay/` only — avoid deep re-export chains

### Composition

```tsx
// ✅ Correct
<Modal open={open} onClose={onClose} title="Add Item" footer={<Actions />}>
  <MenuItemFormFields ... />
</Modal>

// ❌ Forbidden
<div className="fixed inset-0 z-50 ...">
```

### Accessibility

- Every interactive overlay must use a shell component
- Run Storybook a11y addon before merge

### State

- Open state: `useState` in page OR `useModal()`
- Form state: `useState` / RHF; drafts via `useFormDraft`
- Never store overlay open state in Zustand (except CartDrawer pattern — acceptable for global cart)

### Validation

- New forms: Zod + RHF (match checkout pattern)
- Legacy console forms: migrate incrementally; wizard is forcing function for menu

### Testing

- Unit: RTL per primitive (focus, ESC, scroll)
- Storybook: all sizes + mobile variant
- E2E: P0 smoke (menu add, food detail, cart)

### Documentation

- JSDoc on public props interfaces
- Storybook stories = living docs

### Review checklist

- [ ] Uses shell from `ui/overlay`?
- [ ] Single scroll container?
- [ ] Focus trap + restore?
- [ ] Footer sticky and reachable at 320px height?
- [ ] No hardcoded `z-50` / `bg-black/60`?
- [ ] No inline `fixed inset-0`?
- [ ] Tests added/updated?

## 22. Extension Strategy

### New simple modal (≤8 fields)

1. Create `FeatureForm.tsx` in feature folder
2. Page: `const { open, openModal, closeModal } = useModal()`
3. Render `<Modal footer={...}><FeatureForm /></Modal>`
4. No new overlay code

### New wizard

1. Define `WizardStepDefinition[]` in feature folder
2. Create step components (≤150 lines each)
3. Wrap in `<WizardShell steps={...} onSubmit={mutation.mutate} />`
4. Optional: `useFormDraft({ key: 'feature:create:...' })`

### New drawer

1. `<Drawer side="right" footer={...}><Content /></Drawer>`
2. For mobile-only: `<BottomSheet>` or `useResponsiveOverlay`

### New fullscreen flow

1. Prefer **route-based** wizard page for >6 steps
2. Or `<FullscreenDialog>` for mobile takeover

### Without duplication

All paths go through `ui/overlay` — never copy backdrop/panel markup.

## 23. Anti-Patterns

| Anti-pattern | Why forbidden | Current example |
|--------------|---------------|-----------------|
| Nested scroll containers | Unreachable footer, scroll confusion | Modal content + inner div both scroll |
| Hardcoded `max-h-[85vh]` | Inconsistent; breaks on mobile keyboard | FoodDetailModal hack |
| Hardcoded `z-50` | Nested overlays break | All current overlays |
| Duplicated modal wrappers | A11y gaps, drift | Promotion/Reward/Reply/Vendor inline |
| Monolithic page+form+modal | Untestable, 500+ lines | `menu/page.tsx` |
| Business logic in shell | Coupling, reuse failure | N/A today (good) |
| Multiple overlay implementations | 3 systems today | Inline modals vs shared |
| Custom focus handling per feature | Inconsistent a11y | Custom modals lack trap |
| Multiple animation systems | Janky, untokenized | Framer inline per file |
| State duplication | Draft in page + storage | N/A (no drafts today) |
| `closeOnOverlay=true` on forms | Accidental data loss | — |
| Positive tabIndex on fields | Broken tab order | — |
| `overflow-hidden` without `max-h` | **Root bug** | `Modal.tsx` line ~panel |
