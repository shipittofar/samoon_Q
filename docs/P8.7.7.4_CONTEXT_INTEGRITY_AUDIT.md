## 2. Bootstrap Sequence

### Initial page load

```
TenantBootstrapper (mounted once, booted ref prevents double-fire)
  1. readTenantSlug()                      → meta[name="x-tenant-slug"] || NEXT_PUBLIC_TENANT_SLUG
  2. loadTenant(slug)
       set({ isLoading: true, tenantState: 'loading' })
       await tenantService.getTenant(slug)
       set({ tenant, isLoading: false, tenantState: 'ready' })
  3. setRbacInitialized(true)              → canExecute unblocked for RBAC
  4. setFeatureFlags(featureFlagsService.resolve(tenant))
  5. setFeatureFlagsInitialized(true)      → canExecute = true

AuthBootstrapper (runs concurrently)
  1. Check localStorage for access_token
  2. authService.getMe() → setUser(user) + setSentryUser
  3. On success: useRbacStore.setTenantRoles(tenant.id, p7Roles)  ← seeded at login
```

### Persistence behaviour on cold start

| Store field | Persisted | On cold start |
|---|---|---|
| `tenant` | YES | Last tenant loaded |
| `rbacInitialized` | NO | `false` — TenantBootstrapper must re-set |
| `featureFlagsInitialized` | NO | `false` — TenantBootstrapper must re-set |
| `featureFlags` | NO | `{}` — resolved fresh each boot |
| `tenantState` | NO | `'loading'` |
| `tenantRoles` (RBAC store) | YES | All role assignments from previous session |
| `adminActiveBranch` | YES | Last admin branch |
| `activeBranch` | YES | Last public branch |

**Key finding**: `rbacInitialized` and `featureFlagsInitialized` are NOT persisted by design
(`partialize: (state) => ({ tenant: state.tenant })`). They start `false` on every page load
and must be re-set by `TenantBootstrapper`. This is correct for initial load.

**Key finding**: `tenantRoles` in `useRbacStore` IS persisted. Role assignments survive page
reload. But they are keyed by `tenantId` — if you switch to a tenant with no stored roles,
`usePermissions()` returns `[]`.

## 3. Store State Machine

### useTenantStore

```
tenantState: 'loading' ──loadTenant()──→ 'ready'
                       ──error──────────→ 'fallback'

canExecute = tenantState !== 'loading' && rbacInitialized && featureFlagsInitialized

Notes:
- loadTenant() does NOT reset rbacInitialized or featureFlagsInitialized
- Both flags remain at their previous value during re-loads (stays true after boot)
- partialize persists only `tenant` to localStorage
```

### useRbacStore

```
tenantRoles: TenantRoleAssignment[]   keyed by { tenantId, roles[] }
usePermissions() → find(t => t.tenantId === currentTenantId)?.roles ?? []
             ↑
             This is the critical lookup. If no entry exists for tenantId → roles=[] → no permissions.
```

### AdminTenantSwitcher flow

```
switchTenant(slug)
  ├── setAdminActiveBranch(null)
  ├── [clear user-scoped state]
  ├── qc.clear()                    ← ALL React Query cache gone
  ├── await loadTenant(slug)        ← tenant updated, tenantState='ready'
  ├── setFeatureFlags(...)          ← flags resolved for new tenant
  ├── setFeatureFlagsInitialized(true)
  └── ❌ NO role seeding for new tenant
      → usePermissions() reads tenantRoles for new tenantId
      → finds nothing → returns [] → all usePermission() checks = false
      → admin/tenants page → PermissionGuard('tenant.view') → AccessDenied
```

## 4. Bug 1 — AccessDenied after tenant switch

### Reproduction

1. Owner/Admin logs in to samoon (tenant-samoon-01) — roles seeded via `useLogin`
2. Admin → Platform Tenants → click "Brew Cafe"
3. `switchTenant('brew-cafe')` runs → `loadTenant('brew-cafe')` sets `tenant.id = 'tenant-brew-cafe-01'`
4. `usePermissions()` now looks for `tenantRoles.find(t => t.tenantId === 'tenant-brew-cafe-01')`
5. No entry exists → returns `[]` → `getPermissionsForRole([]) = []`
6. `usePermission('tenant.view') = false`
7. `useTenants()` → `enabled: false` → `data = []` → AdminTenantSwitcher shows nothing
8. `admin/tenants/page.tsx` → `PermissionGuard permission="tenant.view"` → renders `<AccessDenied />`

### Root cause

`switchTenant()` in `AdminTenantSwitcher.tsx` (line 54-73) does not seed RBAC roles for the
new tenant after `loadTenant()` completes. `useLogin()` seeds roles via `setTenantRoles(tenantId, p7Roles)`
only for the login-time tenant. The persisted RBAC store has no entry for other tenants.

### Files involved

- `src/components/console/AdminTenantSwitcher.tsx` — `switchTenant()` missing role seeding
- `src/hooks/index.ts` — `usePermissions()` reads roles by current `tenantId`
- `src/hooks/index.ts` — `useTenants()` gated by `usePermission('tenant.view')`

### Fix

In `switchTenant()`, after `loadTenant()` resolves, consult `getMockRoles()` for the new
tenant. If no explicit mock roles exist, fall back to the user's current-tenant roles (the
roles that qualified them to use the tenant switcher in the first place).

See [Section 12](#12-fixes-applied) for exact change.

## 5. Bug 2 — Branch selector disabled

### Reproduction

1. Switch to any tenant with no branch records in `branchManagementService`
2. `useAdminBranches(newTenantId)` refetches after `qc.clear()`
3. `getBranches('tenant-road-bites-01')` → `MOCK_BRANCH_LIST.filter(b => b.tenantId === 'tenant-road-bites-01')` → `[]`
4. `AdminBranchSwitcher` button: `disabled={isLoading || branches.length === 0}` → permanently disabled

### Root cause — two-part

**Part A**: `switchTenant()` calls `qc.clear()` which invalidates all cached queries including
`['admin-branches', tenantId]`. On the next render, `useAdminBranches` refetches. During the
fetch window, `isLoading = true` → button disabled temporarily. This is correct transient
behavior.

**Part B** (actual bug): `road-bites` (tenant-id: `tenant-road-bites-01`) has zero branch records
in `INITIAL_MOCK_BRANCHES`. P8.7.7.3 added branch records for `brew-cafe`, `the-oak-bar`,
`central-food-court`, and `wheels-and-brews` but omitted `road-bites`. When `getBranches()`
returns `[]`, `branches.length === 0` → selector stays disabled indefinitely.

### Files involved

- `src/services/branch.service.ts` — `INITIAL_MOCK_BRANCHES` missing road-bites entry
- `src/components/console/AdminBranchSwitcher.tsx` — `disabled={isLoading || branches.length === 0}`

### Fix

Add a branch record for `tenant-road-bites-01` in `branch.service.ts`.  
Note: road-bites is `suspended` status. The branch should be `inactive` to reflect this.

See [Section 12](#12-fixes-applied) for exact change.

## 8. Bug 5 — PreviewButton URL verification

### Findings

`PreviewButton` reads:
- `tenantSlug = useTenantStore(s => s.tenant?.slug)` — from admin context
- `branchSlug = useBranchStore(s => s.adminActiveBranch?.slug)` — from admin context

`hrefToPublicUrl(href, tenantSlug, branchSlug)`:
```
'/'            → '/samoon'              (if tenantSlug='samoon')
'/restaurant'  → '/samoon'
'/menu'        → '/samoon/main/menu'   (if branchSlug='main')
'/reservation' → '/samoon/main/reservation'
'/promotions'  → '/samoon/main/promotions'
```

Fallbacks:
- No tenantSlug → returns `href` or `/` (flat URL, not '/') — correct
- No branchSlug → returns `/{tenantSlug}/{module}` — no branch in URL, acceptable

**After tenant switch**: `switchTenant()` clears `adminActiveBranch` → `branchSlug = undefined`.
URLs degrade to `/{tenantSlug}/{module}` until a branch is auto-selected by `AdminBranchSwitcher`
(which happens on next render cycle after `useAdminBranches` resolves). This is a brief window of
degraded preview URLs but not a permanent bug.

**After Bug 1 fix**: RBAC seeding ensures `useAdminBranches` is enabled and branches load,
allowing auto-selection and restoring full preview URLs.

**Verdict**: PreviewButton URL generation is correct. Transient degradation post-switch is
expected and self-resolving. No fix needed.

## 10. Bug 7 — Public context initialization

### Findings

`/[tenantSlug]/layout.tsx`:
```typescript
useEffect(() => {
  if (tenant?.slug !== tenantSlug) { loadTenant(tenantSlug) }
}, [tenantSlug, tenant?.slug, loadTenant])
```
Correctly initializes tenant store when navigating to a public tenant URL.

`/[tenantSlug]/[branchSlug]/layout.tsx`:
```typescript
useEffect(() => {
  if (tenant?.slug !== tenantSlug) { loadTenant(tenantSlug) }
}, [tenantSlug, tenant?.slug, loadTenant])

useEffect(() => {
  if (branches.length === 0) return
  const match = branches.find(b => b.slug === branchSlug)
  if (match) {
    setAdminActiveBranch(match)
    setActiveBranch(adminBranchToPublic(match))
  }
}, [branchSlug, branches, setAdminActiveBranch])
```

**Observation**: Public branch pages set `adminActiveBranch` and `activeBranch` in Zustand stores.
This is intentional — it powers context-aware PreviewButton and breadcrumbs when an admin views
a public branch page. There is no cross-tab contamination risk since Zustand is in-memory per tab.

**Public hooks** (`usePublicTenant`, `usePublicBranch`) use React Query with distinct keys and are
fully independent of Zustand stores for rendering content.

**Verdict**: No bug. Public context initialization is correct. The `loadTenant()` guards prevent
re-loading when the slug already matches. `useAdminBranches` query is `enabled: !!tenantId`, so
it correctly waits for tenant to resolve before fetching branches.

## 11. Bug 8 — URL ownership

### Findings

Every tenant's URLs are slug-based:
- Homepage: `/{tenantSlug}` — defined in `src/app/[tenantSlug]/page.tsx`
- Branch: `/{tenantSlug}/{branchSlug}` — defined in `src/app/[tenantSlug]/[branchSlug]/page.tsx`

No shared URLs between tenants. Each tenant's slug namespace is exclusive.

**Verdict**: No bug. URL ownership is correctly enforced by slug-based routing.

## 12. Fixes Applied

### Fix 1 — RBAC role re-seeding in AdminTenantSwitcher (Bugs 1, 6)

**File**: `src/components/console/AdminTenantSwitcher.tsx`

**Change**: Add `useRbacStore` and `useAuthStore` imports; add `getMockRoles` import.  
In `switchTenant()`, after `loadTenant()` completes, look up mock roles for the new tenant.  
If no explicit mock assignment exists, carry over the current tenant's roles (the roles that
authorized the user to use the switcher in the first place — platform admin scenario).

**Why this works**: `usePermissions()` reads `useRbacStore.tenantRoles.find(t => t.tenantId === currentTenantId)?.roles`.
After the fix, an entry exists for the new tenant's ID → permissions resolve correctly →
`usePermission('tenant.view')` returns true → `useTenants()` fetches → `PermissionGuard`
renders the page content instead of `<AccessDenied />`.

**Why this is safe**: Does not modify the RBAC permission matrix, role definitions, or
authorization formula. Only seeds role assignments in the mock store — which is exactly what
`useLogin()` does at login time. In production this would be an API call to fetch the user's
tenant-scoped roles.

### Fix 2 — road-bites branch record (Bugs 2, 3)

**File**: `src/services/branch.service.ts`

**Change**: Add `TENANT_ROAD_BITES = 'tenant-road-bites-01'` constant and one branch record
for road-bites with `status: 'inactive'` (consistent with tenant `status: 'suspended'`).

**Why this works**: `branchManagementService.getBranches('tenant-road-bites-01')` returns the
new record → `branches.length > 0` → `AdminBranchSwitcher` button enabled.

**Why this is safe**: Additive only. No existing branch records modified. Existing tests are
not affected (they check `branches.length >= 12` for samoon, and explicit counts for other tenants,
but not for road-bites).
