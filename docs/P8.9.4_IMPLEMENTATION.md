# P8.9.4 — Admin Dashboard & Navigation UX Foundation: Implementation

## Summary

Audits and redesigns the entire admin navigation and dashboard experience. No new business features, no new backend APIs. Focuses on helping every authenticated role immediately understand where they are, what they can do, and how to navigate.

---

## Phase A — Audit

### `docs/P8.9.4_ADMIN_UX_AUDIT.md` (new)

Complete audit of all 9 admin roles covering:
- First screen after login (found: 3 roles hit `<AccessDenied>` immediately)
- Navigation (flat 20-item sidebar, no grouping, no icons)
- Context awareness (role never shown; environment badge absent)
- Breadcrumbs (broken home link, missing on single-depth pages)
- Accessibility (no focus trap, broken skip-link target, missing ARIA)
- Mobile (context bar truncation, sidebar overlap, undersized touch targets)
- Benchmark against Shopify, Stripe, Linear, Square

46 issues catalogued: 6 critical, 11 high, 12 medium, 7 low.

## Phase B — Role-Aware Dashboard Router

### `src/app/admin/page.tsx` (rewritten)

Replaced the static `redirect('/admin/orders')` with a client component that reads the current user's P7 roles and redirects to their most meaningful first screen:

| Role | Destination |
|---|---|
| Platform Admin (`tenant.view` + `tenant.manage`) | `/admin/tenants` |
| Kitchen (only `kitchen.view`, no analytics/customers) | `/admin/kitchen` |
| Marketing (`analytics.view`, no `orders.view`) | `/admin/analytics` |
| Support (`customers.view`, no `orders.view`) | `/admin/customers` |
| Owner / Admin / Manager / Cashier | `/admin/orders` |

Fixes critical issues C1, C2, C3.

## Phase C+F — Sidebar Redesign

### `src/components/admin/AdminSidebar.tsx` (rewritten)

Complete redesign:

**Grouping:** 7 logical sections with section header labels:
- Operations: Orders, Reservations, Kitchen Display, Live Operations
- Content: Menu, Promotions, Reviews, Loyalty
- Customers: Customers
- Analytics: Analytics, Branch Analytics
- People: Staff, Users, Permissions, Roles
- Platform: Tenants, Branches, Website Builder, Audit Logs
- System: Notifications, Settings

**Icons:** Every nav item has a Lucide icon via `ICON_MAP` lookup.

**Role chip:** Displays current user's P7 roles (e.g., "Manager", "Cashier · Kitchen") below "Admin Panel" header.

**Focus trap:** When sidebar is open on mobile, `Tab` key is trapped within the sidebar. Escape closes it.

**Touch targets:** All interactive elements are `min-h-[44px]` (from `py-2` ~36px to `py-2.5` 44px).

**Accessibility:** `aria-expanded` on mobile toggle, `id="admin-sidebar"` matching `aria-controls`, Escape to close.

### `src/modules/registry.ts` (updated)

Added `icon` and `group` fields to all 22 nav item constants. Added:
- `ANALYTICS_NAV_ITEM` (replaces per-module inline analytics objects)
- `PROMOTIONS_NAV_ITEM` (new — for Marketing role visibility)
- Fixed `CUSTOMERS_NAV_ITEM.featureFlagKey` — removed incorrect `'menu.enabled'` dependency (C7 fix)
- Changed `OPERATIONS_NAV_ITEM.label` from `'Operations'` to `'Live Operations'`
- Reorganized `RESTAURANT_MODULE.adminNavItems` in group order

### `src/types/index.ts` (updated)

Added `group?: string` to `NavItem` interface — sidebar section grouping label.

## Phase E — Global Header

### `src/components/admin/AdminHeader.tsx` (new)

Admin-specific top bar that replaces the consumer `<Header>` on all `/admin/*` routes:

- Logo + tenant name + "Admin" sublabel (links to `/admin`)
- Mock environment badge (amber pill, hidden in production)
- Theme toggle (Light → Dark → System)
- "Public Site" link with external-link icon
- User avatar + first name

No shopping cart, no public nav links, no language picker (admin doesn't need these).

### `src/app/admin/layout.tsx` (updated)

- Imports and renders `<AdminHeader>` instead of consumer `<Header>`
- Adds `aria-expanded={sidebarOpen}` and `aria-controls="admin-sidebar"` to mobile menu toggle
- Adds `id="main-content"` to `<main>` so the skip-to-content link works (fixes C5)

### Admin pages cleaned

Removed `import { Header }` and `<Header />` from 15 admin pages that were importing the consumer header directly:
`kitchen`, `vendors/[id]`, `reservations`, `orders`, `audit-logs/[id]`, `audit-logs`, `reviews`, `customers/[id]/reviews`, `customers/[id]`, `customers`, `notifications/[id]`, `notifications`, `menu`, `promotions/[id]`, `website`.
