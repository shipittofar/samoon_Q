## 2. Phase A — Global Metadata

### 2.1 Root Layout (`src/app/layout.tsx`)

**Before:**
```ts
title: { default: 'Savor — Fine Dining & Delivery', template: '%s | Savor' },
description: 'Experience extraordinary cuisine crafted with passion. Order online, reserve a table, or dine in.',
keywords: ['restaurant', 'food delivery', 'online ordering', 'reservation', 'fine dining'],
openGraph: { siteName: 'Savor', title: 'Savor — Fine Dining & Delivery', description: 'Experience extraordinary cuisine crafted with passion.' },
twitter: { title: 'Savor — Fine Dining & Delivery' },
```

**After:**
```ts
title: { default: 'Savor — Hospitality Platform', template: '%s | Savor' },
description: 'Discover restaurants, cafés, bars, food trucks, and more. Browse menus, book tables, and order from local businesses on Savor.',
keywords: ['restaurant discovery', 'hospitality platform', 'food ordering', 'table booking', 'cafe', 'bar', 'food truck', 'local dining', 'marketplace', 'restaurant marketplace'],
openGraph: { siteName: 'Savor Platform', title: 'Savor — Hospitality Platform', description: 'Discover restaurants, cafés, and bars near you.' },
twitter: { title: 'Savor — Hospitality Platform' },
```

**Rationale:** The default title is used as a fallback for every page that doesn't define its own. "Fine Dining & Delivery" implies a single restaurant. "Hospitality Platform" correctly positions the product. Keywords are now marketplace-oriented, improving SEO for multi-tenant queries.

## 3. Phase B — Structured Data / JSON-LD

### 3.1 New: `buildWebSiteJsonLd()` and `DEFAULT_PLATFORM_JSON_LD` (`src/lib/json-ld.ts`)

**Added:**
```ts
export function buildWebSiteJsonLd(options: JsonLdWebSiteOptions): Record<string, unknown> {
  // Builds @type: 'WebSite' with optional SearchAction
}

export const DEFAULT_PLATFORM_JSON_LD = buildWebSiteJsonLd({
  name: 'Savor',
  description: 'Discover restaurants, cafés, bars, food trucks, and more...',
  url: BASE_URL,
  image: `${BASE_URL}/og-image.jpg`,
  searchUrl: `${BASE_URL}/discover?q={search_term_string}`,
})
```

**Schema emitted on platform homepage:**
```json
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "Savor",
  "description": "Discover restaurants, cafés, bars, food trucks, and more...",
  "url": "https://www.savor.com",
  "potentialAction": {
    "@type": "SearchAction",
    "target": { "@type": "EntryPoint", "urlTemplate": "https://www.savor.com/discover?q={search_term_string}" },
    "query-input": "required name=search_term_string"
  }
}
```

**Rationale:** The platform homepage previously emitted `@type: ["Restaurant", "FoodEstablishment"]`, causing Google to index the entire platform as a single restaurant. The `WebSite` schema with `SearchAction` is the correct schema for a marketplace/platform and enables Google Sitelinks Search Box.

**`DEFAULT_RESTAURANT_JSON_LD` retained** with the same type and name — existing tests assert its `@type` contains `'Restaurant'` and `name` is `'Savor'`. It is kept for potential use on tenant-level pages but must not be used on platform-level pages.

### 3.3 `RestaurantSchema` Component (`src/components/common/JsonLd.tsx`)

**Before:** Exported `RestaurantSchema()` with hardcoded `@type: 'Restaurant'`, name `'Savor Restaurant'`, fictitious address (123 Culinary Avenue), hardcoded phone, and specific social media links (`instagram.com/savorrestaurant`, `twitter.com/savornyc`, `facebook.com/savorrestaurant`).

**After:** Replaced with `PlatformSchema()` using `@type: 'WebSite'` with the Savor platform's correct data and a `SearchAction`. The old `RestaurantSchema` name is retained as a deprecated alias (`export const RestaurantSchema = PlatformSchema`) to avoid breaking any import that might reference it.

**Rationale:** This component was the only place that hardcoded a fictitious physical address and real social media handles for a restaurant that does not exist as a standalone entity at the platform level.

## 4. Phase C — Global Branding

### 4.1 FCM Push Notification Title (`src/hooks/client.ts`)

**Before:**
```ts
const { title = 'Savor', body = '' } = payload.notification ?? {}
```

**After:**
```ts
const { title = process.env.NEXT_PUBLIC_APP_NAME || 'Savor', body = '' } = payload.notification ?? {}
```

**Rationale:** When a push notification arrives without a title, the fallback was the hardcoded string `'Savor'`. This now reads from the `NEXT_PUBLIC_APP_NAME` env var (already defined in `src/lib/env.ts`), making it configurable without a code change. Falls back to `'Savor'` if unset (no behaviour change in existing deployments).
