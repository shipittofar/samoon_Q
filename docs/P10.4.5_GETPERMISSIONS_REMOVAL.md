# P10.4.5 — Remove Legacy `rbacService.getPermissions()`

Removes the third symbol proven `SAFE TO DELETE`/`SAFE AFTER MIGRATION`
by `docs/P10.4.2_REMOVAL_PROOF.md`: `rbacService.getPermissions()`.
Continues the sequence after `rbacService.p7` (P10.4.3) and
`useHasPermission()` (P10.4.4).

## Removed API

**`rbacService.getPermissions(role: UserRole | null | undefined):
readonly LegacyPermission[]`** (`src/services/rbac.service.ts`) — the
complete method implementation and its JSDoc block. It had zero
application/UI callers; every reference was test-only.

**No helper code was removed alongside it.** `ROLE_PERMISSIONS` (and the
`CUSTOMER_PERMISSIONS`/`STAFF_PERMISSIONS`/`OWNER_PERMISSIONS`/
`ADMIN_PERMISSIONS` arrays it's built from) is still required by
`rbacService.hasPermission()`, which was explicitly forbidden from this
phase — confirmed by reading the file before editing: both methods read
from the same shared `ROLE_PERMISSIONS` table, so nothing was
exclusively used by `getPermissions()` alone.

## Files changed

| File | Change |
|---|---|
| `src/services/rbac.service.ts` | Deleted the `getPermissions()` method and its JSDoc. `hasPermission()` and the shared `ROLE_PERMISSIONS`/permission-array constants are unmodified. |
| `src/test/phase1b.test.ts` | Deleted the entire `describe('rbacService.getPermissions()', ...)` block (7 `it()` cases: non-empty for customer, staff > customer, admin > staff, empty for null, empty for undefined, admin contains staff permissions, staff contains customer permissions) — every test in that block exclusively exercised the removed method. No other `describe` block in this file was touched. |

The three `rbacService.hasPermission(...)` behavioral assertions immediately below, in the same test, are unchanged. |

Diff stat: 3 files changed, 49 deletions(-), 0 insertions(+).

Note: this phase's scope statement named `phase4-e2e.test.ts` as the

## Regression Analysis

No behavioral, permission, or ownership changes. `rbacService.getPermissions()`
had zero application callers before this change, so its removal has no
runtime effect on the app. `rbacService.hasPermission()` — the function
every live authorization decision that still touches the legacy layer
depends on (`AuthGuard.tsx`, `useHasDashboardAccess()`'s `legacyGranted`)
— is byte-for-byte unchanged, as is the `ROLE_PERMISSIONS` table it
reads from. All currently-passing application and integration tests
continue to pass; the only test-count delta is the intentional removal
of assertions that existed solely to verify the now-deleted method,
exactly as authorized by this phase's scope.
