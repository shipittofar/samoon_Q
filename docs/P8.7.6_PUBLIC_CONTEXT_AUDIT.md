# P8.7.6 Public Context Integrity & Owner Workflow Audit

## 1. Audit Scope

This audit covers the full context initialization pipeline for the Savor Platform after the P8.7.5 context architecture upgrade. It validates tenant/branch context integrity across admin, preview, and public pages, including all RBAC guards, React Query cache isolation, and feature flag lifecycle.

---

## 2. Architecture Overview

Context flows through two parallel stores:

- **`useTenantStore`** — tenant lifecycle: `tenant`, `featureFlags`, `rbacInitialized`, `featureFlagsInitialized`
- **`useBranchStore`** — dual-mode branch: `activeBranch` (public/customer) + `adminActiveBranch` (admin)

Path-based public URLs (`/[tenantSlug]/[branchSlug]/[module]`) carry context in the URL, allowing the shared layout to re-initialize both stores from params on new-tab opens or refreshes.

## 3. Context Initialization Flows

### 3.1 Admin Preview Flow
```
Admin clicks "Preview Menu"
  → PreviewButton reads useTenantStore → tenant.slug
  → PreviewButton reads useBranchStore → adminActiveBranch.slug
  → hrefToPublicUrl('/menu', slug, branchSlug) → '/savor/main/menu'
  → New tab: /savor/main/menu
  → [tenantSlug]/[branchSlug]/layout.tsx runs
    → loadTenant('savor') if tenant mismatch
    → setAdminActiveBranch(match) + setActiveBranch(adminBranchToPublic(match))
  → Page renders with correct context ✓
```

### 3.2 Admin Branch Switching
```
Admin selects branch in AdminBranchSwitcher
  → setAdminActiveBranch(branch)
  → PreviewButton re-renders with new branchSlug ✓
```

### 3.3 Admin Tenant Switching
```
Admin selects tenant in AdminTenantSwitcher
  → setAdminActiveBranch(null)
  → await loadTenant(slug)
  → featureFlagsService.resolve(newTenant) → setFeatureFlags(flags)
  → setFeatureFlagsInitialized(true)
  → AdminBranchSwitcher auto-selects first branch of new tenant ✓
```

### 3.4 Public Customer Flow
```
Customer visits /savor/main/menu
  → layout.tsx: loadTenant('savor') + setActiveBranch(branch)
  → MenuContent reads useTenantStore + useBranchStore.activeBranch ✓
```

## 5. Fixes Implemented (Phase L)

### Fix 1 — `useMenuItems` query key (hooks/index.ts)
```typescript
// Before
queryKey: ['menu-items', filters]
// After
const tenantId = useTenantStore((s) => s.tenant?.id)
queryKey: ['menu-items', tenantId, filters]
```
**Effect:** Each tenant's menu items are cached independently. Switching tenant invalidates the prior tenant's cache automatically.

### Fix 2 — `useBranches` query key (hooks/index.ts)
```typescript
// Before
queryKey: ['branches']
// After
const tenantId = useTenantStore((s) => s.tenant?.id)
queryKey: ['branches', tenantId]
```
**Effect:** Branch list is tenant-scoped. No cross-tenant branch bleed.

### Fix 3 — `useTenants` RBAC guard (hooks/index.ts)
```typescript
// Before
return useQuery({ queryKey: ['tenants'], queryFn: ... })
// After
const canView = usePermission('tenant.view')
return useQuery({ queryKey: ['tenants'], queryFn: ..., enabled: canView })
```
**Effect:** Only platform admins with `tenant.view` permission can trigger the tenants fetch. Non-admins never fetch tenant list data.

### Fix 4 — Feature flags refresh on tenant switch (AdminTenantSwitcher.tsx)
```typescript
// Before
await loadTenant(slug)
setSwitching(false)
// After
await loadTenant(slug)
const newTenant = useTenantStore.getState().tenant
if (newTenant) {
  setFeatureFlags(featureFlagsService.resolve(newTenant))
  setFeatureFlagsInitialized(true)
}
setSwitching(false)
```
**Effect:** After switching tenant, feature flags are immediately resolved for the new tenant. The `TenantBootstrapper`'s `booted.current` ref no longer blocks re-initialization since the switcher handles it directly.

### Fix 5 — Path-based layout syncs `activeBranch` (layout.tsx)
Added `adminBranchToPublic()` mapping function and called `setActiveBranch()` alongside `setAdminActiveBranch()`:
```typescript
function adminBranchToPublic(b: AdminBranch): Location {
  return {
    id: b.id, tenant_id: b.tenantId, name: b.name, slug: b.slug,
    address: b.location.address, city: b.location.city,
    phone_number: b.contact.phone_number ?? '', lat: b.location.latitude ?? 0,
    lng: b.location.longitude ?? 0, working_hours: [],
    is_active: b.status === 'active',
  }
}
// In useEffect:
if (match) {
  setAdminActiveBranch(match)
  setActiveBranch(adminBranchToPublic(match))
}
```
**Effect:** Public pages (`/reservation`, `/menu`, etc.) can now read `activeBranch` from the store when opened via path-based preview URLs.

### Fix 6 — Reservation page branch context (reservation/page.tsx)
```typescript
// Before
const [selectedBranch, setSelectedBranch] = useState('1')
defaultValues: { guests: 2, branch_id: '1' }
// After
const activeBranchId = useBranchStore((s) => s.activeBranch?.id)
const [selectedBranch, setSelectedBranch] = useState(() => activeBranchId ?? '1')
defaultValues: { guests: 2, branch_id: activeBranchId ?? '1' }
useEffect(() => {
  if (activeBranchId) { setSelectedBranch(activeBranchId); setValue('branch_id', activeBranchId) }
}, [activeBranchId, setValue])
```
**Effect:** Reservation form pre-selects the branch from context. If no context (direct visit), falls back to `'1'` preserving backward compatibility.

### Fix 7 — `module` variable name (public-url.ts)
Renamed local variable `module` → `mod` to avoid conflict with Next.js's reserved `module` global.

## 10. Backward Compatibility

All fixes are additive or narrowing (restricting who can call a hook, not removing capability):

- `useMenuItems` — existing callers pass the same `filters` argument; the added `tenantId` is internal
- `useBranches` — zero API changes; callers unmodified
- `useTenants` — non-platform-admins previously got data they shouldn't have; now they get empty (enabled=false returns `undefined`/`[]`). No consumer depends on non-admin receiving tenant list.
- `AdminTenantSwitcher` — same UI contract; feature flags now correct after switch
- `layout.tsx` — only adds `setActiveBranch` call; no removal
- `reservation/page.tsx` — falls back to `'1'` when no context, preserving direct-visit behavior
