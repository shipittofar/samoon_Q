# P8.9.1 — Authentication & Admin Access Integrity: Audit

## Scope

Every authenticated surface: middleware JWT gate, demo login page, post-login redirects, admin sidebar navigation, session persistence across hard refresh / incognito / deep links. No backend auth, OTP, JWT structure, or token refresh was touched.

---

## Phase A — Auth System Audit

### A1 — Edge middleware: no role check (INFORMATIONAL)
**File:** `src/middleware.ts`
**Finding:** Middleware validates JWT cookie structure + `exp` field only. It does not inspect the user's role. A customer with a valid token can reach `/admin/*` — but is then caught by the `AuthGuard` component which checks `dashboard:access`.
**Decision:** Correct layered defense. Middleware is a first gate; RBAC enforcement is the second. No change needed.

### A2 — No Django Admin redirect (NON-ISSUE)
**Finding:** No route `/admin/login/` exists in Next.js. No `rewrites()` in `next.config.ts`. The spec reference to "Django Admin" is a red herring — all `/admin/*` routes are Next.js App Router pages. Middleware only redirects to `/login` (Next.js page). No fix needed.

### A3 — Demo login: all staff land at `/admin/orders` (HIGH)
**File:** `src/app/login/page.tsx`
**Problem:** `loginAs()` pushed `email === 'demo@savor.com' ? '/' : '/admin'` for every account. Kitchen user landed at `/admin` (→ redirected to `/admin/orders` by `src/app/admin/page.tsx`), not `/admin/kitchen`. Same for Marketing (should be `/admin/analytics`), Support (`/admin/customers`), Platform Admin (`/admin/tenants`).
**Fix:** `getDemoRedirect(email)` from `@/utils/auth-redirect`.

### A4 — `onSubmit` always redirects to `/` (HIGH)
**File:** `src/app/login/page.tsx`
**Problem:** Manual email/password login always pushed to `/`, even for `admin@savor.com` or `owner@savor.com`. Real staff users who sign in with credentials landed on the customer homepage.
**Fix:** `getPostLoginRedirect(result.user.role)` — customer → `/dashboard`, staff/admin → `/admin`.

### A5 — Demo cards show email, not phone (MEDIUM)
**File:** `src/app/login/page.tsx`
**Problem:** Third line of each demo card showed `{email}` in monospace — a UX inconsistency when the product uses phone-first identity in production.
**Fix:** Replaced with international phone numbers (+1 415 555 0101 → 0110).

### A6 — No Platform Admin demo account (HIGH)
**Files:** `src/lib/mock-data.ts`, `src/services/auth.service.ts`, `src/app/login/page.tsx`
**Problem:** `platform@savor.com` existed in the redirect map but had no mock user, no `MOCK_CREDENTIALS` entry, and no demo card. Login would fail with "Invalid credentials."
**Fix:** Added `MOCK_PLATFORM_ADMIN_USER` (id: '10', legacy role: 'admin', P7 role: 'owner'), entry in `MOCK_CREDENTIALS`, and demo card with `Building2` icon.

### A7 — Admin sidebar: no Logout or home navigation (HIGH)
**File:** `src/components/admin/AdminSidebar.tsx`
**Problem:** No way to log out from within the admin panel — users had to navigate to the login page manually. No "Back to Public Site" link (the old "Preview Public Site" opened in a new tab). No permanent Dashboard home link at the top of nav.
**Fix:** Added `useLogout()` + Logout button (red hover, redirects to `/login`). Replaced ExternalLink "Preview Public Site" with `<Home>` "Back to Public Site" (same-tab). Added permanent Dashboard `<Link>` at top of nav.

---

## Phase C — Admin Redirect Integrity

No Django Admin redirect exists. `src/app/admin/page.tsx` does `redirect('/admin/orders')` — this is intentional. The new always-visible Dashboard link in the sidebar gives users a stable anchor to `/admin`.

## Phase F — Auth Consistency

| Scenario | Before | After |
|---|---|---|
| Hard refresh while logged in | ✅ Token persists via cookie | ✅ Unchanged |
| Incognito deep link to `/admin/kitchen` | Middleware redirects to `/login?redirect=/admin/kitchen` | ✅ Unchanged |
| Customer accesses `/admin/*` | `AuthGuard` → `/` | ✅ Unchanged |
| Kitchen logs in via demo card | → `/admin` (wrong) | ✅ → `/admin/kitchen` |
| Platform Admin logs in | ❌ Fails "Invalid credentials" | ✅ → `/admin/tenants` |
| Staff types email + password | → `/` (customer homepage) | ✅ → `/admin` |
| Customer types email + password | → `/` | ✅ → `/dashboard` |

- `useRbacStore` / `useAuthStore` internals
