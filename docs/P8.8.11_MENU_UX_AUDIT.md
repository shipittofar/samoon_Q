## Phase A — Section-by-Section Audit

---

### 1. First Impression (5-Second Test)

**Score: 7.0 / 10**

Within 5 seconds a visitor can determine:
- ✅ This is a menu page (heading "Our Full Menu")
- ✅ There is a search bar
- ✅ Categories are visible and scrollable
- ✅ Items have images, names, and prices
- ✅ A "Add" button is on every card
- ❌ No tenant/branch name in the page heading — "Our Full Menu" is generic
- ❌ No breadcrumb or context anchor linking back to the branch homepage
- ❌ Dietary filter options not immediately visible (hidden in filter panel)

Positive assessment: FoodCard design is visually strong — images, badges, rating, preparation time, and price are all well presented. The category tab bar and sticky controls are modern. First impression is generally good but the tenant identity is completely absent from the experience.

---

### 2. Category Navigation

**Score: 6.5 / 10**

Positive:
- Sticky category bar stays at `top-16` while scrolling ✅
- Horizontal scroll with `scrollbar-hide` ✅
- Active state uses filled orange pill — clear visual hierarchy ✅
- Item counts shown per category ✅
- Loading skeleton with animated placeholders ✅
- Emoji icons supported via `cat.icon` ✅

Negative:
- **Active category tab doesn't auto-scroll into view** — When category is pre-selected via URL (`?category=burgers`), the active tab may be off-screen on mobile. No `scrollIntoView` call when active category changes.
- **Category tabs don't trigger section scroll** — Selecting a category re-fetches items but does NOT scroll the page to the items. On desktop, users may not notice the grid changed. Uber Eats and DoorDash scroll smoothly to the matching section.
- **No "jump to section" within a combined view** — All categories display in a single paginated list. There's no section-based layout (e.g. "Starters" → anchor → "Mains" → anchor → "Desserts") like Uber Eats uses.
- **Category URL bug** — `handleCategoryChange` writes to `/menu?category=...` (the global route) instead of `/{tenantSlug}/{branchSlug}/menu?category=...`. Selecting a category from the tenant-specific menu URL navigates to the wrong route.

---

### 3. Menu Search

**Score: 6.2 / 10**

Positive:
- 350ms debounce is appropriate ✅
- Clear (X) button appears when search has content ✅
- Empty state with message "No results for X. Try different keywords." ✅
- `type="search"` on the input ✅

Negative:
- **No search suggestions / autocomplete** — Uber Eats, DoorDash both show dropdown suggestions as you type (category names, popular dishes, ingredients). Savor shows nothing until results load.
- **No no-result suggestions** — When zero results are found, there's no "Did you mean...?", no popular items, no "Browse all" shortcut. Users who fail to find an item hit a dead end.
- **Search is client-side filtered via API** — but there's no indication of search scope (e.g., "searching menu items for The Coffee House Downtown"). If the API returns empty due to branch/tenant scoping issues, users don't know why.
- **Search doesn't persist to URL** — `debouncedSearch` is local state only. Sharing a link to "croissant" results doesn't work. (CategoryFilter syncs to URL but search does not.)
- **No "Recent searches" or "Popular dishes"** — Cold start of the search field shows nothing. Uber Eats, DoorDash fill the initial search with popular/trending items as suggestions.

---

### 4. Menu Cards (FoodCard)

**Score: 8.0 / 10**

This is the strongest component in the menu experience. Most Uber Eats/DoorDash card patterns are implemented.

Positive:
- `next/image` with proper `sizes` attribute ✅
- Favorite button (heart) with animated filled state ✅
- Badges: New, Popular, Featured, Discount % ✅
- Rating + rating count ✅
- Preparation time ✅
- Calories ✅
- Discount price with strikethrough original ✅
- Compact (list) mode ✅
- "Added!" animation with scale and color feedback ✅
- For items with extras: "Customize" button opens modal ✅
- Unavailable overlay ✅

Negative:
- **No image fallback** — `<Image src={item.image}>` — if `item.image` is an empty string or undefined the component throws. No `onError` handler or placeholder.
- **"Customize" label for extras items** — When `item.extras.length > 0`, the Add button shows `<ChefHat /> Customize`. "Customize" implies you must do work. Uber Eats shows "Add" and the customization panel appears naturally. The word "Customize" creates friction.
- **Compact mode (list view) has no image fallback** — `<Image src={item.image}>` in compact mode also has no guard for empty image URLs.
- **Grid is 4-column on XL screens** — `xl:grid-cols-4` — card images at `h-48` in a 4-column layout on a 1440px screen produce very wide, short cards. Images appear cropped and the card proportions feel off. 3-column max is more appropriate for food photography.

---

### 5. Item Details (FoodDetailModal)

**Score: 7.5 / 10**

This is a rich, well-implemented modal. Most hospitality ordering patterns are present.

Positive:
- Two-panel layout (image left, content right) on desktop ✅
- Tags, nutritional info (collapsible), extras, notes, reviews all in one scroll ✅
- Related items at bottom ✅
- Quantity control + "Add to Cart · $X.XX" total ✅
- Favorite button in modal ✅
- Review submit inline ✅

Negative:
- **Related items in modal don't open sub-modals** — `FoodCard` components in the related section have no `onOpenDetail` prop. Clicking a related item calls `addRecentlyViewed` but the modal never opens. Related items are dead-ends.
- **Reviews collapsed by default** — `showReviews` starts `false`. Trust signals (reviews, ratings) should be visible without an extra click. The summary line "Reviews · 4.2 (128)" is shown, but actual review text requires clicking.
- **Modal `max-h-[85vh]`** — On mobile (375px height), an 85vh modal is ~318px. The two-panel layout collapses to stacked (image top, content below) — the image at `h-60` (240px) leaves only ~78px for content before the footer CTA. This makes the modal feel cramped on mobile.
- **"Add Extras" section heading** — "Add Extras" is generic. Uber Eats labels each extra group by its role: "Choose your sauce", "Select size", "Add toppings". Savor shows all extras in a single undifferentiated list.
- **No loading state for "Add to Cart"** — The CTA has no loading indicator after being pressed. If the API is slow, users might tap twice.

### 6. Customization

**Score: 7.0 / 10**

Positive:
- Extras toggle (checkbox pattern) ✅
- Unavailable extras greyed out ✅
- Price updates live in the modal footer total ✅
- Special requests / notes field ✅

Negative:
- **Required extras not distinguished from optional** — There's no "required" marker on extras. If a pizza requires a size selection, the user can add to cart without choosing. This would cause order errors.
- **No extra grouping** — All extras appear as a flat list. "Sauces", "Toppings", "Drinks" should be grouped under their respective headings.
- **No maximum selection enforcement** — If 2 sauces max are allowed, there's no UI enforcement. All extras use the same toggle pattern regardless of rules.

---

### 7. Cart Experience

**Score: 7.5 / 10**

`CartDrawer` and `FloatingCart` are well-implemented.

Positive:
- Right-side drawer with animated open/close ✅
- Quantity controls in drawer ✅
- Remove item button ✅
- Extras and notes shown per cart item ✅
- Discount code field ✅
- Full price breakdown (subtotal, tax, service, total) ✅
- FloatingCart: spring-animated bottom bar with count + total ✅
- `AnimatePresence` for item add/remove in drawer ✅

Negative:
- **FloatingCart covers bottom card row on mobile** — `fixed bottom-6` positions the cart bar at the bottom. On mobile, the last visible row of FoodCards is hidden behind it. `main` content needs `pb-28` when cart is visible.
- **No "Undo remove" after deleting item** — Removing an item from the cart is permanent and instant. Uber Eats, DoorDash both offer an undo snackbar ("Item removed · Undo"). This is especially important when removing the last item.
- **"Clear cart" is a low-prominence text link** — `w-full text-xs text-[var(--fg-subtle)]` — the destructive action of clearing the entire cart is styled as a tiny grey text link. It should require confirmation or be less prominent.
- **Checkout CTA "Proceed to Checkout" links to `/checkout`** — This loses the tenant/branch context. Checkout at `/checkout` should receive the branch context from the cart store, which it presumably does — but the URL doesn't communicate context.
- **Empty cart CTA "Browse Menu" closes the drawer** — It calls `setOpen(false)` but doesn't navigate anywhere. The user is left on whatever page they were on. It should navigate to the current branch menu.

### 8. Upselling

**Score: 5.5 / 10**

Positive:
- Related items appear at the bottom of `FoodDetailModal` ✅
- "You might also like" section exists ✅

Negative:
- **Related items don't open modals** — The most critical issue: the related item `FoodCard` components in the modal have no `onOpenDetail` callback, so tapping them does nothing useful.
- **No "Frequently bought together"** — DoorDash, Uber Eats show items frequently ordered together. Savor shows only "related" items without explanation of why they're related.
- **No upselling in cart** — When the drawer opens, there's no "You might also like" or "Don't forget a drink!" prompt. Uber Eats shows category suggestions in the cart.
- **No combo suggestions** — No "Make it a meal for +$X" pattern.
- **Upsell only accessible via item detail modal** — Users who Quick-Add without opening the modal never see related items at all.

### 9. Availability

**Score: 7.5 / 10**

Positive:
- `!item.available` shows dark overlay "Currently Unavailable" ✅
- `opacity-70` on unavailable cards ✅
- Add button `disabled` when unavailable ✅
- Filter panel has "Available only" toggle ✅

Negative:
- **No visual distinction between sold out vs. time-limited unavailability** — "Currently Unavailable" could mean sold out, outside serving hours, or temporarily paused. Uber Eats shows specific labels: "Sold out", "Not available until 5pm".
- **Unavailable items mixed in main grid** — Sold-out items appear throughout the grid at full opacity minus 70%. DoorDash moves unavailable items to the bottom of the category. This reduces scrolling past items users can't order.

### 10. Filtering

**Score: 5.8 / 10**

Positive:
- Animated filter panel with Framer Motion ✅
- Price range sliders ✅
- Minimum rating filter ✅
- "Available only" toggle ✅
- Clear all filters button ✅
- Active filter indicator on Filters button ✅

Negative:
- **No dietary/allergen filters** — The #1 filter type on every food delivery platform. No Vegetarian, Vegan, Halal, Gluten-Free, Spicy, or Dairy-Free options. Users with dietary requirements bounce immediately.
- **Price range uses two independent sliders** — Users can accidentally set min > max. An integrated dual-handle range slider or discrete price buckets ("Under $10", "$10–$20", "$20+") would be far less error-prone.
- **Filters require a panel click to open** — Primary dietary filters should be visible as chips above the grid (like Uber Eats's "Vegan · Halal · Gluten-free" chip row) without requiring a filter panel.
- **No filter count** — The filter indicator shows "!" when filters are active but not how many filters are applied. Uber Eats shows "Filters (2)".

### 11. Performance

**Score: 7.8 / 10**

Positive:
- `FoodCard` uses `next/image` with proper sizes ✅
- `FoodCardSkeleton` shown during loading ✅
- 8 skeletons shown (appropriate) ✅
- 350ms search debounce prevents over-fetching ✅
- Framer Motion `AnimatePresence` with `mode="popLayout"` ✅
- `LazyFoodDetailModal` — lazy-loaded modal component ✅

Negative:
- **Stagger animation delay `i * 0.04`** — With 40+ items, the last item animates in at 1.6 seconds after load. Stagger delays should be capped at ~10 items or 200ms total.
- **No virtualization** — For menus with 100+ items, all are rendered into the DOM. `react-virtual` or `@tanstack/react-virtual` would prevent performance degradation.
- **`FoodCardSkeleton` count hardcoded to 8** — Doesn't match `xl:grid-cols-4` layout (should be 8 or 12 for full rows).

### 12. Trust

**Score: 6.8 / 10**

Positive:
- Ratings (star + count) on each card ✅
- Preparation time on each card ✅
- "Popular" / "Featured" / "New" badges ✅
- Discount % badge ✅
- Reviews inside item detail modal ✅
- Recently Viewed section ✅

Negative:
- **No "Best Seller" or "#1 in category" rank** — DoorDash shows "#1 Most Liked" on standout items. This drives click-through on high-performing items.

- **No chef/business owner highlight** — Airbnb shows "Host Recommendation". OpenTable shows "Chef's Pick". Savor has a `ChefHat` icon for customize — this icon could be used more effectively for "chef's pick" items.
- **Preparation time displayed as `{item.preparation_time}m`** — Just a number followed by "m". "~15 min" is friendlier and sets appropriate expectations.

### 13. Conversion

**Score: 6.0 / 10**

Full conversion path: Menu → Item detail → Customize → Add → Cart → Checkout

Friction points found:
1. **Category URL bug** — Selecting a category navigates to `/menu?` (wrong route) — could lose tenant context
2. **Related items in modal are non-functional** — Breaking the upsell path
3. **Quick-add skips customization prompts** — Items with optional extras get added without being asked
4. **FloatingCart obscures bottom row cards** — Users can't see/tap Add on partially hidden cards
5. **Search results not URL-persistent** — Can't share a filtered view
6. **Empty cart "Browse Menu" doesn't navigate** — Closes drawer but leaves user stranded
7. **No order summary before checkout** — Cart drawer shows totals but "Proceed to Checkout" could benefit from a brief "Are you ready?" confirmation moment

Click count from landing on menu to checkout: **6 clicks minimum** (category → scroll → card → quantity → add → open cart → checkout). Uber Eats target is 4 clicks from intent to checkout.

## Phase B — Priority Register

---

### CRITICAL Issues

---

**C1 — Category URL Bug: Navigates to Wrong Route**

| | |
|---|---|
| Severity | Critical |
| Problem | `handleCategoryChange` calls `router.replace('/menu?category=X')` which navigates to the global `/menu` route, not `/{tenantSlug}/{branchSlug}/menu?category=X`. Clicking any category from the tenant-specific menu URL loses the tenant/branch context in the URL. |
| Evidence | `MenuContent.tsx` line 78: `router.replace('/menu?${params.toString()}', { scroll: false })` |
| UX Impact | Category tabs appear broken — tap a category, URL changes from `/coffee-house/downtown/menu` to `/menu?category=pizza`. Tenant context is lost in the URL (though the store context may persist). |
| Business Impact | SEO: category-filtered URLs become non-canonical. Analytics: category navigation appears as page-to-page transitions, inflating bounce rate. |
| Conversion Impact | High — any URL navigation bug erodes user trust |
| Solution | Use `usePathname()` to get the current path prefix, then build category URLs relative to it: `router.replace(`${pathname}?${params.toString()}`)`. |
| Complexity | Low |
| Expected Improvement | +0.5 trust score, correct URL behavior |

---

**C2 — No Dietary / Allergen Filters**

| | |
|---|---|
| Severity | Critical |
| Problem | The filter panel has price range, rating, and availability but NO dietary filters: Vegetarian, Vegan, Halal, Gluten-Free, Spicy, Dairy-Free. |
| Evidence | `MenuContent.tsx` filter panel (lines 263–315) has only `priceRange`, `minRating`, `onlyAvailable` state |
| UX Impact | Users with dietary restrictions cannot filter — they must manually scan the entire menu. Most will abandon. |
| Business Impact | Dietary filters are the #1 most-used filter on Uber Eats/DoorDash. Missing this feature means losing the vegan/halal/GF demographic. |
| Conversion Impact | Very High — dietary filter users have above-average order frequency and basket size |
| Solution | Add dietary tag chips above the grid as always-visible quick-filters: "🌱 Vegan · 🥗 Vegetarian · ✡ Halal · 🌾 Gluten-Free · 🌶 Spicy". These filter on `item.tags` which is already available in `MenuItem`. |
| Complexity | Low |
| Expected Improvement | +1.5 conversion score |

---

**C3 — FoodCard Missing Image Fallback**

| | |
|---|---|
| Severity | Critical |
| Problem | `FoodCard` renders `<Image src={item.image}>` without checking if `item.image` exists. If it's an empty string (likely for items created without photos), the Next.js Image component throws an error or renders broken. |
| Evidence | `FoodCard.tsx` line 106: `<Image src={item.image} alt={item.name} fill ...>` — no null/empty guard |
| UX Impact | Cards with missing images crash visibly — broken image icon or unhandled error boundary. |
| Business Impact | Any item without a photo appears broken. New businesses onboarding without photos see a broken menu. |
| Conversion Impact | High — broken UI destroys trust immediately |
| Solution | Guard with: `{item.image ? <Image ... /> : <div className="w-full h-full bg-gradient-to-br from-orange-100 to-orange-50 flex items-center justify-center"><span className="text-4xl opacity-40">🍽️</span></div>}` |
| Complexity | Low |
| Expected Improvement | +0.5 trust score, prevents crashes |

---

**C4 — Related Items in Modal Are Non-Functional**

| | |
|---|---|
| Severity | Critical |
| Problem | `FoodDetailModal` renders related items using `<FoodCard ... />` without passing an `onOpenDetail` callback. Clicking a related item calls `addRecentlyViewed` but the detail modal does not open for the clicked item. |
| Evidence | `FoodDetailModal.tsx` line 357: `<FoodCard key={rel.id} item={rel} compact />` — no `onOpenDetail` prop |
| UX Impact | Users tap related items expecting to view them. Nothing happens. This destroys the upsell path. |
| Business Impact | Related item cross-sell is directly correlated with basket size increase (industry avg +12–18%). |
| Conversion Impact | High — broken upsell path |
| Solution | Thread an `onOpenDetail` callback through `FoodDetailModal` (via a local state swap or an external handler), or replace FoodCard in the related section with a simple card that opens a new item in the same modal by updating `item` state. |
| Complexity | Medium |
| Expected Improvement | +1.0 conversion score |

### HIGH Issues

---

**H1 — FloatingCart Obscures Bottom Card Row on Mobile**

| | |
|---|---|
| Severity | High |
| Problem | `FloatingCart` is `fixed bottom-6` (~70px tall). The main content area has no bottom padding to compensate. On mobile, the last visible row of food cards is partially hidden behind the floating cart bar. The "Add" button on the bottom row is unreachable. |

| Complexity | Low |
| Expected Improvement | +0.8 mobile conversion score |

---

**H2 — Category Active Tab Doesn't Scroll Into View**

| | |
|---|---|
| Severity | High |
| Problem | When a category is pre-selected via URL `?category=X`, the active tab may be off-screen in the horizontal scroll container. No `scrollIntoView` is called. |
| Evidence | `MenuContent.tsx` `categoryBarRef` is created but never used to scroll the active tab into view |
| Solution | In `handleCategoryChange`, after updating state, call `categoryBarRef.current?.querySelector('[aria-selected=true]')?.scrollIntoView({ behavior: 'smooth', block: 'nearest', inline: 'center' })`. Or use `useEffect` when `activeCategory` changes. |
| Complexity | Low |
| Expected Improvement | +0.5 UX score on mobile |

**H8 — Stagger Animation Delay Too Long at Scale**

| | |
|---|---|
| Severity | High |
| Problem | Item entry animation uses `delay: i * 0.04`. With 40+ items, last item animates in at 1.6 seconds after data loads. Users see items popping in for over a second. |
| Evidence | `MenuContent.tsx` line 379: `transition={{ delay: i * 0.04 }}` |

| Complexity | Trivial |
| Expected Improvement | +0.3 performance score |

**H10 — Empty Cart "Browse Menu" Closes Drawer Only**

| | |
|---|---|
| Severity | High |
| Problem | The empty cart state has a "Browse Menu" button that calls `setOpen(false)`. It closes the drawer but doesn't navigate anywhere. If the user is on a non-menu page, they're left stranded. |
| Evidence | `CartDrawer.tsx` line 117: `<Button onClick={() => setOpen(false)}>Browse Menu</Button>` |
