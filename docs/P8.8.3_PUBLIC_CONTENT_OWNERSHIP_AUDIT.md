## Phase G — Dynamic Footer

**Before P8.8.3:** All tenant and branch pages used the static platform `Footer` component.

**After P8.8.3:** 
- Root pages (`/`, `/restaurant`, etc.) → Platform `Footer` (unchanged)
- Tenant pages (`/[tenantSlug]`) → `TenantFooter` (new component)
- Branch pages (`/[tenantSlug]/[branchSlug]`) → `TenantFooter` when meta available, else `Footer`

`TenantFooter` renders:
- Business name + logo initial
- Tagline + short description
- Social links (Instagram, Twitter — from `meta.socialLinks`)
- Quick links to business page, menu, reservations, locations
- Contact: city, phone_number, email, website
- Dynamic copyright: "© {year} {tenantName}"
- "Powered by Samoon Platform" link

## Phase H — Dynamic Contact

`/restaurant/page.tsx` contact section now reads from:
1. `meta.phone_number` (from Public Profile admin)
2. `meta.email` (from Public Profile admin)
3. `meta.website` (from Public Profile admin)
4. Fallback: `settings.contactPhone`, `settings.contactEmail` (from General admin)

Contact cards are rendered only when a value is present (no empty cards).

## Phase I — Public About

`/restaurant/page.tsx` About section now reads from:
1. `meta.story` — New field added to `MarketplaceMeta` (editable via Admin → Settings → Public Profile)
2. Fallback: generic platform description

The hardcoded founder story ("Chef Marco Rossi and his partner Amara Chen...") has been replaced with dynamic content. When `meta.story` is blank, a neutral fallback is shown.
