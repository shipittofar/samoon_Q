# P8.8.4 — Discovery Audit

> **SUPERSEDED (cuisines / amenities):** Cuisine/amenity search and filters operate
> on Branch payloads only. See `docs/BACKEND_API_CONTRACT.md` §30.4.

**Date:** 2026-06-27  
**Scope:** `/discover` page — search, filters, sorting, cards, collections, empty states, loading states, SEO, data source, performance.

---

## 1. Search Flow (Before)

| Aspect | State Before |
|--------|-------------|
| Debounce | 300ms ✅ |
| Fields searched | Name, city, description, cuisines, tags, business type labels |
| Case sensitivity | case-insensitive (`.toLowerCase()`) ✅ |
| Accent sensitivity | Not normalized — `cafe` ≠ `café` ❌ |
| Partial matching | Yes ✅ |
| Missing fields | Tagline, amenities, branch names not searched ❌ |

**After:**
- Accent-insensitive via `normalize('NFD').replace(/\p{M}/gu, '')`.
- Added: tagline, amenities, branch names to search scope.
- Updated placeholder text to reflect new scope.

---

## 2. Filters (Before)

| Filter | State Before |
|--------|-------------|
| Category chip | ✅ Single select by business type |
| Cuisine | ❌ Not available |
| City | ❌ Not available |
| Price Level | ❌ Not available |
| Open Now | ❌ Not available |
| Services (Reservations, Loyalty) | ❌ Not available |
| Amenities | ❌ Not available |
| Multi-filter combine | ❌ Not applicable |

**After:**
- `AdvancedFilters` component with collapsible panel.
- Supports: cuisines (multi), cities (multi, hidden when only 1 city), price levels (multi), Open Now toggle, services (Reservations, Loyalty), amenities (multi).
- All active filters combine with AND logic.
- Filter options derived dynamically from the live tenant list.
- Active filter count badge on toggle button.
- "Clear all" resets all filters at once.

| Sorting | State Before |

## 11. Data Source

| Layer | Source |
|-------|--------|
| Tenants | `usePublicTenants()` → `tenantService.getTenants()` → filters `active` + `trial`, excludes `default` |
| Cache | `['public-tenants']` query key, 5min stale / 30min cache |
| Filtering | Fully client-side: `matchesSearch()`, `matchesCategory()`, `matchesFilters()` |
| Sorting | Fully client-side: `sortItems()` |
| Collections | Derived from tenants in `useMemo` hooks |

| Aspect | State |

## 14. Known Remaining Gaps

| Gap | Severity | Notes |
|-----|----------|-------|
| Map/geo-location sort | Low | "Nearest" sort deferred until maps integration |
| Saved searches / favourites | Low | Requires auth context |
| Infinite scroll / pagination | Low | Needed only when tenant count > ~50 |
| `<img>` vs `<Image>` on cards | Low | Cover images use raw `<img>` (aria-hidden); fine for decorative images, no LCP impact since cards are below fold |
| Autocomplete suggestions | Low | Enhancement for future iteration |
| Search analytics | Low | No tracking of queries — backend contract specifies endpoints |
