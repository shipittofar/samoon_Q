## 1. Header Spacing & Hero Position

**File:** `src/components/layout/Header.tsx` (line 86–88), `src/app/page.tsx` (line 92)

**Finding:**  
Header is `fixed top-0 h-16` (64 px). Hero content has `pt-20` (80 px) which provides 16 px of breathing room above the pill badge. Background image fills the full viewport starting at `top: 0`, correctly extending behind the transparent header. No content is hidden.

**Status:** ✅ Correct by design. Intentional transparent-overlay pattern.

## 2. Scroll Transition

**File:** `src/components/layout/Header.tsx` (lines 61–65, 79–84)

**Finding:**  
Threshold is `scrollY > 20`. Transition is `duration-300` (300 ms). On scroll, the header transitions:

```
bg-transparent
→ bg-[var(--card)]/90 backdrop-blur-xl border-b shadow-sm
```

In **light mode**: `var(--card)` = `#ffffff`. The header becomes 90 % white with blur. The 300 ms transition prevents a flash. Blur activates simultaneously.

**Issue:** In light mode, when scrolled up past the hero gradient, the white header may briefly show the hero image through the 10 % transparency gap before blur fully kicks in. Minor but noticeable on low-end devices.

**Severity:** 🟢 Polish — no jarring flash, only subtle perceptibility.

## 3. Header Transparency — Text Contrast (CRITICAL)

**File:** `src/components/layout/Header.tsx` (lines 99–127)

**Finding:**  
When `scrolled === false` (transparent header over hero), the logo and nav links use:

- Logo text: `text-[var(--fg)]` → in light mode = `surface.900` = `#1c1917` (near black)
- Nav link inactive: `text-[var(--fg-muted)]` → in light mode = `surface.500` = `#78716c` (medium gray)

The hero background has a `from-black/85` left-side gradient. A dark text colour on a near-black background produces near-zero contrast — **WCAG AA failure** (contrast ratio < 1.5:1).

In dark mode this is fine: `--fg` = `surface.50` = near white, which reads against the dark overlay.

**Root cause:** The Header uses the same semantic colour tokens regardless of whether it is transparent-over-dark or opaque-over-light. No page-context awareness exists.

**Recommended solution:**  
Add `const isTransparentHero = pathname === '/' && !scrolled` and apply conditional white text classes to logo, nav links, and icon buttons when true.

**Severity:** 🔴 Critical — legally fails WCAG AA contrast; visible UX breakage in light mode.

## 4. Navigation Items — Labelling & Destination

**File:** `src/components/layout/Header.tsx` (lines 15–19)

```typescript
const PLATFORM_NAV: NavItem[] = [
  { href: '/discover',     label: 'Discover'      },
  { href: '/reservation',  label: 'Reservations'  },
  { href: '/restaurant',   label: 'About'         },   // ← problem
]
```

**Issues:**

| Item | Label | Destination | Problem |
|------|-------|-------------|---------|
| `/restaurant` | "About" | Business-owner landing | "About" implies platform info; `/restaurant` is partner sign-up. The label actively misleads visitors. |
| `/reservation` | "Reservations" | Reservation flow | Fine as a feature link, but placing it at the same level as "Discover" implies it is a standalone product rather than a platform feature. Low discovery friction though — keeping it is acceptable. |

**Recommended solution:**  
Rename `/restaurant` nav label from `'About'` to `'For Business'`. This immediately communicates who that destination is for.

**Severity:** 🟡 Important — first-time visitors testing "About" to learn what Savor is are routed to a partner sign-up page.

## 6. Hero Messaging — Headline Scope Mismatch

**File:** `src/app/page.tsx` (lines 100–104)

```html
<h1>
  Find Great
  <span>Restaurants</span>
  Near You.
</h1>
```

**Issue:**  
The headline promises only restaurants. The subheadline (line 105) says "Discover restaurants, cafés, bars, food trucks, and more." The pill badge (line 97) says "500+ businesses on Savor." The category chips and CTAs all reinforce a multi-type marketplace.

The headline contradicts everything around it. It positions Savor as a restaurant-only app which:
1. Under-sells the platform
2. Misleads potential bar, café, or food-truck visitors
3. Reduces click-through from non-restaurant segments

**Root cause:** Headline was set before the platform was rebranded to multi-business-type in P8.8.x.

**Recommended solution:**  
Replace "Restaurants" with a category-agnostic word: "Local Businesses", "Great Places", or "Food & Drink".

Example:
```
Find Great
Local Businesses
Near You.
```

Or more aspirational:
```
Discover
Local Food & Drink
Near You.
```

**Severity:** 🔴 Critical — messaging mismatch causes brand confusion on the most visible element.

## 7. Search Input Accessibility

**File:** `src/app/page.tsx` (lines 113–118)

```html
<input type="text" name="q" placeholder="Search restaurants, cafés, bars…" />
```

**Issue:**  
No `<label>` element. `placeholder` text is not a substitute for a label per WCAG 1.3.1 and 3.3.2. Screen readers will announce the input with no accessible name.

**Recommended solution:**  
Add a visually-hidden `<label>`:
```html
<label for="hero-search" class="sr-only">Search for restaurants, cafés, and bars</label>
<input id="hero-search" ... />
```

**Severity:** 🟡 Important — accessibility failure.

## 8. Duplicate `<nav>` Without aria-label

**File:** `src/components/layout/Header.tsx` (lines 112, 302)

Both desktop and mobile navs render `<nav>` without aria-label. Screen readers announce two "navigation" landmarks with no way to distinguish them.

**Recommended solution:**
```html
<nav aria-label="Main navigation" class="hidden md:flex …">
<nav aria-label="Mobile navigation" class="px-4 …">
```

**Severity:** 🟡 Important — assistive technology UX.

## 9. Skip-to-Content Link Missing

**File:** `src/components/layout/Header.tsx`

**Issue:**  
No skip-to-content link exists anywhere in the app. Keyboard users must tab through all header items (logo, 3 nav links, 5+ icon buttons) on every page load before reaching main content. WCAG 2.4.1 (bypass blocks) — Level A.

**Recommended solution:**  
Add a visually-hidden, focus-visible skip link at the top of the `<header>`:
```html
<a href="#main-content" class="sr-only focus:not-sr-only focus:fixed …">
  Skip to main content
</a>
```
And add `id="main-content"` to the hero section in `page.tsx`.

**Severity:** 🔴 Critical — WCAG Level A failure.
