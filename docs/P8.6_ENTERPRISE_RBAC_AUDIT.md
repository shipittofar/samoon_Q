### Phase 2 — Multi Role Management (`RoleAssignment` store)

**Files modified:**
- `src/types/rbac.ts` — Added `RoleAssignment` interface
- `src/stores/index.ts` — Added `roleAssignments` state with full CRUD

**`RoleAssignment` fields:**
- `id`, `userId`, `tenantId`, `role` — core identity
- `branchId?` — optional branch scope (undefined = tenant-wide)
- `enabled` — soft disable without removal
- `priority` — conflict resolution order (higher = evaluated first)
- `expiresAt?` — ISO timestamp for time-limited assignments
- `assignedBy`, `assignedAt` — audit trail

**Store actions:** `addRoleAssignment`, `removeRoleAssignment`, `updateRoleAssignment`, `getRoleAssignmentsForUser`, `getActiveRoleAssignmentsForUser` (filters by `enabled=true` AND `expiresAt` not past).

---

### Phase 3 — Branch-Scoped Permissions

**Resolution order (highest priority first):**
1. User Deny override
2. User Allow override
3. Branch role permissions (via `branchId` on `RoleAssignment`)
4. Tenant-wide role permissions
5. Default deny

**Store support:** `BranchRoleAssignment` (P8.5), `RoleAssignment.branchId` (P8.6) — branch role assignments are resolved in `getActiveRoleAssignmentsForUser`.

### Phase 7 — Navigation Audit

Navigation is derived entirely from role-based permissions via `getAdminNav()`. All nav items in the registry declare a `permissionKey` and `featureFlagKey`. The `useAdminNav()` hook (P7) filters items by effective permissions + feature flags. No hardcoded nav items.

### Phase 9 — Permission Dependency Rules

**Files modified:**
- `src/services/permission.service.ts` — Added `PERMISSION_DEPENDENCIES`, `validatePermissionGrant()`, `resolveWithDependencies()`

**`PERMISSION_DEPENDENCIES`:** 30 rules covering:
- `orders.manage` requires `orders.view`
- `menu.manage` requires `menu.view`
- `staff.manage` requires + implies `staff.view`
- `payments.refund` requires `payments.process`
- `analytics.export` requires `analytics.view`
- `audit.export` requires `audit.view`
- `audit.manage` requires `audit.view`
- ... and 23 more rules

**`validatePermissionGrant(permission, currentEffective)`:**
Returns `DependencyValidationResult` with `missingRequirements`, `impliedGrants`, `conflicts`, `hasIssues`.

**`resolveWithDependencies(toGrant, currentEffective)`:**
Returns array of permissions to grant (including auto-resolved requirements and implied grants).
