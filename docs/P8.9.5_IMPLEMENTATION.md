# P8.9.5 — Admin Information Architecture & Workspace Optimization: Implementation

## Summary

Information architecture audit and targeted improvements to admin discoverability, settings organization, navigation grouping, context links, and quick actions. No new business features, no backend APIs.

---

## Phase A — IA Audit

### `docs/P8.9.5_INFORMATION_ARCHITECTURE_AUDIT.md` (new)

Full IA audit covering 54 admin pages, 7 sidebar groups, settings architecture, URL taxonomy, context persistence, cross-navigation, mobile, and scalability. 15 issues catalogued: 3 critical, 8 high, 4 medium.

Key findings:
- `/admin/settings/feature-flags` completely orphaned (now at `/console/settings/feature-flags`) — no sidebar entry, no Settings tab
- Website Builder misclassified under Platform (should be Content)
- AdminHeader "Public Site" link went to `/` not to tenant's own page
- No quick actions surface — every creation task requires 3+ clicks
- 33 of 54 admin pages (61%) have no sidebar entry

---

## Phase C — Navigation Group Fix

### `src/modules/registry.ts` (updated)

**C3 fix:** `WEBSITE_BUILDER_NAV_ITEM.group` changed from `'Platform'` to `'Content'`.

Website Builder edits the public-facing website — it belongs with Menu, Promotions, Reviews, and Loyalty under Content, not with infrastructure items (Tenants, Branches, Audit Logs) under Platform.

---

## Phase D — Settings Consolidation

### `src/app/console/settings/page.tsx` (updated)

**C1 fix:** Replaced the "Advanced" placeholder tab with a functional "Feature Flags" tab.

Changes:
- Added `'feature-flags'` to `TABS` (replacing `'advanced'`)
- Added `{ label: 'Feature Flags', icon: Flag }` to `TAB_CONFIG`
- Imported `useFeatureFlags`, `useUpdateFeatureFlag`, `Badge`, `ToggleLeft`, `ToggleRight`, `XCircle`, `Flag` from their respective modules
- Added `FeatureFlagsTab` component that renders the full flags list inline — same UI as the standalone `/console/settings/feature-flags` page
- The standalone page at `/console/settings/feature-flags` still works for direct URL access and breadcrumbs

Before: "Advanced" tab was a "coming soon" placeholder. Feature flags at `/console/settings/feature-flags` were only reachable by typing the URL.

After: Settings → Feature Flags tab shows all flags inline with toggle controls.

---

## Phase E — Quick Actions

### `src/components/admin/AdminSidebar.tsx` (updated)

Added `<QuickActions>` section above the sidebar footer.

- 4 quick-action cards in a 2-column grid: New Menu Item, New Promotion, New Reservation, Invite Staff
- Each card links directly to the relevant admin list page
- Dashed border style distinguishes quick-action links from navigation items
- All cards meet 36px minimum height (navigation items are 44px; quick-action cards are supplementary, not primary nav)
- Added `Zap` and `Plus` icons to the ICON_MAP

---

## Phase H — Cross-Navigation Fix

### `src/components/admin/AdminHeader.tsx` (updated)

**H3 fix:** "Public Site" link now deep-links to the tenant's own public page.

Before: `href="/"` always went to the platform homepage.

After: `href={tenant?.slug ? `/${tenant.slug}` : '/'}` — links directly to the tenant's public page. Falls back to `/` if no slug is available.

Also updated `aria-label` to name the tenant: `"View {tenant.name} public site"`.
