# P10.4.12 — Legacy RBAC Engine Removal (Compatibility Layer Retirement)

**The legacy RBAC engine has been fully retired.**

`src/services/rbac.service.ts` is deleted. `rbacService`, `ROLE_PERMISSIONS`,
`CUSTOMER_PERMISSIONS`, `STAFF_PERMISSIONS`, `OWNER_PERMISSIONS`,
`ADMIN_PERMISSIONS`, `hasPermission()`, and `LegacyPermission` no longer
exist anywhere in `src/`. Every previous runtime caller was already
migrated in P10.4.9–P10.4.11, so this phase's audit found zero live
dependencies — the removal proceeded to completion, not an abort.

five permission-array constants above (`ROLE_PERMISSIONS` and its four
sub-tables) — all five were removed together, since the whole file
became dead once its one export was gone.

## Type Cleanup

`LegacyPermission` was confirmed unused repository-wide (besides its own
declaration and the one regression test asserting its existence) before
removal. Removed from `src/types/index.ts`; the regression test in
`phase7-rbac.test.ts` was updated to assert its absence instead of
deleted outright, matching this codebase's established pattern for
retired types (P10.4.6 `Role`, P10.4.7 `Permission`).

`UserRole` was **not** touched, per this phase's explicit instruction.
It remains in `src/types/index.ts` as the `User.role` identity field's
type, used for authentication identity, UI display, and observability —
none of which route through the now-deleted legacy engine.

No other compatibility type was found to be newly unused as a result of
this phase's removal.
