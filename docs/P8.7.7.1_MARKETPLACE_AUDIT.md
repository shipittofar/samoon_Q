## 4. Architecture

### Data Flow

```
/discover (Server Component)
  └── DiscoverClientPage (Client Component)
        └── usePublicTenants()           ← React Query, queryKey: ['public-tenants']
              └── tenantService.getTenants()
                    └── select: active|trial tenants only (slug !== 'default')
```

### Isolation Guarantees

- **Query key**: `['public-tenants']` — separate from all tenant-scoped admin queries
- **No tenantId in key**: Public marketplace is cross-tenant by design; there is no single active tenant context
- **No RBAC guard**: `usePublicTenants` does not check `usePermission` or `useRbacStore`
- **No store mutations**: The page reads data only; it does not touch `useTenantStore`, `useCartStore`, `useBranchStore`, or any other persisted store
- **No cross-tenant leakage**: Each business card links to `/{slug}/menu/{primaryBranchSlug}` — the tenant's own public namespace

### Filtering Logic

`matchesSearch(name, meta, businessTypes, query)` checks (OR across):
1. Tenant name (case-insensitive substring)
2. `meta.city`
3. `meta.cuisines[]`
4. `meta.tags[]`
5. `meta.description`
6. Business type labels (e.g., `cafe` → `"Café"`)

`matchesCategory(businessTypes, category)` returns `true` if category is empty (no filter) or if `businessTypes` includes the selected category.

## 6. Key Design Decisions

### Default Tenant Exclusion
The `MOCK_TENANTS` object contains a `default` key (`{ ...DEFAULT_TENANT }`) used as a system fallback. `usePublicTenants` excludes it with `t.slug !== 'default'` to prevent a tenant without marketplace metadata from appearing in the discovery feed.

### Debounced Search
Search state is split into `rawQuery` (immediate, drives input display) and `searchQuery` (debounced 300 ms, drives filter). This prevents excessive re-renders and keeps the UI responsive.

### Section Architecture
The discovery view shows 4 sections when no filter is active: Featured, Popular Right Now, Newly Opened, All Businesses. When a search or category filter is active, a flat filtered results view replaces the sections.

### No `isNew` in Mock Default
The `isNew` field is optional in `MarketplaceMeta`. Only tenants marked explicitly as new show in the "Newly Opened" section.

## 11. Next Steps (P8.7.7.2)

The foundation is designed for direct extension:
- `BusinessCard` accepts `tenant` + `meta` — no changes needed to add more fields
- `MarketplaceMeta` is extensible — add fields without breaking existing consumers
- `matchesSearch` is a pure function — easy to extend with additional search vectors
- `/discover` layout is section-based — add new sections (e.g., "Near You") without restructuring
