## 2. Architecture Review

### 2.1 Admin Layout Stack

```
Global Header (fixed, h-16)                   ← src/components/layout/Header.tsx
Admin Context Bar (fixed, top-16, ~36px)      ← AdminContextBar (tenant + branch switchers)
Breadcrumb row (same bar)                     ← AdminBreadcrumbs
  └─ Body (pt-28)
       ├─ AdminSidebar (fixed 224px, left)    ← AdminSidebar
       └─ <main> (flex-1, px-4 sm:px-6)
```

**Issues:**
- The global customer-facing `<Header>` renders inside `/console/*` routes — it is a full consumer-facing header with Cart, Notification bell, User menu, Language picker, theme toggle, and public nav links. Admin staff see a shopping cart icon.
- Admin body starts at `pt-28` (header 64px + context bar ~36px) which is correct, but the value is hard-coded and will break if either bar height changes.
- The sidebar is `w-56` (224px) with no collapse state. On desktop it is always 224px wide; no narrow/icon-only mode exists.
- `<main>` has `lg:ps-8` which means on large screens it only adds 32px of extra left padding — no sidebar offset is applied, so on `lg` screens the content renders under the sidebar.

### 2.2 `/console` Root — The Missing Dashboard

**Critical issue:** `/console/page.tsx` contains only:

```typescript
export default function AdminIndexPage() {
  redirect('/console/orders')
}
```

Every role lands on `/console/orders` — regardless of whether they can view orders. This means:
- Kitchen staff (`kitchen.view`, `kitchen.manage` only) land on Orders, see `<AccessDenied>`, and must manually navigate to Kitchen Display.
- Marketing staff (`analytics.view`) land on Orders, see `<AccessDenied>`, and must navigate to Analytics.
- Support staff (`customers.view`, `reservations.view`) land on Orders, see `<AccessDenied>`.
- Platform admins land on Orders instead of Tenants.

There is no role-aware dashboard. Every role sees the same `/console/orders` redirect.

## 4. Navigation Audit

### 4.1 Sidebar Structure Issues

The sidebar is a flat, unsorted list of 20 items (for Owner/Admin) with no visual grouping.

**Current order (Restaurant module):**

```
Dashboard (always shown, hardcoded)
Analytics
Orders
Menu
Customers
Reservations
Reviews
Loyalty
Kitchen Display
Tenants
Staff
Branches
Branch Analytics
Audit Logs
Notifications
Operations
Settings
Permissions
Roles
Users
Website Builder
```

**Issues:**
- Zero grouping — Operations items (Orders, Kitchen Display) mixed with Analytics, mixed with Platform (Tenants, Permissions, Roles).
- "Branch Analytics" appears separately from "Branches" — no hierarchy indication.
- "Permissions", "Roles", "Users" appear at the bottom — rare admin tasks buried below everything.
- "Website Builder" is the last item — no logical reason.
- No icons on nav items (except Dashboard which has `LayoutDashboard`).
- `ChevronRight` appears on the active item — fine, but no sub-menu nesting is supported.
- No section headers (e.g., "Operations", "People", "Analytics", "Platform").

### 4.2 Missing Nav Items

| Missing | Where It Belongs | Who Needs It |
|---|---|---|
| Quick "New Order" shortcut | Top of sidebar or Quick Actions | Cashier, Manager |
| Quick "Seat Table" shortcut | Top of sidebar or Quick Actions | Waiter, Cashier |
| Profile / Account settings | Sidebar footer or header user menu | All |
| Help / Documentation | Sidebar footer | All |
| Keyboard shortcut reference | Somewhere discoverable | All |
| Feedback / Report a bug | Sidebar footer | All |

### 4.3 Dead / Confusing Items

| Item | Issue |
|---|---|
| "Branch Analytics" | Duplicates "Branches" — should be a sub-route or tab |
| "Operations" | Unclear what this is from the label — contains Live Orders + Kitchen + Staff + SLA |
| "Kitchen Display" + "Operations" | Both show kitchen info — overlapping purpose |
| "Permissions" + "Roles" + "Users" | Three separate pages for staff/access management — could be tabbed under a single "People" section |

### 4.4 Breadcrumb Issues

`AdminBreadcrumbs.tsx` builds breadcrumbs from the URL path segments. Issues:

- Breadcrumbs only render when there are more than 2 crumbs (i.e., `/console/X/Y` — not `/console/X`). So single-depth admin pages (e.g., `/console/orders`) show **no breadcrumbs** at all.
- ID segments produce `"Orders Order abc12345…"` instead of an actual order number or customer name.
- Segment `'analytics'` is not in `SEGMENT_LABELS` — renders as "Analytics" via the fallback capitalizer which works but is inconsistent.
- No `overrides` prop is used anywhere in the actual admin pages — the API exists but is dead.
- Breadcrumbs container is inside the context bar along with AdminContextBar — they share horizontal space. On narrow screens, the branch switcher and breadcrumbs compete for space and truncate.

### 4.5 Header Issues (Global Header in Admin)

The consumer-facing `<Header>` renders on all admin routes. Problems:

| Item | Admin relevance |
|---|---|
| Shopping cart (with count badge) | Not relevant to admin staff |
| Public nav links (Menu, Reservation, About) | Admin staff don't need these |
| "For Business" link | Admin users are already in "for business" |
| Language picker | Relevant |
| Theme toggle | Relevant |
| Notification bell | Should be admin notification context, not customer context |
| User menu → Profile, Orders, Favorites | Customer-focused; admin users have no "My Orders" |

The header is not context-aware: it shows the same consumer shell in admin as on the public site.

## 6. Dashboard Cards Audit

### 6.1 `/console` — No Dashboard

There is no dashboard. The route immediately redirects to `/console/orders`. This means:
- Zero "today's summary" view for any role.
- No quick-action grid.
- No pending-work indicators.
- No welcome or onboarding prompt.

### 6.2 `/console/orders` (de facto dashboard for most roles)

The orders page functions as the main admin view for most roles. It has:
- Status filter tabs (Pending, Accepted, Preparing, Ready, Delivered, Cancelled, All)
- Search box
- Branch filter
- Bulk action bar
- Order cards/rows

It is a functional list view but not a dashboard. It shows no:
- Revenue summary
- Comparison vs yesterday
- Average order time
- Pending items requiring action

### 6.3 `/console/analytics`

Full analytics dashboard exists with KPI cards, sparklines, expandable charts. Issues:
- Very deep — all metrics in one page with accordion sections. No "top 3 things you need to know today".
- No role-specific default view — Marketing sees the same thing as Owner.

### 6.4 `/console/kitchen`

Kitchen Display exists with fullscreen mode and refresh intervals. Issues:
- Reached by navigating sidebar — not the default for kitchen staff.
- No shift-start state (e.g., "Shift starts at 14:00").

### 6.5 `/console/operations`

Full realtime operations dashboard: Live Orders, Live Reservations, Branch Status, Staff Presence, Kitchen Display, SLA Monitor, Activity Feed. Well-built. Issues:
- Not linked from any role's first screen.
- Not mentioned in sidebar for lower roles.
- "Operations" label is too generic — not obvious that this is the realtime command center.

### 8.1 Sidebar

- Hidden by default on mobile; toggled by `<Menu>` button in context bar.
- `Menu` button uses `aria-label="Open admin menu"` — ✅ accessible.
- Overlay (black/50 backdrop) closes on click — ✅.
- Sidebar is `w-56` (224px) which is reasonable for mobile.
- Footer logout and "Back to Public Site" visible on mobile ✅.

**Issues:**
- No swipe-to-close gesture on mobile.

- No bottom navigation bar for mobile — sidebar drawer is the only navigation.

### 8.2 Context Bar

- Context bar is `flex items-center justify-between gap-2 px-4 py-1.5`.
- On small screens, breadcrumbs and context switchers share one row — gets very tight.
- Tenant name is `hidden sm:flex` — invisible on mobile (320-640px).

### 8.3 Tables and Lists

Not audited in detail. General risk: admin tables with 6+ columns do not mention responsive handling. Likely overflow on mobile.

Nav items in sidebar: `py-2 px-3` — approximately 36px height. Below the recommended 44px minimum for touch targets.

## 9. Accessibility Audit

### 9.1 Sidebar

- `<aside>` with `aria-label="Admin navigation"` ✅
- `<nav>` with `role="navigation" aria-label="Admin menu"` — redundant (`role="navigation"` is the default for `<nav>`) but harmless.
- `aria-current="page"` on active link ✅
- Dashboard link hardcoded above navItems — correct for always-accessible item ✅
- Overlay has `aria-hidden="true"` ✅
- Close button has `aria-label="Close sidebar"` ✅

**Issues:**
- No focus trap in mobile sidebar — pressing Tab will reach content behind the overlay.
- No `aria-expanded` on the hamburger menu button (in AdminLayout, the `<Button>` for `Menu` icon has no `aria-expanded` state tied to `sidebarOpen`).
- Sidebar footer buttons have no accessible description for what "Back to Public Site" navigates to.

### 9.2 Breadcrumbs

- `<nav aria-label="Breadcrumb">` ✅
- `aria-current="page"` on last crumb ✅
- Home crumb uses `aria-label="Home"` ✅

**Issues:**
- `Home` icon crumb (`/`) in admin breadcrumbs links to public site root — admin users clicking "Home" in breadcrumbs leave the admin. Should link to `/console`.

### 9.3 Context Bar

- Branch switcher: `<button>` with no `aria-label` — only visual text. Accessible via text content.
- Dropdown menus: no `aria-haspopup="listbox"`, no `role="listbox"` on the dropdown list.

### 9.4 Header (in Admin)

- Header has "Skip to main content" link ✅
- `<header>` landmark present ✅
- Admin-specific: no `<main id="main-content">` in the admin body — the skip link target may not exist.

## 11. Specific Page Issues

### 11.1 AdminBreadcrumbs — Home Link Bug

```typescript
crumbs.push({ label: 'Home', href: '/' })
```

The first crumb always links to `/` (public site root). In admin, Home should be `/console`.

### 11.2 No `<main id="main-content">` in Admin Layout

The header has a skip-to-content link targeting `#main-content`. The admin layout's `<main>` element has no `id="main-content"`. The skip link is broken in admin.

### 11.3 Sidebar `pt-16` + `lg:static`

The sidebar has `pt-16` on mobile to clear the global header. On desktop (`lg:static`) it is removed from fixed positioning and becomes a column in flexbox. The `pt-16` is also removed on desktop via `lg:static`. However, the parent `<div className="flex pt-28 min-h-screen">` provides the vertical offset for the entire body. On desktop, the sidebar renders within this `pt-28` offset — but the sidebar header (`flex items-center justify-between px-4 py-3`) is the first visible element, which aligns correctly. **OK for desktop but the mobile sidebar header may overlap the global header.**

On mobile, the sidebar is `fixed inset-y-0 start-0 pt-16` — the `pt-16` accounts for the global header only, not the context bar. The sidebar content is visible under the admin context bar (which is at `top-16`). **The sidebar slides behind the context bar on mobile.**

### 11.4 `orders.view` Granted to Kitchen but Not on Their Workflow

`kitchen` role has `orders.view` and `kitchen.view/manage`. Kitchen staff see Orders in their sidebar but their actual workflow is Kitchen Display. This creates a confusing sidebar where the first item is their secondary workflow.

### 11.5 Promotions Gating

`PROMOTIONS_NAV_ITEM` is not in the shared nav constants reviewed — promotions is in the analytics-only stack. Marketing has `promotions.view/manage`. Where does Promotions appear in their sidebar? The nav item is defined per-module but the permissionKey gating should show it for marketing. **Verify in implementation.**

## 13. Recommended Architecture for Phase B–J

### 13.1 Role-Aware Dashboard Router

Replace the static redirect in `/console/page.tsx` with a client component that reads the user's P7 roles and redirects to their appropriate dashboard:

| Role(s) | Dashboard |
|---|---|
| `owner`, `admin` | `/console` (new dashboard) |
| `manager` | `/console` (new dashboard) |
| `cashier` | `/console/orders` |
| `kitchen` | `/console/kitchen` |
| `marketing` | `/console/analytics` |
| `support` | `/console/customers` |
| Platform (`tenant.view`) | `/console/tenants` |

### 13.2 Sidebar Grouping Structure

```
[OPERATIONS]        Orders, Kitchen Display, Reservations, Operations

[CONTENT]           Menu, Reviews, Promotions, Loyalty

[CUSTOMERS]         Customers

[ANALYTICS]         Analytics, Branch Analytics

[PEOPLE]            Staff, Permissions, Roles, Users

[PLATFORM]          Tenants, Branches, Website Builder, Audit Logs

[SYSTEM]            Notifications, Operations (realtime), Settings
```

Each group has a small section header label (8px text, uppercase, muted) and 4px top margin.

### 13.3 Admin-Specific Header

The admin layout should suppress the consumer header and render a slimmer admin-specific top bar containing:
- Logo + "Admin" label (links to `/console`)
- Active tenant + branch (or promote AdminContextBar into this bar)
- User avatar + name + role chip
- Notifications (admin-scoped)
- Theme toggle
- Link to public site (with external-link icon)

### 13.4 Dashboard Cards Per Role

Each role's dashboard should show 3–5 cards relevant to their workflow, plus a "Quick Actions" row.

| Role | Dashboard Cards |
|---|---|
| Owner/Admin | Revenue today, Orders pending, Reservations today, Active staff, Branch status |
| Manager | Orders queue, Table availability, Staff on shift, Today's reservations |
| Cashier | Open orders, Tables needing attention, Quick: New Order |
| Kitchen | Pending tickets, Avg ticket time, Quick: Open KDS |
| Marketing | Active promotions, Loyalty members, Analytics snapshot |
| Support | Open support cases, Today's reservations, Recent customer contacts |
| Platform Admin | Total tenants, Active/suspended counts, Recent provisioning |

### 13.5 Contextual Empty States

| Page | Empty state headline | CTA |
|---|---|---|
| Menu (no items) | "Your menu is empty" | "Add first item" |
| Staff (no staff) | "No team members yet" | "Invite your first staff member" |
| Promotions (none) | "No active promotions" | "Create a promotion" |
| Reservations (none today) | "No reservations today" | "View all reservations" |
| Customers (none) | "No customers yet" | Link to menu / public site |

## 15. Audit Conclusion

The admin foundation is structurally sound — AuthGuard, PermissionGuard, RBAC filtering, breadcrumb infrastructure, branch/tenant switchers, and the sidebar are all implemented. However, the UX layer has significant gaps:

1. **No role-aware landing** — 3 of 9 roles hit `<AccessDenied>` immediately after login.
2. **No meaningful dashboard** — `/console` is a redirect; no role has a "home base".
3. **Flat navigation** — 20 items, no groups, no icons, no hierarchy.
4. **Consumer header in admin** — shopping cart and public nav visible to staff.
5. **Identity gaps** — users cannot see their own role, active context, or environment.
6. **Accessibility gaps** — focus trap, skip-link target, and ARIA on switchers missing.
7. **Mobile gaps** — context bar truncates, sidebar overlaps, touch targets undersized.

Phase B–J implementation should address these in priority order: role-aware routing first, then admin chrome, then sidebar redesign, then dashboards per role, then empty states, then mobile polish, then accessibility hardening.
