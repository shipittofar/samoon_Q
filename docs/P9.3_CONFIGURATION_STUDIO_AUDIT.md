# P9.3 — Configuration Studio UX Audit

> Phase A of P9.3. Audits the Configuration Center built in P9.1.3/P9.2
> (`ConfigurationModulePage`, `ConfigurationFieldRow`, the module index page)
> against enterprise admin benchmarks, to decide what P9.3 must replace vs.
> keep. No code changes in this document — see
> `docs/P9.3_CONFIGURATION_STUDIO.md` for what was actually built.
>
> Last updated: 2026-07-05

---

## 1. What exists today

- **Module index** (`/console/settings/configuration`) — a static card grid,
  one card per registered module, linking to its module page. No search, no
  grouping, no pinning, no recents.
- **Module page** (`/console/settings/configuration/[moduleId]`) — a single
  scrollable column: sticky header (name/description/lifecycle/environment/
  version/last-modified), a search box, collapsible sections of
  `ConfigurationFieldRow`s, and a save bar that appears at the bottom only
  while dirty.
- **Field row** — label, badges, description, control, preview, inline
  validation, and a toggle-able inline "inspector" panel (path/default/
  current/resolvedFrom/last 5 audit entries) triggered by a small History
  icon.
- **Collection field** (P9.2) — renders `ConfigurationCollectionTable`
  instead of a control: search/filter/group/sort/bulk-select/statistics,
  row click opens `ConfigurationEntityDrawer` (7 tabs).

This is functionally complete and genuinely metadata-driven (Rule 7), but it
was built one module page at a time, not as a cohesive **workspace**. That
gap is P9.3's entire mandate.

## 2. Benchmark comparison

| Dimension | Shopify Admin | Stripe Dashboard | Cloudflare Zero Trust | **Configuration Center (current)** |
|---|---|---|---|---|
| **Navigation** | Persistent left rail, grouped, searchable, pinned | Left rail + top search (Cmd+K) | Left rail with nested sections, collapsible | Only a card grid to jump between modules — no persistent module list once inside one, no back-and-forth without a full page nav |
| **Hierarchy** | 2-pane (nav + workspace), settings pages get a 3rd contextual panel | 2-pane, contextual side panel on demand | 3-pane (nav / list / detail) | 1 pane (a single scrolling column); no dedicated space for metadata/inspection — it's an inline expando fighting for the same vertical space as the control itself |
| **Density** | High but breathable — 40px rows, generous but not wasteful | Medium-high, information-dense tables | High, compact rows with expand-on-demand | Medium — each field is a full card with 12–16px padding; fine for ~20 fields, cumbersome for Authentication's 17 across 5 sections stacked vertically |
| **Discoverability** | Search-first (Cmd+K everywhere) | Search + breadcrumbs + "jump to" | Search + breadcrumbs | Per-module search only (P9.1.3 Phase G); nothing global — finding "OTP length" requires already knowing it's under Authentication |
| **Inspector** | Contextual side panel per resource | Side panel (e.g. event detail) | Side panel per rule/policy | Inline expando *inside* the row — no persistent selection concept, can't compare two fields' inspectors side by side, and it competes for the same scroll position as the edit control |
| **Forms/Save** | Sticky bottom bar, Discard/Save, non-blocking | Same pattern | Same pattern | Already matches this pattern well (P9.1.3 Phase J) — a real strength to preserve, not replace |
| **Keyboard flow** | Cmd+K, Esc, Tab order, arrow nav in lists | Cmd+K, Esc | Similar | None beyond native browser Tab order — no Ctrl+S, no Ctrl+K, no Esc-to-close |
| **Accessibility** | WCAG AA, full ARIA on custom controls | Same | Same | Reasonable ARIA on individual controls (role=switch, aria-expanded, aria-label) inherited from P9.1.3, but no live-region announcements, no documented focus-management strategy for the (currently nonexistent) side panels |
| **Responsiveness** | Nav collapses to a drawer/sheet on mobile | Similar | Similar | Single column already degrades reasonably on narrow viewports since there's no multi-pane layout yet — but that's an accident of the current architecture being simple, not a designed responsive strategy |
| **Motion** | Subtle, fast (150–200ms), respects reduced-motion | Same | Same | Drawer/Modal (shared UI kit) already use spring transitions via framer-motion; the module page itself has no motion (section collapse/save bar have no transition) |
| **Loading** | Skeletons matching final layout | Same | Same | None — modules resolve synchronously from the in-memory mock store, so there's nothing to show a skeleton for *today*, but the absence of any loading affordance will be wrong the moment a real backend introduces latency |
| **Empty states** | Illustrated, actionable ("no results — try X") | Text + icon, actionable | Similar | One generic "No settings match ⟨query⟑" string; no dedicated empty state for an empty collection table (P9.2 shows "No matches." as plain table text), no empty state anywhere for history/audit |
| **Command palette** | None (search-first instead) | Cmd+K present | None | Absent entirely |
| **History/Audit** | Full changelog per resource | Full event log | Full audit log with diff | Only the last 5 entries inline per field, no dedicated timeline view, no rollback action, no cross-field history |
| **Compare** | N/A (not resource-versioned) | N/A | Version diff on rule changes | Absent — no way to compare current vs. a previous version, or Platform vs. Tenant override, side by side |

## 3. Findings, ranked by impact

1. **No persistent workspace shell.** Every other benchmark uses a
   nav/workspace/inspector 2-or-3-pane layout that stays put while the
   *content* changes. Today, moving between modules is a full route
   navigation with no shared chrome — you lose your place. This is the
   single highest-impact gap and the reason Phase B (Studio Layout) is
   first.
2. **No global search/command surface.** Every benchmark treats Cmd/Ctrl+K
   as table stakes for an admin surface with more than a handful of
   settings. Fixing this compounds in value with every future module
   (Languages, Themes, Payments, …) registered.
3. **Inspector is inline, not a first-class surface.** The existing inline
   expando (`ConfigurationFieldRow`'s `showInspector` state) is fine for
   "one more detail," not for the multi-tab depth (Inheritance/Dependencies/
   Audit/Preview/Statistics/Documentation) every benchmark's side panel
   provides. It also cannot be extended without bloating every field row.
4. **No keyboard-driven workflow.** Ctrl+S / Ctrl+K / Esc are absent. For a
   surface admins live in daily, this is a real productivity gap versus
   every benchmark.
5. **History is a stub, not a feature.** 5 inline entries with no filter,
   search, or rollback falls well short of Stripe/Cloudflare's audit logs.
6. **No compare/diff view.** Given the system already models a 4-level
   inheritance chain (Platform → Tenant → Branch → User) with real
   `resolvedFrom` data, not visualizing that chain is leaving a genuinely
   distinguishing feature (most SaaS admin panels don't have inheritance at
   all) invisible to the people who'd benefit most from seeing it.
7. **What already works and must not be re-litigated:** the sticky
   save-bar pattern (Phase J), the metadata-driven control/badge/preview
   dispatch (Rule 7), the dependency engine reacting to live edits, and the
   P9.2 collection table/drawer — these already match or exceed the
   benchmarks for their specific job. P9.3 wraps and extends these, it does
   not rebuild them.

## 4. What P9.3 must build (mapped to phases)

| Gap | Phase |
|---|---|
| No persistent 3-pane shell | B — Studio Layout |
| No pinned/recent/grouped module nav | C — Studio Navigation |
| No global toolbar/breadcrumb/status | D — Global Toolbar |
| Inspector trapped inline | E — Inspector Panel |
| Inheritance chain invisible | F — Configuration Diff (inheritance tree) |
| Save bar needs shortcut hints + reuse | G — Sticky Save Experience |
| No global search/command surface | H — Command Palette |
| No keyboard-driven workflow | I — Keyboard Shortcuts |
| Preview limited to 4 kinds | J — Visual Preview System |
| History stub, no rollback/filter | K — History & Timeline |
| No compare/diff view | L — Compare Mode |
| Empty states minimal/inconsistent | M — Empty States |
| No loading affordance | N — Loading Experience |
| No designed motion system | O — Motion System |
| No designed responsive strategy | P — Responsive Experience |
| A11y gaps (live regions, focus mgmt) | Q — Accessibility |
| Spacing/radius ad hoc per component | R — Design Tokens |

Every item above is framework-level — driven by the registry, by
`field.collection`/`field.preview`/`field.dependency` metadata, or by the
audit/service layer — and none references Authentication or Countries by
name, per the phase's explicit mandate.
