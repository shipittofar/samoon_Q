## 2. Findings

### H1 — CRITICAL: AccessDenied hardcodes /console/orders for all roles

**File:** `src/components/admin/AccessDenied.tsx:37`
**Impact:** A marketing user or platform admin who hits a permission-denied page is sent to `/console/orders` — a page they also lack permission to view. Creates an infinite access-denied loop.
**Root cause:** Static `<Link href="/console/orders">` with no role awareness.
**Fix:** Resolve role → workspace via `resolveWorkspace()` from navigation-intelligence.ts.

---

### M1 — Stale JSDoc in auth-redirect.ts

**File:** `src/utils/auth-redirect.ts:49`
**Impact:** Documentation says `"staff/console → /admin"` — the route `/admin` does not exist in this codebase. Misleads future developers.
**Fix:** Update comment to reflect actual behaviour (`/console`) and delegate to `resolveWorkspace()`.

---

### M2 — AdminBreadcrumbs aria-label mislabels the console

**File:** `src/components/admin/AdminBreadcrumbs.tsx:102`
**Impact:** Screen readers announce the root breadcrumb as "Admin dashboard" instead of "Admin console". Wrong surface name.
**Fix:** Change `aria-label="Admin dashboard"` → `aria-label="Admin console"`.

---

### L1 — No Business Console link for privileged users in Dashboard

**Files:** `src/app/dashboard/layout.tsx`, `src/components/layout/Header.tsx`
**Impact:** An owner or admin who is also a registered customer cannot navigate from `/dashboard` to `/console` without manually typing the URL. No surface-switching affordance exists.
**Fix:** Show "Business Console" link gated on `dashboard:access` permission.

---

### L2 — Dashboard quick actions and checkout CTA use hardcoded /menu

**Files:** `src/app/dashboard/page.tsx:16`, `src/app/checkout/success/page.tsx:70`
**Impact:** On a multi-tenant platform, `/menu` may resolve to a different tenant's menu than the one the user last ordered from. Should respect tenant context.
**Fix:** Centralise routing via `resolveBestMenu(tenantSlug)`.

---

### L3 — getPostLoginRedirect has two-branch logic only

**File:** `src/utils/auth-redirect.ts:51`
**Impact:** Any role that is not `customer` lands on `/console` root. Staff roles (kitchen, cashier, marketing, support) would be better served by landing on their specific workspace directly.
**Note:** The `DEMO_EMAIL_REDIRECTS` map already does this correctly for demo accounts; real-account login was not equivalent.
**Fix:** Delegate to `resolveWorkspace()`.

## 3. Navigation Architecture Analysis (Pre-Implementation)

### Surface Map

```
Public (/)
  Header nav — module-aware (correct, uses useModuleNav)
  User dropdown — customer links only (gap: no console link for staff)

Customer Dashboard (/dashboard)
  Dashboard sidebar — getDashboardNav() (correct)
  Quick actions — INLINE CONSTANT (gap: not tenant-aware)
  No staff → console escalation link

Business Console (/console)
  AdminSidebar — getConsoleNav() with RBAC filtering (correct)
  AccessDenied — hardcoded /console/orders CTA (BUG)
  AdminBreadcrumbs root — wrong aria-label
```

### Decision Logic Duplication

Before this phase, role → route decisions were made in 4+ separate places:
1. `DEMO_EMAIL_REDIRECTS` (correct)
2. `getPostLoginRedirect()` (two-branch only)
3. `AccessDenied` (hardcoded single destination)
4. `console/page.tsx` (correct, role-aware)

No shared utility existed. Each was an independent, divergent implementation.

## 4. Implementation Plan

**Phase F (foundation):** Create `src/utils/navigation-intelligence.ts` with:
- `resolveWorkspace(role)` — canonical role → route mapping
- `resolveBestMenu(tenantSlug)` — tenant-aware menu URL
- `resolveBestReservation(tenantSlug)` — tenant-aware reservation URL
- `resolveBestBusiness(tenantSlug)` — best business/discover URL
- `resolveBestDashboardActions(tenantSlug)` — four quick-action items
- `resolveFallbackRoute(isAuthenticated, role)` — safe fallback
- `resolvePostLoginRedirect(role)` — delegates to resolveWorkspace

**Phase B:** Fix AccessDenied — use `resolveWorkspace(user.role)`.
**Phase C:** Add Business Console link in dashboard sidebar + header dropdown, gated on `dashboard:access`.
**Phase D:** Remove redundant "Console Home" nav item from AdminSidebar.
**Phase E/G:** Update checkout success + dashboard quick actions to use intelligence utility.
**Phase H:** Fix stale JSDoc + aria-label; add `dashboard:access` to P7Permission type.
**Phase I:** 40 regression tests covering all resolvers.
