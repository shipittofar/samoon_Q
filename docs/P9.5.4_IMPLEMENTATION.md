## Bugs discovered and fixed

**The one real architectural finding of this phase**, per the instruction
to document, fix, and test any genuine issue found: storing
`configFields`/`seo` translation entries as flat JSON keys with literal
dots embedded in the property name (e.g. `"authentication.core.title": "..."`)
silently never resolves through next-intl, which treats every dot as
object nesting. Caught via direct `use-intl/core` experimentation before
being relied upon anywhere in the app's actual render path, fixed by
converting every such entry to a genuinely nested JSON object, and locked
in with dedicated regression tests
(`src/test/p9-5-4-production-localization.test.tsx`). Full account in
`docs/P9.5.4_TRANSLATION_MANAGEMENT.md`.

## Bundle-size impact

Locale JSON file growth this phase (uncompressed, via `git diff --stat`):
- `en.json`: 21,516 → 29,937 bytes (+8,421 bytes, +39%)
- `fa.json`: 28,184 → 39,290 bytes (+11,106 bytes, +39%)
- `ar.json`: 24,904 → 37,515 bytes (+12,611 bytes, +51%)

Because the platform's established one-locale-per-request strategy
(`docs/P9.5.0_PERFORMANCE_STRATEGY.md`) is unchanged, a single user
request only ever downloads **one** of these files — the practical impact
per request is roughly +8–13KB uncompressed JSON (a few KB gzipped),
consistent with the growth already seen in P9.5.1B/P9.5.2/P9.5.3. No new
JS bundle chunks were introduced beyond the new `src/config/i18n.ts`
(< 1KB), `src/lib/seo.ts` (server-only, not shipped to the client bundle),
`src/i18n/ClientIntlProvider.tsx` (thin wrapper, negligible), and
`MissingTranslationInspector.tsx` (dev-only — excluded from production
bundles by its own `NODE_ENV === 'production'` early return, though
tree-shaking this out of the client bundle entirely was not verified via
a production build in this phase; the honest statement is "no code runs
in production," not "zero bytes shipped").

## Runtime performance impact

No new client-side polling, subscriptions, or re-render triggers were
added to any production code path:
- `resolveConfigText()` is a pure synchronous function called during
  render — no new state, no new effects.
- The dev-only `MissingTranslationInspector` uses a 1.5s `setInterval`,
  but only mounts when `NODE_ENV === 'development'` (verified by the
  early-return guard, not a production-build bundle-analyzer run).
- `getLocalizedPageMetadata()` runs once per request on the server
  (Next.js `generateMetadata` semantics), the same cost profile as the
  static `metadata` object it replaced, plus one `getTranslations()` call
  already paid for elsewhere in the same request's render (next-intl
  caches per-request).

No benchmark was run to produce a number; the above is a code-path
analysis, consistent with how prior P9.5.x phases reported this section.
