# P8.8.3 — Owner-Controlled Public Business Experience: Implementation

## Overview

Architecture synchronization phase ensuring every piece of public-facing content has a single source of truth in the Admin Panel. Admin edits propagate to public pages.

---

## Phase A — Public Content Ownership Audit

**Deliverable:** `docs/P8.8.3_PUBLIC_CONTENT_OWNERSHIP_AUDIT.md`

Audited all public pages against their data sources. Key findings:
- `MarketplaceMeta` in `Tenant.settings.marketplace` was missing several fields needed for public pages.
- `/restaurant` page was fully hardcoded — no admin ownership.
- Tenant footers used generic platform footer ignoring tenant contact details.
- No admin UI existed to edit public profile fields.

---

## Phase B — Single Source of Truth

All public content is now owned by `MarketplaceMeta` stored at `Tenant.settings.marketplace` and accessed via `getMarketplaceMeta(tenant.settings)`.

## Phase D — Missing Editable Fields

**File:** `src/types/marketplace.ts`

Added four optional fields to `MarketplaceMeta`:

```typescript
/** Long-form about / story text shown on the public About page. */
story?: string

/** Amenities the business offers (e.g. "WiFi", "Parking", "Outdoor Seating"). */
amenities?: string[]

/** Public social media profile URLs. */
socialLinks?: {
  instagram?: string
  twitter?: string
  facebook?: string
  youtube?: string
}

/** Hero / banner image URL (used on the full-page tenant hero; falls back to coverImage). */
heroImage?: string
```

All fields are optional — fully backward compatible with existing tenants.

## Phase E — Branch Ownership

Branch data displayed on public pages (`/restaurant#branches`, `TenantHomepageClient`) is sourced from `meta.branches` (`PublicBranchInfo[]`). This connects to branch admin data through the tenant service. Fallback static data is provided when `meta.branches` is empty.

## Phase F & G — Preview Synchronization & Dynamic Footer

**File:** `src/components/layout/TenantFooter.tsx` (new)

Tenant-aware footer component replacing the generic `Footer` on tenant-scoped pages. Renders:
- Business name with initial avatar
- Tagline and description from `meta`
- Social links (Instagram, Twitter) from `meta.socialLinks`
- Quick links with primary branch menu link when `meta.primaryBranchSlug` is set
- Contact section (city, phone, email, website) — only shown when at least one contact field is present

- "Powered by Savor Platform" attribution

**File:** `src/app/[tenantSlug]/TenantHomepageClient.tsx`

Replaced `<Footer />` with `<TenantFooter tenantName={tenant.name} tenantSlug={tenantSlug} meta={meta} />` in the main render path. Loading and error states keep `<Footer />` (no meta available).

**File:** `src/app/[tenantSlug]/[branchSlug]/BranchHomepageClient.tsx`

Conditionally renders `<TenantFooter>` when `meta` is available, falls back to `<Footer />` otherwise.

## Phase H — Dynamic Contact

Contact fields on public pages are now sourced from `meta.phone`, `meta.email`, `meta.website`. The `/restaurant` page contact section only renders cards for fields that are present (no empty placeholders).

## Phase I — Public About Page (`/restaurant`)

**File:** `src/app/restaurant/page.tsx`

Converted from a fully hardcoded static page to a dynamic `async` Server Component:

```typescript
export default async function RestaurantPage() {
  const tenant = await tenantService.getTenant('savor').catch(() => null)
  const meta = tenant ? getMarketplaceMeta(tenant.settings) : undefined
  // ...
}
```

Dynamic fields:
- Hero image: `meta.heroImage || meta.coverImage || fallback`
- Story / About text: `meta.story || FALLBACK_STORY`
- Tagline: `meta.tagline || default`
- Gallery: `meta.gallery` (falls back to `FALLBACK_GALLERY`)
- Contact: `meta.phone`, `meta.email`, `meta.website`
- Branches: `meta.branches` (falls back to `FALLBACK_BRANCHES`)

Hardcoded founder story (Chef Marco Rossi, Amara Chen) removed. All static fallback constants renamed with `FALLBACK_` prefix for clarity.

## Phase J — Media Ownership

Gallery and hero images are now editable through the Public Profile admin tab. URLs stored in `meta.gallery` (array) and `meta.heroImage`/`meta.coverImage`.

## Phase K — Admin UI: Public Profile Tab

**File:** `src/app/admin/settings/page.tsx`

Added a "Public Profile" tab to the admin settings page:

- **Tab ID:** `publicprofile`
- **Icon:** `Globe` (from lucide-react)
- **Position:** Between "Hours" and "Integrations"

Fields exposed:
| Field | Input Type | Maps To |
|---|---|---|
| Tagline | Text | `marketplace.tagline` |
| Description | Textarea | `marketplace.description` |
| Story / About | Textarea | `marketplace.story` |
| Cuisine Types | Text (comma-sep) | `marketplace.cuisines` |
| Tags | Text (comma-sep) | `marketplace.tags` |
| Amenities | Text (comma-sep) | `marketplace.amenities` |
| Price Level | Select 1–4 | `marketplace.priceLevel` |
| Phone | Text | `marketplace.phone` |
| Email | Text | `marketplace.email` |
| Website | Text | `marketplace.website` |
| Cover Image URL | Text | `marketplace.coverImage` |
| Gallery Images | Textarea (one per line) | `marketplace.gallery` |
| Instagram | Text | `marketplace.socialLinks.instagram` |
| Twitter | Text | `marketplace.socialLinks.twitter` |

**Save strategy:** `save({ marketplace: { ...existingMeta, ...formData } })` — spreads existing `MarketplaceMeta` before applying form values to avoid overwriting fields not shown in the form (e.g. `branches`, `heroImage`).

**State initialization:** `useEffect` re-initializes form state when `tenant.slug` changes (multi-tenant safe).
