## Phase A — Architecture Audit

### Technology Stack

| Layer | Technology |
|---|---|

### Service Layer (33 services)

Core: `auth`, `tenant`, `branch`, `menu`, `order`, `payment`, `promotion`, `loyalty`, `reservation`, `review`, `staff`, `vendor`

Infrastructure: `analytics`, `audit-log`, `notification`, `rbac`, `rbac-audit`, `feature-flags`, `websocket`, `realtime-operations`, `order-routing`

Admin: `admin`, `branch-analytics`, `combined`, `permission`, `tenant-provisioning`, `qr-experience`, `notification-preferences`, `branch-access`

### Authorization Architecture

P7 Enterprise RBAC gates every admin page with a triple-check:
1. **Permission** (`useHasPermission`) — dot-notation string (e.g. `menu.manage`)
2. **Capability** (`useHasCapability`) — feature capability key
3. **Feature Flag** (`useTenantFeatureFlag`) — tenant-level toggle

Both `PermissionGuard` and `useAdminModuleNav` apply all three checks. Items the user cannot access are omitted from the nav silently.

### Known Architecture Observations

- `features/` directories exist as placeholders — empty stubs, not dead code
- `ErrorBoundary` wraps all admin pages consistently
- Mock API layer (`NEXT_PUBLIC_USE_MOCK=true`) allows full UI development without a live backend
- CSS custom properties (`var(--fg)`, `var(--bg)`, `var(--primary)`) enable tenant-level theming

## Phase D — Customer Journey Audit

### Happy Path (Verified via Code Inspection)

1. Customer lands on `/` (public home)
2. Browses `/menu` — menu items load from `menuService` (mock or API)
3. Adds items to cart via `useCartStore` (Zustand, persisted)
4. Proceeds to `/checkout` — payment via `paymentService`
5. Views order status at `/order/[id]`
6. Can make reservations at `/reservation`
7. Can earn/redeem loyalty points at `/loyalty`
8. Can scan QR code to reach `/table/[code]` for table-ordering flow

### Identified Customer Routes

All customer routes protected by public-facing auth where appropriate (login, register, verify-otp, forgot-password flows present).

## Phase E — Admin Journey Audit

### Admin Happy Path (Verified)

1. Admin logs in → redirected to `/admin`
2. Sidebar shows only permitted modules (filtered by RBAC + feature flags)
3. Each module page loads data via TanStack Query hooks
4. Actions (create, update, delete) go through mutation hooks → service layer → mock or API
5. Errors are caught by `ErrorBoundary` per page
6. Audit events logged to `rbacAuditService` for permission changes

## Phase F — Branch & Public Website Relationship

### How Branches Map to Public Pages

- `Branch` entity has `slug`, `location`, `businessHours`, `settings`
- Public pages use the active tenant context from `useTenantStore`
- `/restaurant` shows the current branch's restaurant page
- Branch-specific settings (delivery, pickup, table ordering) affect the `/menu` and `/checkout` flows via `branch.settings`
- Multi-branch scenario: customer selects branch at `/location`, sets branch context in store
