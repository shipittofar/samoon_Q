# P8.8.11.1 — Tenant Navigation & Brand Identity Audit

**Phase A — Audit First**
**Benchmark:** Shopify storefronts, Squarespace custom domains, Webflow multi-tenant, OpenTable restaurant pages, Airbnb property pages
**Scope:** Navigation system for tenant and branch pages only. Admin, Dashboard, and Platform pages are out of scope.

---

## Executive Summary

The Savor platform currently uses a **single shared `Header` component** across every route — platform marketplace, tenant homepage, branch homepage, menu, and even admin preview. This creates a critical identity problem: when a customer visits `/{tenantSlug}/{branchSlug}/menu`, they see the **Savor platform header**, not the business's branded header. The business feels like an internal page on the Savor marketplace, not a standalone restaurant website.

**Before score: 4.5/10**
**After score (projected): 8.5/10**

## 4. Active Link Logic — Current vs Required

### Current (broken for tenant pages):
```tsx
pathname.startsWith(link.href)
// For href="/menu" and pathname="/brew-cafe/midtown/menu"
// → "/brew-cafe/midtown/menu".startsWith("/menu") === false ❌
```

### Required (branch-aware):
```tsx
pathname.startsWith(`/${tenantSlug}/${branchSlug}${item.baseHref}`)
// → "/brew-cafe/midtown/menu".startsWith("/brew-cafe/midtown/menu") === true ✓
```

## 6. Scroll & Sticky Behavior — Current vs Required

### Current:
- Transparent hero: only on `pathname === '/'` (platform landing)
- Fixed, `z-40`, scroll detection at `scrollY > 20`
- Tenant/branch pages: header is opaque from the top (scrolled=false → transparent, but `isTransparentHero` is false so styling is still transparent until scroll)

Wait — actually on tenant pages (not `/`), `isTransparentHero = pathname === '/' && !scrolled` is false. So the header starts **transparent** (no bg class when scrolled=false) but is not the transparent-hero variant. This causes the header to be invisible over non-hero backgrounds. This is a secondary bug.

### Required for TenantHeader:
- Always visible (non-transparent): `bg-[var(--card)]/90 backdrop-blur-xl` even when not scrolled
- Add `shadow-sm` when scrolled for elevation feedback
- Same z-40 fixed positioning

## 9. Website Builder Integration — Current State

The Website Builder (`/console/website`) manages:
- `HomepageLayout.sections` — section visibility and order
- `HomepageLayout.theme` — brand theme settings
- `HomepageLayout.hero` — hero content
- `HomepageLayout.about`, `contact`, `faq` — content blocks

**Gap:** There is no `navItems` config in `HomepageLayout`. Navigation cannot be customized through the Website Builder.

### Required Addition to `HomepageLayout`:
```typescript
navItems?: TenantNavItemConfig[]
```

Where `TenantNavItemConfig` controls which items are enabled and their order.

## 10. Feature Flag Integration — Navigation

### Current (correct):
`useModuleNav()` already filters items by feature flags:
```tsx
return allNav.filter((item) =>
  !item.featureFlagKey || featureFlags[item.featureFlagKey] !== false
)
```

This means if `reservations.enabled = false`, the Reservations nav item is hidden.

### What the TenantHeader needs:
- Use `useModuleNav()` to get pre-filtered items
- Map each item's `href` to a branch-aware full path
- Add Discover as the fixed first item
- Respect the same filtering that already exists

## 11. Module Registry — Nav Item Gap

The module navItems have no concept of "tenant/branch prefix". The registry's `getHeaderNav()` returns:
```typescript
[{ href: '/menu', label: 'Menu' }, { href: '/reservation', label: 'Reservation' }, ...]
```

The TenantHeader must convert these at render time:
```typescript
const branchNavLinks = moduleNav.map((item) => ({
  ...item,
  href: branchSlug
    ? `/${tenantSlug}/${branchSlug}${item.href}`
    : `/${tenantSlug}${item.href}`,
}))
```

This conversion is a presentation concern — the registry should not know about URL slugs. The TenantHeader owns this transformation.

## Conclusion

The implementation requires:
1. A new `TenantHeader` component (does NOT modify the existing `Header`)
2. Surgical replacement of `<Header />` → `<TenantHeader />` in 5 tenant-scoped files
3. A `TenantNavItemConfig` type in `website-builder.ts` for Phase J
4. Zero changes to admin, dashboard, platform, or API layers

The existing `Header` component remains **completely unchanged** and continues serving platform pages.
