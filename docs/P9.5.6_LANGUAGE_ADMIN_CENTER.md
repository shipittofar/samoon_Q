# P9.5.6 — Language Administration Center

Builds the Platform Language Administration experience on top of the
existing P9.2 Collection Framework / P9.3 Configuration Studio / P9.4
Platform Administration / P9.5.0–P9.5.5 Localization foundation. See
`docs/P9.5.6_LANGUAGE_ADMIN_AUDIT.md` for the read-only audit performed
before any code changed, and the "Final Report" section below for an
honest accounting of what's real vs. mocked vs. deferred.

## What this phase is, architecturally

Almost everything the phase brief asked for already existed structurally
after P9.5.5 — a 30-language collection field with a 30-property schema, a
generic table/drawer/bulk-action framework, dashboard widgets, a search
registry, and an unwired cross-entity validator. The actual work of this
phase was: closing the three real gaps the audit identified, adding real
(not mocked) translation-quality analysis, and extending the framework
with two small, generic, reusable hooks — not building a sixth UI system.

### Framework additions (reusable beyond Languages)

1. **`ConfigCollectionMeta.validateEntries`** (`src/config/types.ts`) — any
   collection module can now supply a cross-entity validator. Consumed
   generically by two places:
   - `ConfigurationCollectionTable` renders any returned errors as a
     banner (works for any future collection, not just languages).
   - `useConfigurationBulkActions`'s `'publish'` action now runs it before
     committing a batch, rejecting the whole batch with the specific
     reasons if it would fail.
2. **Real JSON import** (`useConfigurationBulkActions`) — `'import'`
   previously returned "not implemented yet". It now parses a JSON payload
   in the exact shape `'export'` produces and merges it in, with a
   round-trip test proving export → import is lossless.

### Real (not mocked) additions

- **`src/i18n/quality.ts`** — static analysis over the actual locale
  message bundles (`en`/`fa`/`ar` — the only locales with real message
  files today). Computes missing keys, broken ICU balance, broken
  placeholder-token mismatches, and a crude broken-HTML (angle-bracket
  balance) check, all against `en` as the reference. Explicitly does NOT
  attempt duplicate-key or unused/deprecated-key detection — see the
  Honest Scope section.
- Three new dashboard widgets (`translation_quality_issues`,
  `missing_translation_keys`, `broken_icu_placeholder_keys`) surface this
  analysis through the existing `platformDashboardRegistry` — zero new
  widget-kind support needed (`'stat'`/`'list'` already existed).
- **`locale_bundle_sizes`** widget reports the real byte size of each
  locale's actual JSON module (not network-measured, but not invented
  either).
- **`platform.languages.registry` `version` field** — added to the
  30-property schema (Phase B's literal ask), defaulting to `'1.0.0'` for
  the 6 operational languages and `'0.1.0'` for the 24 disabled ones.

### Gap-closing (design + tests, wiring deferred — see Honest Scope)

- **`src/platform-admin/language-runtime-sync.ts`** —
  `computeRuntimeSyncPlan()` derives what `languages.supported`/
  `languages.default`/`languages.rtl_locales` should be from the admin
  collection's `enabled`/`default`/`rtl` flags. Pure, tested, NOT
  auto-wired — see Honest Scope for why.

### Search (Phase K)

A `languages` provider registered in `platform-admin/search-providers.ts`,
reusing `matchesCollectionEntrySearch` (the same haystack builder the
Collection Table's own search box uses) instead of the simpler label-only
match the three existing providers use — so a query matches any schema
property's value (native name, status, font, currency, translator, ...),
not just the display label.

### Live Preview (Phase C) — simulated, not live-iframe

`ConfigurationEntityDrawer`'s existing Preview tab gained a generic
"Device Preview" block — three fixed-width frames (desktop/tablet/mobile)
rendering representative sample content (heading/body/button) at the
entity's own `fontFamily`/`headingFontFamily`/`direction`/`fontScale`
values. Gated purely on the entity's schema having `fontFamily` and
`direction` properties (works for any typography-bearing collection, not
hardcoded to languages).

This is **not** a live iframe of the six named pages (Home/Login/Menu/
Checkout/Dashboard/Console) — see Honest Scope for exactly why, and what a
real implementation would need.

## Final Report

### Architecture decisions

- Extended the Collection Framework with one new optional metadata hook
  (`validateEntries`) rather than adding a language-specific validation
  path — any future collection module gets cross-entity validation for
  free by supplying the same hook.
- Kept the 6-language runtime and 30-language admin collection
  **deliberately un-auto-synced** rather than making one derive from the
  other silently — `languages.supported`/`languages.default` are
  tenant-overridable; auto-deriving them from the platform-only admin
  collection on every read would silently remove that per-tenant
  capability, a real runtime-behavior change the task's own validation
  requirements forbid. The correct derivation is implemented and tested;
  making it *automatic* vs. an explicit admin action is a product decision
  for P9.5.7, not an engineering shortcut taken here.
- Chose a simulated typography/direction preview over a live-iframe
  preview specifically because wiring an explicit locale override into
  `src/i18n/request.ts`/`middleware.ts` — the shared code path every
  single request in the app goes through — is exactly the code path that
  caused two full-site production outages earlier in this same
  engagement (see `docs/P9.5.5.1_RUNTIME_RECOVERY.md` and
  `docs/P9.5.5.2_STARTUP_REGISTRATION.md`). Given "no runtime behavior
  regressions" is a hard requirement, touching that path again for a
  preview feature was judged not worth the risk without a dedicated,
  reviewed design (e.g. a signed preview token or a separate preview-only
  route) rather than a quick query-param addition.

### Generic framework improvements

- `ConfigCollectionMeta.validateEntries` (types.ts) — new optional hook.
- `ConfigurationCollectionTable` — renders cross-entity validation errors
  generically for any collection that supplies the hook.
- `useConfigurationBulkActions` — `'publish'` now validation-gated;
  `'import'` is now real (was a placeholder since P9.2).
- `ConfigurationEntityDrawer` — generic Device Preview block, gated on
  schema shape, not module identity.

### Reused components (no new UI system built)

`ConfigurationCollectionTable`, `ConfigurationEntityDrawer`,
`ConfigurationModulePage`, the full Studio shell, `platformDashboardRegistry`,
`platformSearchRegistry`, `configurationAudit`/`configurationVersionManager`
(available for a future "Publish" action to call — no new persistence
mechanism needed), `matchesCollectionEntrySearch`.

### Real bugs discovered and fixed

`validateLanguageCollection()` (P9.5.5) was fully implemented, unit-tested,
and completely unreachable from any UI path — confirmed during the audit
and fixed by wiring it through the new `validateEntries` hook. This was a
real, load-bearing gap: an admin could previously mark two languages both
"default" or publish a language missing required metadata with no warning
anywhere in the product.

### Remaining work for P9.5.7

1. **Runtime sync UI** — `computeRuntimeSyncPlan()` exists and is tested;
   an explicit "Sync to Runtime" action/button (Studio toolbar or a
   dedicated control) that calls it and writes through
   `configurationService.updateField()` is not yet built.
2. **Live-iframe preview of real pages** — needs a deliberately-designed,
   reviewed mechanism to preview a locale override for one request without
   touching the shared middleware/request-config path for every other
   request (e.g. a signed preview token, or a dedicated `/preview/*` route
   segment with its own request config). Today's Device Preview is a
   simulated typography/direction preview, not this.
3. **Duplicate-key detection** — needs a raw-text (non-JSON-parse) scanner,
   since `JSON.parse` silently collapses duplicate keys before any
   analysis can see them.
4. **Unused/deprecated-key detection** — needs a full source-tree scan for
   `t()` call sites; `scripts/check-translation-coverage.mjs` already does
   this at CI time — surfacing it live in the dashboard was judged too
   slow/duplicative to re-run per render without a caching layer that
   doesn't exist yet.
5. **CSV/XLIFF/PO/YAML import/export** — documented (§38.7 of
   `docs/BACKEND_API_CONTRACT.md`), not implemented, per the phase's own
   "mock implementation only" instruction for Phase G.
6. **A dedicated `/platform-admin` Language Dashboard route distinct from
   the generic module page** was not built — the generic
   `ConfigurationCollectionTable`'s stats badges plus the new dashboard
   widgets already satisfy Phase B's field list; a bespoke, denser
   dashboard layout is a UI-polish item, not a missing capability.

### Performance impact

Production build: `/platform-admin` and `/platform-admin/[moduleId]` first
load JS grew from ~402 kB to ~435 kB (both routes) — attributable to
`src/i18n/quality.ts` eagerly importing the three real locale JSON bundles
(en/fa/ar, ~750 lines each) into the server bundle that also contains the
new dashboard widgets. No client-side bundle impact (the widgets/quality
module are server-only, never imported from a `'use client'` file). No
other route's bundle size changed.

### Honest scope statement

This phase does **not** claim full completion of all 12 sub-phases (A–L)
at the fidelity the brief describes. Delivered at real, working fidelity:
Phase A (audit), Phase H (validation wiring), Phase K (search), and the
real parts of Phase E/F/J (translation quality analysis, real bundle
sizes). Delivered at reduced/honest fidelity: Phase G (JSON only, other
formats documented not implemented — as explicitly instructed), Phase C
(simulated device preview, not live-iframe — a deliberate risk-avoidance
decision explained above), Phase I (the underlying version/audit/
validation primitives are reused and available, but no dedicated "Publish
workflow" UI beyond the existing bulk `'publish'` action was built), Phase
J (bundle size is real, cache/load-time stats are not mockable-because-
non-existent-instrumentation and were not added as fake numbers — they're
simply not implemented, and the doc says so rather than inventing
plausible-looking metrics). Not built: a bespoke Language Dashboard route
distinct from the generic module page (judged unnecessary — see Remaining
Work #6), font-download integration (explicitly out of scope per the
brief), and a true draft/testing/published/archived workflow *engine*
(the framework audit found none exists anywhere in the codebase, and
building one from scratch was correctly out of scope for "reuse, don't
rewrite").
