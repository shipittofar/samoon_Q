### C.2 D-05 Fix: Cart cleared on tenant switch

**Root cause:** `useCartStore` persists cart items in localStorage under key `'savor-cart'` with no tenant association. `useLogout()` correctly clears the cart on logout, but `TenantLayout`'s `loadTenant()` effect did not clear the cart on tenant switch.

**Impact:** A user adding items to cart at `/brew-cafe/main/menu`, then navigating to `/savor/main/menu`, would see brew-cafe items in the cart and could attempt checkout against savor's order endpoint with wrong items.

**Fix:** Added `clearCart()` call in `TenantLayout`'s `loadTenant` effect, before calling `loadTenant(tenantSlug)` when the active tenant slug differs from the URL slug.

### C.3 Remaining Risks

**Risk-F:** `useFavoritesStore` and `useRecentlyViewedStore` not tenant-scoped. Documented from P8.7.7.6 as R-02. In production, item IDs from different tenants may collide, causing cross-tenant favorites. Deferred to P8.8 (requires adding tenantId prefix to all favorite/recently-viewed IDs).

**Risk-G:** `useDineInStore.tableNumber` not tenant/branch-scoped. A table number persisted from tenant A could persist into tenant B's checkout flow. Low-risk scenario (requires deliberate cross-tenant navigation with same browser session and no table clearing). Deferred to P8.8.

## Confirmed Defects & Fixes

### D-05 — Cart persists across tenant switches

**Status:** ✅ FIXED

**Root cause:** `TenantLayout.tsx` called `loadTenant(tenantSlug)` when the URL slug differed from the active tenant slug, but did not call `clearCart()`. The cart (persisted in localStorage under `'savor-cart'`) retained items from the previous tenant.

**Impact:** User browses `/brew-cafe/main/menu`, adds items to cart, navigates to `/savor/main/menu` — cart shows brew-cafe items. Attempting checkout would place an order with wrong-tenant menu items against savor's order API.

**Fix:** Added `clearCart()` call in `TenantLayout`'s existing `loadTenant` effect, immediately before `loadTenant(tenantSlug)`. Only fires when a tenant change is detected (`tenant?.slug !== tenantSlug`), not on initial mount or within-tenant navigation.

---

### D-06 — `useFeaturedItems()` missing `tenantId` in query key

**Status:** ✅ FIXED

**Root cause:** Query key `['featured-items']` had no tenant scope. With `STALE_TIME = 5 minutes`, visiting savor's homepage (which renders `FeaturedSection` via `useFeaturedItems()`) caches featured items under a global key. Navigating to brew-cafe's homepage within 5 minutes would serve stale savor featured items from cache (React Query cache hit on identical key).

**Fix:** Changed to `['featured-items', tenantId]`. Each tenant now has an isolated cache entry.

---

### D-07 — `useMenuSearch()` missing `tenantId` in query key

**Status:** ✅ FIXED

**Root cause:** Query key `['menu-search', query]` had no tenant scope. Searching "pasta" on savor and then switching to brew-cafe and searching "pasta" would return savor's cached pasta results.

**Fix:** Changed to `['menu-search', tenantId, query]`.

---

### D-08 — `useRelatedItems()` missing `tenantId` in query key

**Status:** ✅ FIXED

**Root cause:** Query key `['related-items', id]` had no tenant scope. A related items lookup for item `id` would be shared across all tenants.

**Fix:** Changed to `['related-items', tenantId, id]`.
