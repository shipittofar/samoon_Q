## 5. Feature Flag Findings

### Promotions Nav Item

The "Promotions" sidebar item is hidden for the **default tenant** via a feature flag (`promotions` flag = disabled). This affects all personas including owner and admin who have `promotions.view` and `promotions.manage` in their permission set.

| Condition                                  | Behavior                   |
|--------------------------------------------|----------------------------|
| Sidebar: Promotions visible (all roles)    | ❌ Hidden (feature flag)   |
| Direct URL `/console/promotions` — owner     | ✅ Renders (has permission)|
| Direct URL `/console/promotions` — admin     | ✅ Renders (has permission)|
| Direct URL `/console/promotions` — marketing | ✅ Renders (has permission)|
| Direct URL `/console/promotions` — manager   | AD (no permission)         |
| Direct URL `/console/promotions` — cashier   | AD (no permission)         |

**Assessment**: This is **expected behavior**. The three-layer protection is:
1. Middleware: JWT check (blocks unauthenticated)
2. AuthGuard: `dashboard:access` check (blocks non-staff/console users)
3. PermissionGuard: P7 permission check (blocks unauthorized roles)

Feature flags control **sidebar visibility**, not **route access**. Users with the required permission who know the URL can still navigate there. This is intentional — feature flags are tenant configuration, not security boundaries. The RBAC layer correctly allows/denies access based on permissions.

## 6. RBAC Inconsistencies

### Investigated Items

Two apparent inconsistencies were flagged by the audit script and investigated:

#### 6.1 "Analytics" label mismatch (FALSE POSITIVE)

**Flagged**: manager and support have "Analytics" in their sidebar but `analytics.view` permission is NOT in their permission set.

**Root cause**: The sidebar contains **two distinct items**:
- `"Analytics"` — requires `analytics.view` — shown to owner, admin, marketing
- `"Branch Analytics"` — requires `branches.view` — shown to owner, admin, manager, support

The audit script matched the label string "Analytics" without distinguishing the two items. Manager and support correctly see **"Branch Analytics"** (not "Analytics"), which is gated by `branches.view` — a permission both roles hold.

**Status**: ✅ No defect. Script false positive.

#### 6.2 Promotions URL bypass for owner/console/marketing

**Flagged**: `/console/promotions` renders for owner, admin, marketing despite "Promotions" not appearing in the sidebar.

**Root cause**: Feature flag gating (see Section 5).

**Status**: ✅ Expected behavior. Not an RBAC bypass.
