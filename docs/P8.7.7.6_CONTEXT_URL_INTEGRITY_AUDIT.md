## 14. Risk Assessment

### R-01 — `useAdminBranches` in Public Layout (Medium)
**File:** `src/app/[tenantSlug]/[branchSlug]/layout.tsx`  
**Detail:** `TenantBranchLayout` calls `useAdminBranches(tenant?.id)` to resolve the branch from URL slug and set `adminActiveBranch`. In mock mode this works fine. In production, `useAdminBranches` calls an admin-scoped API endpoint that requires authentication. An unauthenticated customer visiting `/samoon/main/menu` would trigger a 401 on the admin branches API.  
**Impact:** In production, `TenantBranchLayout`'s branch initialization fails silently for unauthenticated users; `adminActiveBranch` stays null; child pages render without branch context initialized via this path.  
**Mitigation (future):** Public branch context should use `usePublicBranch(tenantSlug, branchSlug)` (which calls the public tenant API, not the admin branches API). Branch context for public pages can be initialized from `getMarketplaceMeta(tenant.settings).branches`.  
**Current state:** Not broken in mock mode. Documented for P8.8.

### R-02 — Favorites/RecentlyViewed Storage Keys Not Tenant-Scoped (Low)
**File:** `src/stores/index.ts`  
**Detail:** `useFavoritesStore` persists under `'samoon-favorites'`; `useRecentlyViewedStore` under `'samoon-recently-viewed'`. These keys are the same regardless of active tenant. Item IDs added to favorites while on brew-cafe are stored in the same localStorage key as samoon favorites.  
**Impact in production:** Menu item IDs are tenant-scoped in production. Favorites from brew-cafe loaded while on samoon would reference IDs that don't exist in samoon → items would not render or show 404. In mock mode, menu data is global, so this appears to work.  
**Mitigation on switch:** `switchTenant()` calls `setFavorites([])` which clears and persists `[]` to localStorage. The risk window is: hard refresh while on a different tenant without having done a switch in the same tab.  
**Current state:** Acceptable in mock mode. Documented for P8.8 production hardening.
