## 1. Architecture Diagram

```
Owner Login
    │
    ▼
AuthStore (runtime, not persisted)
    │ authService.login()
    ▼
TenantBootstrapper (src/providers/index.tsx)
    │ loadTenant(slug)  ←── reads user.tenantSlug from AuthStore
    ▼
TenantStore (persisted: 'savor-rbac')
    ├── tenant: { id, slug, name, businessTypes, settings, ... }
    ├── featureFlags: Record<string, boolean>   ← featureFlagsService.resolve(tenant)
    ├── rbacInitialized: boolean
    └── featureFlagsInitialized: boolean
    │
    ▼
BranchStore (persisted: 'savor-branch')
    ├── activeBranch: Location | null          ← public/customer context
    └── adminActiveBranch: AdminBranch | null  ← admin context
    │   set by AdminBranchSwitcher or [tenantSlug]/[branchSlug]/layout.tsx
    ▼
React Query (tenant-scoped keys after P8.7.7)
    │  queryKey: ['resource', tenantId, ...filters]
    ▼
Service Layer (src/services/*.service.ts)
    │  mock-first: reads NEXT_PUBLIC_USE_MOCK
    ▼
Mock Store (module-level arrays in service files)
    │  OR
Real API (fetch/axios with tenantId in headers/path)
    │
    ▼
Component / Page
    │  reads useTenantStore + useBranchStore + React Query data
    ▼
PreviewButton
    │  hrefToPublicUrl(href, tenant.slug, adminActiveBranch.slug)
    ▼
Public Preview Route  /[tenantSlug]/[branchSlug]/[module]
    └── layout.tsx re-initializes both stores from URL slugs
```

## 8. Security Audit

### Attack Vector 1: Cart Cross-Tenant Leakage
**Pre-fix:** Customer adds Tenant A items → switches tenant → checks out to Tenant B with Tenant A items.
**Post-fix:** `switchTenant()` calls `clearCart()` before `loadTenant()`. Cart is empty when Tenant B loads.
**Status:** ✅ Mitigated

### Attack Vector 2: React Query Cache Collision
**Pre-fix:** Admin A loads orders (queryKey `['admin-orders']`) → switches to Tenant B → cache serves Tenant A orders.
**Post-fix:** `switchTenant()` calls `qc.clear()` before `loadTenant()`. All cache entries are destroyed. Next load fetches fresh data for Tenant B.
**Status:** ✅ Mitigated

### Attack Vector 3: Favorites Cross-Tenant Persistence
**Pre-fix:** Item ID `abc` favorited at Tenant A; at Tenant B, unrelated item also has ID `abc` → appears favorited.
**Post-fix:** `switchTenant()` and logout both call `setFavorites([])`. Favorites reset on every tenant switch.
**Status:** ✅ Mitigated

### Attack Vector 4: DineIn Table Cross-Tenant Leakage
**Pre-fix:** User scans QR at Tenant A table 5 → `useDineInStore.tableNumber = 5` persisted → switches to Tenant B → checkout sends `table_number = 5` for Tenant B (wrong table).
**Post-fix:** `switchTenant()` and logout call `clearTable()`. Table number reset on switch.
**Status:** ✅ Mitigated

### Attack Vector 5: adminActiveBranch Survives Logout
**Pre-fix:** Admin A selects "Downtown" branch → logs out → Admin B logs in → `useBranchStore.adminActiveBranch` still set to Admin A's branch → PreviewButton generates URLs for wrong branch.
**Post-fix:** `useLogout.onSettled()` calls `useBranchStore.getState().setAdminActiveBranch(null)`.
**Status:** ✅ Mitigated

### Attack Vector 6: Manual URL Manipulation
**Scenario:** User visits `/evil-tenant/main/admin` directly.
**Defense:** Admin routes are protected by RBAC (`usePermission` / `PermissionGuard`). The user's authenticated roles belong to their tenant, not `evil-tenant`. Even if the page renders, `useTenantStore.tenant` has the user's own tenant, so all queries fetch from the authenticated tenant's scope.
**Status:** ✅ Acceptable (backend row-level security is the final authority in production)

### Attack Vector 7: Branch Slug Mismatch
**Scenario:** User visits `/savor/evil-branch/menu`.
**Defense:** `[tenantSlug]/[branchSlug]/layout.tsx` calls `loadTenant('savor')` and then searches `branches.find(b => b.slug === 'evil-branch')`. If no match, `setAdminActiveBranch` is never called. Page renders with whatever branch context is already in the store (or none).
**Status:** ✅ Safe (no data for unrecognized slug)
