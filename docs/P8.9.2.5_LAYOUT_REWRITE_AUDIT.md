# P8.9.2.5 — Country Picker Layout Rewrite Audit

## Root Cause of P8.9.2.4 Remaining Issues

### Desktop: rows overflowing / modal not scrolling

**Cause:** The dialog container used `flex flex-col h-full`. In a flex parent that
has `max-height` (not an explicit `height`), `h-full` resolves to `height: 100%` which
is **indefinite** — the browser cannot compute a definite pixel value, so the children
size to their intrinsic content. The list's `flex-1` never activated because there was
no definite parent height to distribute. Result: the sheet grew past its `max-h` constraint
and content overflowed.

### Mobile: keyboard still overlapping

**Cause:** `flex-1` on the list without `min-h-0` means the flex item's minimum size
defaults to `auto` (= content size). A list of ~180 rows at 48px each = ~8640px intrinsic
height. The flex item refused to shrink below 8640px regardless of the parent's `max-height`.

## Architectural Changes

### Before (P8.9.2.4)

```
sheet [flex flex-col, max-h-[85dvh], overflow-hidden]
├── drag handle [shrink-0]
└── dialog [flex flex-col, h-full]         ← h-full on indefinite parent: broken
    ├── header [shrink-0]
    ├── search [shrink-0]
    └── list   [flex-1, overflow-y-auto]   ← min-h:auto blocks shrinking
```

### After (P8.9.2.5)

```
sheet [flex flex-col, max-h-[85dvh], overflow-hidden]
├── drag handle [shrink-0]
└── dialog [flex-1, min-h-0, grid grid-rows-[auto_auto_minmax(0,1fr)], overflow-hidden]
    ├── header [auto row]                  ← intrinsic height, never scrolls
    ├── search [auto row]                  ← intrinsic height, never scrolls
    └── list   [min-h-0, overflow-y-auto]  ← minmax(0,1fr) + min-h-0 = scrollable
```

## Removed Constraints (Phase H)

| Element | Removed | Replacement | Reason |
|---|---|---|---|
| Dialog container | `flex flex-col` | `grid grid-rows-[auto_auto_minmax(0,1fr)]` | CSS Grid gives each row explicit sizing rules |
| Dialog container | `h-full` | `flex-1 min-h-0` | `flex-1` fills parent; `min-h-0` allows shrinking |
| Header div | `shrink-0` | (none needed) | Grid `auto` row is intrinsically sized |
| Search div | `shrink-0` | (none needed) | Grid `auto` row is intrinsically sized |
| List div | `flex-1` | (none needed) | `minmax(0,1fr)` grid track replaces flex-grow |

**Retained:**
- Sheet `overflow-hidden` — clips content at rounded corners
- List `overscroll-contain` — prevents scroll chaining to page body
- List `[WebkitOverflowScrolling:touch]` — iOS momentum scrolling
- Sheet `flex flex-col` — still needed so drag handle + dialog stack vertically

---

## Why CSS Grid Solves the Problem

`grid-template-rows: auto auto minmax(0,1fr)` gives definite sizing to all three rows:

- `auto` rows: sized to their content. Header and search always get exactly the space
  they need. No explicit `shrink-0` required.
- `minmax(0,1fr)`: the `1fr` distributes remaining space; the `0` minimum allows the
  track to shrink all the way to 0px when available space is tiny (e.g. landscape + large
  keyboard). This is the critical difference from `flex-1` which uses `min-height:auto`.

In a CSS Grid context, items do NOT have `min-height:auto` by default — they have
`min-height:0`. The `min-h-0` class on the list is belt-and-suspenders: it works in
both Grid and Flex contexts and documents intent.

## Platform Behavior

| Platform | Behavior |
|---|---|
| Windows Chrome | Modal capped at 70vh; list scrolls within grid row; header/search fixed |
| Windows Firefox | Same — Grid and VisualViewport both supported |
| macOS Safari | Same — Safari 16.4+ supports `dvh`; `85dvh` fallback works on older |
| Android Chrome | Sheet pinned at bottom:0; VisualViewport shrinks sheet maxHeight; list scrolls |
| Samsung Internet | Same — grid + VisualViewport supported since Samsung Browser 14 |
| iOS Safari | Same — `env(safe-area-inset-bottom)` in list padding; momentum scrolling |
| Landscape phone | List shrinks to ~90px available; remains scrollable; header+search visible |
| Keyboard rotate | VisualViewport fires resize; maxHeight recalculates immediately |
| Small viewport (320px) | maxHeight = viewportHeight × 0.92 > 0; list always scrollable |
| Large viewport (4K) | keyboardHeight=0; CSS max-h-[70vh] applies; no override needed |
