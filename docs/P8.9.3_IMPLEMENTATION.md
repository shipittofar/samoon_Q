## Key Design Decisions

### Challenge-ID Bound OTPs (resolves P1)

OTPs are tied to a `challenge_id` UUID, not just a phone number. This allows:
- Concurrent OTP sessions for the same phone (different devices)
- Precise rate limiting per challenge
- Replay protection (challenge is single-use)

### `next_step` Field (resolves P6, enables future MFA)

The verify response carries `next_step: "complete" | "complete_profile" | "mfa_totp"`.
- Frontend branches on this field, not on `is_new_user` boolean
- Backward compatible: old clients get `complete` and work as before
- Future MFA steps (TOTP, backup codes) can be added without a new endpoint

### Token Family Revocation (resolves R1, R2)

Every refresh token belongs to a `family_id`. If a used token is presented again:
1. All tokens in the family are revoked
2. User is logged out everywhere
3. Error `FAMILY_REVOKED` is returned

This detects stolen refresh tokens within one refresh cycle.

### `token_revoke_version` (resolves R4, S2)

`POST /auth/logout-all` increments `users.token_revoke_version`. The JWT must carry the version at issuance; backend rejects JWTs with a lower version than the current user record. This invalidates all sessions without needing a blocklist for every token.

### Nullable Email (resolves M1, M2)

`ALTER TABLE users ALTER COLUMN email DROP NOT NULL` allows phone-only accounts. The `User` type on the frontend will be updated separately to reflect `email: string | null`.

### Profile Token (resolves P6)

New users get a short-lived (15 min) `profile_token` instead of full tokens. This token can only call `POST /auth/complete-profile`. After profile completion, full tokens are issued. This prevents half-registered accounts from accessing protected resources.

## Migration Blockers Addressed

All 10 blockers from the audit are resolved by this contract:

| Blocker | Resolution |
|---|---|
| M1 — `email` required | `ALTER TABLE ... ALTER COLUMN email DROP NOT NULL` |
| M2 — `phone` optional | New phone-first flow; phone stored on `phone_verified_at` set |
| M3 — No verification timestamps | `phone_verified_at`, `email_verified_at` columns added |
| M4 — No `challenge_id` | `/auth/phone/start` returns `challenge_id`; verify requires it |
| M5 — No `is_new_user` | `is_new_user` in `AuthResponse`; `next_step: "complete_profile"` for new users |
| M6 — No `p7_roles` in OTP response | `p7_roles` in `AuthResponse` (all auth responses) |
| M7 — No refresh token rotation | 2.11 rotation algorithm + family revocation |
| M8 — No `jti` claim | JWT payload schema updated with `jti` |
| M9 — No device sessions | `user_devices` table + `/auth/devices` endpoints |
| M10 — Missing endpoints | All 14 missing endpoints now specified |
