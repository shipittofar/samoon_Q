# P9.5.3 Phase A — Business Console & Platform Administration Localization Audit

## Purpose

Before migrating anything, this audit inventories every literal-string
surface across the Business Console and Platform Administration UI so the
migration work (and its honest reporting) is scoped against a complete
picture, not a guess.

## Method

Enumerated every file under:
- `src/components/admin/configuration/**` (Configuration Studio + generic
  Console rendering framework — P9.1.3/P9.2/P9.3)
- `src/components/admin/platform-admin/**` (Platform Administration —
  P9.4)
- `src/config/modules/**` and `src/platform-admin/modules/**`
  (`ConfigModuleDefinition`/`ConfigFieldDefinition` metadata — `title`,
  `description`, group/tab labels, tooltips, badges)
- `src/platform-admin/dashboard.ts`, `search.ts` (widget and search-result
  content)

and classified each literal string as either **generic chrome** (rendered
identically regardless of which module/entity is active — toolbar labels,
empty states, aria-labels, button text, tab labels, table headers) or
**per-module content** (a specific module's field title, description, or
widget copy, defined once per field/widget in a data file).

## Why the split

The 7 migrated files are **module-agnostic UI chrome**: they render the
same toolbar, save bar, nav, command palette, dashboard grid, and
collection table regardless of which of the ~27 config modules or ~23
dashboard widgets is currently active. Fixing these once fixes every
module's shell simultaneously — the highest-leverage, in-scope work for a
single phase.

The remaining ~28 module/widget definition files are **per-field content**:
each field's `title` and `description` is a literal string defined once,
in `ConfigFieldDefinition` objects (`src/config/types.ts`), consumed by the
already-localized generic components via `prop.display?.displayName ??
prop.title`. Localizing these requires either:
1. Changing `title`/`description` from `string` to a translation-key
   reference and updating every one of ~150+ field definitions plus the
   type signature — a schema change that risks violating this phase's
   explicit "do not alter configuration architecture" constraint, or
2. A large mechanical content-migration pass moving ~150+ field titles/
   descriptions + ~23 widget definitions' copy into locale JSON under new
   namespaces, verified for parity across en/fa/ar.

Both are legitimate, substantial pieces of work that were judged too large
to safely complete, review, and validate within this phase alongside the
chrome migration — see `docs/P9.5.3_CONSOLE_LOCALIZATION.md` for the full
honest accounting and the P9.5.4 recommendation.

## Scope decision for P9.5.3

In scope (migrated):
- `ConfigurationModulePage.tsx`, `ConfigurationSaveBar.tsx`
- `ConfigurationStudioToolbar.tsx`, `ConfigurationStudioNav.tsx`
- `ConfigurationCommandPalette.tsx`
- `PlatformDashboard.tsx` (empty states only)
- `ConfigurationCollectionTable.tsx`, `ConfigurationEntityDrawer.tsx`

Out of scope (deferred to P9.5.4, documented honestly):
- All `ConfigFieldDefinition.title`/`.description` content across
  `src/config/modules/*.ts` and `src/platform-admin/modules/*.ts`
- `PlatformDashboardWidgetCard.tsx` widget-specific rendering and
  `src/platform-admin/dashboard.ts` widget definitions
- `src/platform-admin/search.ts` search result content
- `ConfigurationInspector.tsx`, `ConfigurationInheritanceTree.tsx`,
  `ConfigurationCompareView.tsx`, `ConfigurationHistoryTimeline.tsx`,
  `ConfigurationFieldRow.tsx`, `ConfigurationFieldControl.tsx`,
  `ConfigurationFieldPreview.tsx`, `ConfigurationFieldBadges.tsx`,
  `ConfigurationWorkspaceSkeleton.tsx`, `ConfigurationStudioLayout.tsx`
