## What Changed

### New File

**`src/utils/navigation.ts`**

Pure, framework-free navigation builder. All business logic for constructing
tenant navigation lives here. TenantHeader renders the output — it contains no
nav business logic itself.

Three exported functions:

| Function | Purpose |
|---|---|
| `buildTenantNavigation(opts)` | Ordered, feature-aware, branch-aware nav links |
| `getSmartCTA(opts)` | Priority-ordered hero/header CTAs |
| `getBusinessTypeBadge(businessTypes)` | Emoji + label for business type identity |

Two exported types: `TenantNavLink`, `SmartCTA`.

## Architecture — Phase Map

### Phase B: `src/utils/navigation.ts`
Pure functions exported from a single module. No React, no hooks, no imports
from `@/stores`. Testable in isolation with plain TypeScript objects.

### Phase D: Branch awareness in `buildTenantNavigation()`
`branchCount` comes from `getMarketplaceMeta(tenant.settings)?.branchCount`.
If `branchCount > 1`, a Locations item `{ key: 'locations', href: '/{tenantSlug}#branches', isLocations: true }` is injected after the first business item so it appears second in nav.

### Phase E: "Explore Businesses" marketplace re-entry
Marketplace item is always first: `{ key: 'marketplace', href: '/discover', label: 'Explore Businesses', isMarketplace: true }`.
Replaces the hardcoded "Discover" label from P8.8.11.1.

### Phase F: Business type badge in TenantHeader
`getBusinessTypeBadge(tenant.businessTypes)` returns `'☕ Cafe'`, `'🍽️ Restaurant'`,
`'🚚 Food Truck'`, etc., or `null` if unknown type. Rendered beside the tenant name
in the logo section.

### Phase G: `getSmartCTA()` — centralized hero CTA logic
Priority rules (applied in this order):

| Flags | Primary | Secondary |
|---|---|---|
| `branchCount > 1` + no `branchSlug` | Choose a Location | View Menu (primary branch) |
| `ordering.enabled` + `reservations.enabled` | Order Online | Reserve a Table |
| `reservations.enabled` only | Reserve a Table | View Menu |
| `ordering.enabled` only | Order Online | — |
| `menu.enabled` only | View Menu | — |
| nothing | — | — |

Both `BranchHomepageClient.HeroSection` and `TenantHomepageClient.HeroSection` now
use `getSmartCTA()`. Neither contains inline CTA business logic.

### Phase G (bug fix): Feature flag source
Both hero components previously read `tenant.settings?.featureFlags` (raw setting
overrides only — missing module defaults and capability-derived flags).

Fixed to use `useTenantStore((s) => s.featureFlags)` — the fully resolved map that
merges module defaults + capability flags + tenant overrides.

### Phase H: Active state
- Marketplace (`/discover`): exact match `pathname === '/discover'`
- Business routes: `pathname.startsWith(branchAwareHref)` — correct for branch paths
- Locations (`#branches`): hash is not in pathname — never active (acceptable, section anchor)

### Phase I: Website Builder nav config
`buildTenantNavigation()` accepts `layoutNavConfig?: TenantNavItemConfig[]` from
`HomepageLayout.navItems`. When present:
1. Items with `enabled: false` are removed
2. Custom `label` overrides are applied
3. Items are reordered by `order` field

`TenantHeader` reads layout via `useHomepageLayout(tenant.slug)` and passes
`layout?.navItems` to `buildTenantNavigation()`.

### Phase J: TenantHeader is a pure renderer
`TenantHeader` calls `buildTenantNavigation()` once and maps the result.
It applies no nav business logic — no inline href construction, no feature flag
reads for nav, no CTA calculations.
