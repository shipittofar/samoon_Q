# P8.8.12 — Complete Public UX & Interaction Polish: Audit

## Scope

Every public customer-facing surface: 404 page, global error page, UI component library, loading skeletons, navigation header animations, accessibility landmarks, ARIA attributes, copy states, icon semantics, section headings, color token consistency.

---

## Identified Issues

### U1 — not-found.tsx: Typo "Lets" (HIGH)
**File:** `src/app/not-found.tsx`  
**Problem:** "Lets get you back on track" missing apostrophe.  
**Fix:** "Let's get you back on track."

### U2 — not-found.tsx: Broken CTA link `/menu` (HIGH)
**File:** `src/app/not-found.tsx`  
**Problem:** "Browse Menu" linked to `/menu` — a route that 404s in any tenant context; no global menu page exists.  
**Fix:** Changed to `/discover` with label "Browse" so customers reach the marketplace.

### U3 — not-found.tsx: Missing `aria-hidden` on decorative emoji/icon (MEDIUM)
**File:** `src/app/not-found.tsx`  
**Problem:** 🍽️ emoji and `<Home>` icon lacked `aria-hidden="true"`, causing screen readers to announce "fork and knife with plate" decorative content.  
**Fix:** Added `aria-hidden="true"` to emoji span and icon.

### U4 — not-found.tsx: No `<nav>` landmark around recovery CTAs (MEDIUM)
**File:** `src/app/not-found.tsx`  
**Problem:** Two CTA links with no landmark container — screen reader users couldn't jump to recovery actions via landmark navigation.  
**Fix:** Wrapped links in `<nav aria-label="Recovery options">`.

### U5 — error.tsx: Hardcoded `bg-orange-500` (HIGH)
**File:** `src/app/error.tsx`  
**Problem:** "Try Again" button used `bg-orange-500 hover:bg-orange-600` instead of design tokens. Breaks in tenant themes with non-orange accent.  
**Fix:** `bg-[var(--accent)] hover:bg-[var(--accent-hover)]`.

### U6 — error.tsx: "Our team has been notified" misleading claim (LOW)
**File:** `src/app/error.tsx`  
**Problem:** Copy implies automatic error reporting; no such integration exists (only `console.error`). Trust-breaking on error page.  
**Fix:** Removed that sentence. Copy is now "An unexpected error occurred. Please try again."

### U7 — error.tsx: Missing `aria-hidden` on emoji/icons (LOW)
**File:** `src/app/error.tsx`  
**Problem:** 💥 emoji and icons not hidden from assistive technology.  
**Fix:** Added `aria-hidden="true"`.

### U8 — Button.tsx: Hardcoded `focus-visible:ring-orange-500` (HIGH)
**File:** `src/components/ui/Button.tsx`  
**Problem:** Focus ring color hardcoded to orange — breaks visual consistency in non-orange tenant themes.  
**Fix:** `focus-visible:ring-[var(--accent)]`.

### U9 — Avatar: No `onError` fallback (MEDIUM)
**File:** `src/components/ui/index.tsx`  
**Problem:** Broken image URLs show browser's default broken-image icon inside the avatar circle, overriding initials fallback.  
**Fix:** Added `onError` handler that hides the `<img>` so the initials background becomes visible.

### U10 — TenantHeader: Framer Motion animations ignore `prefers-reduced-motion` (HIGH)
**File:** `src/components/layout/TenantHeader.tsx`  
**Problem:** Theme-toggle rotation, dropdown scale/translate animations run unconditionally. Violates WCAG 2.3.3 (AAA) and causes vestibular discomfort.  
**Fix:** Added `useReducedMotion()` from framer-motion; conditional `initial`/`exit` transforms and `duration: 0` when reduced motion is preferred.

### U11 — LoadingSkeleton (Tenant): Low fidelity, no ARIA status (HIGH)
**File:** `src/app/[tenantSlug]/TenantHomepageClient.tsx`  
**Problem:** Three lines of placeholder for a full-page layout. No `role="status"` or `aria-label` — screen readers cannot announce loading state.  
**Fix:** Upgraded to a full-fidelity skeleton matching page structure (hero, QuickActions row, menu grid, secondary section). Added `role="status" aria-label="Loading page content"` with `sr-only` "Loading…" text.

### U12 — BranchSkeleton: Same issues (HIGH)
**File:** `src/app/[tenantSlug]/[branchSlug]/BranchHomepageClient.tsx`  
**Problem:** Three-line skeleton for a two-column branch layout. No ARIA.  
**Fix:** Upgraded to two-column skeleton (main content + sidebar). Added `role="status" aria-label="Loading branch page"`.

### U13 — BranchInfo: `<div>` instead of `<section aria-labelledby>` (MEDIUM)
**File:** `src/app/[tenantSlug]/[branchSlug]/BranchHomepageClient.tsx`  
**Problem:** `BranchInfo` used a plain `<div>` with an `<h2>` inside — no landmark, assistive-tech users cannot navigate to "Branch Information" via section navigation.  
**Fix:** Changed to `<section aria-labelledby="branch-info-heading">` with matching `id` on heading.

### U14 — BranchSwitcher: Same landmark issue (MEDIUM)
**File:** `src/app/[tenantSlug]/[branchSlug]/BranchHomepageClient.tsx`  
**Problem:** `BranchSwitcher` used a plain `<div>` container.  
**Fix:** `<section aria-labelledby="branch-switcher-heading">` with `id="branch-switcher-heading"` on the "Locations" heading.

### U15 — ShareButton: "Copied!" state not announced to screen readers (MEDIUM)
**File:** `src/app/[tenantSlug]/[branchSlug]/BranchHomepageClient.tsx`  
**Problem:** Visual "Copied!" label and check icon appear when clipboard copy succeeds, but no live region announces the state change to AT users.  
**Fix:** Added `<span role="status" aria-live="polite" className="sr-only">` that changes from empty to "Link copied to clipboard" when `copied` is true.

### U16 — Category emoji: Double-announce with link `aria-label` (MEDIUM)
**File:** `src/app/[tenantSlug]/TenantHomepageClient.tsx`  
**Problem:** Category link had `aria-label="Browse {cat.name}"` AND the emoji span had `role="img" aria-label={cat.name}`. Screen readers announced the category name twice.  
**Fix:** Changed emoji span to `aria-hidden="true"` — the link label provides the full accessible name.

### U17 — Gallery transition duration inconsistency (LOW)
**File:** `src/app/[tenantSlug]/TenantHomepageClient.tsx`  
**Problem:** Tenant gallery used `duration-500` for hover scale; BranchHomepageClient used `duration-300`. Inconsistent tactile feel.  
**Fix:** `duration-300` to match branch page.

## Flows with No Issues Found

- **Breadcrumbs:** Correct `aria-label="Breadcrumb"` and hierarchy on all public pages.
- **Hero CTAs:** `getSmartCTA()` correctly produces the highest-priority CTA. `<Button>` component used consistently.
- **Journey engine:** No issues — ordering and CTA priority correct per business type.
- **Website Builder:** Override precedence respected everywhere.
- **Feature flags:** Gating correct; null CTAs handled gracefully.
- **SEO / JSON-LD:** Metadata builders unchanged and correct.
- **TenantFooter:** Dynamic links rendering correctly with feature flag gating.
- **Skip-to-content:** Present in TenantHeader with correct `href="#main-content"`.
