# P8.7.5 Context Audit — Tenant & Branch Context Architecture

## Executive Summary

This document is the Phase A pre-change audit of the Samoon platform's tenant and branch context architecture. It identifies every structural gap that P8.7.5 addresses before a single line of production code changes.

---

## 1. Current Store Architecture

### useTenantStore (`src/stores/index.ts`)

**Persisted:** `tenant` only  
**Runtime-only (reset on every page load):** `tenantState`, `rbacInitialized`, `featureFlagsInitialized`, `featureFlags`

```typescript
interface TenantState {
  tenant: Tenant | null                // persisted
  tenantState: TenantLifecycle         // runtime: 'loading' | 'ready' | 'fallback'
  rbacInitialized: boolean             // runtime
  featureFlagsInitialized: boolean     // runtime
  featureFlags: Record<string, boolean> // runtime
  loadTenant: (slug?: string) => Promise<void>
  setTenant: (t: Tenant | null) => void
  setFeatureFlags: (f: Record<string, boolean>) => void
  setRbacInitialized: (v: boolean) => void
  setFeatureFlagsInitialized: (v: boolean) => void
}
```

**Status:** Robust. Single source of truth for tenant lifecycle.

### useBranchStore (`src/stores/index.ts`)

```typescript
interface BranchState {
  activeBranch: Branch | null    // Branch = Location (public type)
  setActiveBranch: (b: Branch) => void
}
```

**Gap 1:** Only tracks public-facing `Branch` (= `Location` type). Does NOT track the admin-selected `AdminBranch` (from `types/branch.ts`) with full data like `settings`, `businessHours`, `status`, `tenantId`.  
**Gap 2:** No `adminActiveBranch` concept. Admin has no branch context.  
**Gap 3:** `BranchSelector` in public header shows ALL branches with no RBAC filtering.

### useAuthStore (`src/stores/index.ts`)

```typescript
interface AuthState {
  user: User | null
  isAuthenticated: boolean
  isLoading: boolean
}
```

**Gap 4:** `User.role` is a single global value (`customer | staff | admin`). No per-tenant role at user level. Multi-tenant RBAC relies entirely on `useRbacStore`.

## 2. Admin Context Architecture Gaps

### Gap 5: No Admin Branch Switcher
- The admin has no UI to switch branches
- A branch manager on the admin orders page has no way to filter by branch from a single control
- Admin pages accept `branchId` as a query param but there is no central branch context selector

### Gap 6: No Tenant Switcher
- Platform administrators cannot switch between tenants in a single session
- Switching tenants requires changing the environment variable or subdomain
- The `useTenants()` hook exists and `tenantService.getTenants()` returns the full list, but no UI exists to switch

### Gap 7: PreviewButton Uses Hardcoded Flat URLs
All current `PreviewButton` usages:

| `admin/menu/page.tsx` | `/menu` |
| `admin/branches/page.tsx` | `/restaurant` |

**Gap 8:** Every single preview link navigates to a flat public URL with no tenant or branch context in the URL. If two tenants are running on the same dev server, the preview always opens the default tenant.

## 4. Query Key Analysis

### Current Patterns
```typescript
queryKey: ['admin-orders', filters]              // no tenant, no branch
queryKey: ['admin-reservations', filters]        // no tenant, no branch
queryKey: ['admin-branches', tenantId]           // has tenantId ✓
queryKey: ['admin-branch', id]                   // no tenantId
queryKey: ['branch-orders', branchId]            // has branchId ✓
queryKey: ['menu-items', filters]                // no tenant
queryKey: ['branches']                           // no tenant
queryKey: ['tenants']                            // global (correct — platform-level)
queryKey: ['audit-logs', filter]                 // no tenant
```

**Gap 10:** Admin queries for orders, reservations, menu, and audit logs do not include `tenantId` or `branchId` in the query key. If a platform admin switches tenants, the cache from Tenant A may be returned for Tenant B.

## 6. Middleware

`src/middleware.ts` resolves tenant from:
1. Subdomain (production)
2. `NEXT_PUBLIC_TENANT_SLUG` env var (development)
3. Falls back to `DEFAULT_TENANT`

**Gap 11:** No path-based tenant resolution. The new `/[tenantSlug]/[branchSlug]/...` routes must handle their own context initialization client-side since middleware only injects `X-Tenant-Slug` for subdomain-resolved tenants.
