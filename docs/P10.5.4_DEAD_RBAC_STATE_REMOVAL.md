Acts on the audit findings from `docs/P10.5.3_PERMISSION_MODEL_CONSOLIDATION.md`
by removing state proven dead via fresh, repository-wide usage analysis.
No authorization behavior changes. No UI regressions.

## Justification Summary

`branchRoles` and `roleAssignments` were removed because repository-wide
analysis proved zero application-code consumers exist for either field —
no page, hook, component, or service reads or writes them outside the
store's own definition and the four test files updated in Phase G. Their
removal cannot change any permission decision because no permission
decision ever consulted them. `customRoles` was deliberately kept because
it has one live write call site (`app/console/roles/new/page.tsx`) whose
removal would visibly break the Console's "Create Custom Role" form,
violating the task's explicit stop condition. `ROLE_TEMPLATES`,
`tenantRoles`, and `userOverrides` were left untouched per the forbidden
list in Phase D — all three are live, load-bearing, and out of scope.

The repository behaves identically from the user's perspective after this
phase, except that the two verified-dead RBAC state fields — and the
localStorage bytes they previously occupied under the `savor-rbac`
persistence key — no longer exist.
