## Phase A — Section-by-Section Audit

---

### 1. First Impression (5-Second Test)

**Score: 5.0 / 10**

Within 5 seconds a visitor can determine:
- ✅ Branch name (visible in hero headline)
- ✅ Open/Closed status (badge in hero)
- ✅ Today's hours (small text in hero)
- ❌ WHERE it is (address is absent from hero — only in sidebar, below the fold on mobile)
- ❌ WHY to choose THIS branch (no branch identity, no neighborhood, no differentiator)
- ❌ What to DO next (zero CTAs in the hero)

The hero answers "who" but not "where" or "what next."

Google Maps, Apple Maps, and Booking.com all display full address + map thumbnail in the top card. The branch hero here forces the user to scroll past the Quick Actions bar and into the sidebar to find out where they're going.

---

### 2. Branch Identity

**Score: 5.0 / 10**

There is no branch-specific identity. The page shows:
- Branch name
- The tenant's business name (as a subtitle)
- Open/Closed status

What is missing:
- Neighborhood / area context (e.g. "Downtown", "Airport Terminal 2", "Westfield Mall")
- Branch-specific description or "what makes this location unique"
- Floor, unit, or landmark context
- Parking / transit hints specific to this branch
- Whether this branch offers drive-through, outdoor seating, etc.

Every branch currently looks identical in structure and content. A "Flagship" branch and a "Food Court" kiosk render the same template with the same tenant-wide gallery. This creates a commoditized, low-trust experience — the opposite of what Booking.com's per-property pages achieve.

---

### 3. Hero

**Score: 5.2 / 10**

Positive:
- Branch name is the `<h1>`
- Tenant name shown as subtitle — good parent-child hierarchy
- Open/Closed badge visible
- Today's hours shown
- Graceful fallback gradient when no image

Negative:
- **Hero height is too short** — `h-64` (256px) on mobile, `md:h-80` (320px) on desktop. The tenant homepage uses `h-[55vh] min-h-[340px] max-h-[600px]`. This jarring size difference signals a "lesser" page that hurts user trust.
- **Zero CTAs in the hero** — Every hospitality benchmark (Booking.com, OpenTable, Airbnb) places the primary action inside the hero. The branch page has nothing. CTAs appear below in a separate Quick Actions section, often below the fold on mobile.
- **Hero image uses raw `<img>`** — No `next/image`, no `priority` attribute. This is the LCP element and it loads without optimization.
- **Address absent from hero** — The single most critical piece of location information is not in the first thing users see.
- **`aria-labelledby` missing** — `<section>` has no `aria-labelledby` linkage to the h1.
- **Hero tagline absent** — The tenant's tagline (from `meta.tagline`) is not shown; there's no branch-specific equivalent either.

---

### 4. Branch Information

**Score: 5.5 / 10**

The `BranchInfo` sidebar panel shows:
- ✅ Address (two lines)
- ✅ Phone (clickable tel: link)
- ✅ Today's hours
- ✅ Map placeholder (opens Google Maps)
- ❌ Full week hours — not available in `PublicBranchInfo` type (shows only today)
- ❌ Parking — not in `PublicBranchInfo`
- ❌ Accessibility — not in `PublicBranchInfo`
- ❌ Delivery zones — not in `PublicBranchInfo`
- ❌ Pickup availability — not shown
- ❌ Outdoor seating — not shown
- ❌ Amenities — not pulled through to branch level (only on `MarketplaceMeta`)

The map placeholder (`h-36 rounded-lg`) is too small to convey meaningful spatial context. It is a text label with a pin icon — not an actual embedded map or a street-level preview. Booking.com shows a 200px static map thumbnail. Google Maps shows a live embedded tile.

The panel also has an accessibility bug: the map div uses `role="button"` and `onClick` but no `onKeyDown` handler, failing WCAG 2.1 SC 4.1.2 (Name, Role, Value).

---

### 5. Quick Actions

**Score: 5.8 / 10**

The Quick Actions bar contains: View Menu · Reserve Table · Order Online · Call · Directions · Share · Copy URL

Positive:
- Directions uses a real Google Maps deep-link — excellent
- Call links to `tel:` — excellent
- Share / Copy URL offer both Web Share API and clipboard fallback

Negative:
- **"View Menu" and "Order Online" both link to `/${tenantSlug}/${branchSlug}/menu`** — identical destinations. This is redundant and dilutes user attention. One CTA should be removed; alternatively "Order Online" should link to the order/delivery flow if one exists.
- **"Reserve Table" is always shown** — regardless of whether reservations are enabled for this tenant (`featureFlags['reservations.enabled']`). Clicking it always links to `/reservation` even for tenants that don't accept reservations.
- **Secondary actions crowd primary actions** — "Share" and "Copy URL" are utility actions, not conversion actions. They should be de-emphasized (smaller, or in a `...` overflow menu) so "View Menu" and "Reserve" have clear visual priority.
- **Actions are equal weight** — Every button looks the same. Best practice (Uber Eats, DoorDash) is to give the primary action a filled style and secondary actions outlined/ghost styles.

---

### 6. Menu Entry

**Score: 6.5 / 10**

Menu entry exists in three places:
1. Quick Actions bar — "View Menu" (primary CTA, filled)
2. Quick Actions bar — "Order Online" (duplicate, identical destination)
3. FeaturedMenuSection — "Full Menu" link at top-right

This is actually reasonably discoverable. The main issue is that on mobile, the Quick Actions bar may scroll off screen once the user is reading the FeaturedMenuSection. There is no sticky menu CTA while scrolling.

The FeaturedMenuSection shows 6 items in a 2-column grid. Items show name + price. No category context. Users can't tell if the 6 shown items match their preferences without clicking through to the full menu.

Price display bug: `item.price / 100` is used here, while the tenant homepage uses `item.price.toFixed(2)`. The API likely returns prices in dollars (not cents), so dividing by 100 would display $0.12 instead of $12.00. This is a data integrity concern.

---

### 7. Reservation Entry

**Score: 5.5 / 10**

- "Reserve Table" CTA appears in Quick Actions
- There is no reservation state shown (available times, party size, date picker preview)
- The CTA is always shown — even if the business doesn't accept reservations (no feature flag check)
- OpenTable, Booking.com, and Resy all show inline availability on the listing page itself (e.g. "Next available: Tonight 7:30 PM, 8:00 PM, 8:30 PM"). Savor shows none of this.
- No indication of whether reservations are required vs preferred vs walk-in only.

---

### 8. Location Confidence

**Score: 4.8 / 10**

This is the weakest dimension. Users deciding whether to physically visit a location need to trust that they can find it, park, and get there efficiently.

Current state:
- Address shown in sidebar BranchInfo (not in hero)
- "View on Map" placeholder opens Google Maps in a new tab
- No map thumbnail or static map image
- No nearby landmarks
- No parking information
- No transit information
- No distance from user's location
- No popular times / busy hours
- No street-level imagery hint

Benchmark: Google Maps shows a satellite thumbnail, driving time, walking time, transit options, popular times histogram, and "directions" call to action — all on the listing card. Apple Maps shows a map preview immediately. Booking.com shows a map with neighborhood pins.

Savor's branch page has a gray placeholder box that says "View on Map." This is the UX equivalent of giving someone a street address and saying "use a map app."

---

### 9. Reviews

**Score: 6.0 / 10**

- `ReviewsSection` is rendered with `branchId={branchSlug}` — the prop is passed, suggesting branch-specific review scoping is intended
- The `initialRating` and `initialReviewCount` come from `meta.rating` and `meta.reviewCount` — these are **tenant-wide** averages stored in `MarketplaceMeta`. A specific branch could have a different rating. This creates a mismatch: the branch page shows the tenant's aggregate score, not that branch's score.
- Reviews appear at position 4 in the main column (after Featured Items, Categories, Promotions). This is too far down — reviews are trust signals that should appear earlier (position 2 or 3), before promotions.

---

### 10. Gallery

**Score: 3.5 / 10 — Most Critical Content Issue**

```tsx
const gallery = meta?.gallery ?? []
// ...
{gallery.length > 0 && <GallerySection images={gallery} />}
```

**Every branch shows the same tenant-wide gallery.** `meta.gallery` is a field on `MarketplaceMeta`, which belongs to the tenant — not the branch. `PublicBranchInfo` has no `gallery` field. This means:
- The Downtown branch and the Airport branch show identical photos
- Users cannot see what THIS branch looks like
- If no gallery images exist at tenant level, the section is hidden entirely (missing single-photo businesses issue also present here)
- Gallery uses raw `<img>` with `loading="lazy"` — no `next/image`

Benchmark: Booking.com shows hotel-room-specific photos, floor plans, and 360° views per property. Airbnb shows host-uploaded photos specific to the exact listing. Google Maps shows photos tagged to a specific business location.

The fix at the data model level is to add a `gallery?: string[]` field to `PublicBranchInfo`. Short of that, the branch hero image (`branch.image`) should be used as a branch-specific photo, and the tenant gallery should be clearly labeled as "Business Gallery" rather than implying branch-specific imagery.

---

### 11. Promotions

**Score: 5.8 / 10**

- Promotions are fetched via `useActivePromotions()` — presumably tenant-wide
- Promo cards show: type badge, name, description — but **no CTA to use the offer**
- There is no branch-specific promotion vs tenant-wide promotion distinction
- No discount value shown (unlike the tenant homepage which showed `{promo.discountPercent}% off`)
- "All Offers" link goes to `/${tenantSlug}/${branchSlug}/promotions`

Issues:
- Promo cards are dead ends — no "Use this offer" link
- No visual hierarchy difference between 10% off and BOGO offers
- Discount values (discountPercent, discountAmount) are not displayed, making it impossible to evaluate the offer without clicking through

---

### 12. Branch Switching

**Score: 6.5 / 10**

`BranchSwitcher` component:
- Shows all other branches (excludes current)
- Renders name, address, city, and Open/Closed badge
- Links to each branch homepage

Positive:
- Exists and is functional
- Open/Closed badge aids quick comparison

Negative:
- **No "current branch" indicator** — The switcher only shows OTHER locations. There is no visual confirmation of which branch the user is currently viewing. Booking.com always shows "You are viewing: [Property Name]" with a checkmark or highlighted state.
- **No distance shown** — Without distance/travel time, users can't make a rational choice between branches
- **No today's hours on switcher entries** — `b.todayHours` is available in `PublicBranchInfo` but not displayed in the switcher
- **Placed in sidebar, below BranchInfo** — On mobile, this is extremely far from the top. A branch switcher should be accessible from the hero or breadcrumb level

---

### 13. Information Hierarchy

**Current order:**
1. Header
2. Breadcrumb
3. Hero (image, name, open/closed, hours)
4. Quick Actions (full-width bar)
5. [Main] Featured Menu Items
6. [Main] Categories
7. [Main] Promotions
8. [Main] Reviews
9. [Main] Gallery
10. [Sidebar] Branch Info (address, phone_number, hours, map)
11. [Sidebar] Branch Switcher

**Problems:**
- Address is in position 10 — a critical location trust signal shown after content about food
- Reviews are in position 8 — trust signals should appear higher
- Gallery comes after reviews — visual evidence should appear higher
- Promotions are in position 7, before reviews — offers that require trust to act on are shown before trust is established
- Branch Info sidebar on desktop is simultaneously shown alongside main content (positions 5–9), but on mobile it stacks below everything

**Expected order (per spec):**
1. Hero (with CTA, address, status)
2. Trust signals (rating / reviews preview)
3. Menu CTA
4. Reservation CTA
5. Branch Details (full address, hours, map)
6. Reviews
7. Gallery
8. Promotions
9. Related Branches (switcher)
10. Footer

---

### 14. Navigation

**Score: 6.5 / 10**

Positive:
- Breadcrumb: Discover → Tenant → Branch (3-level, correct)
- Breadcrumb uses real navigation links, not just text
- "Back to Business" in not-found state

Negative:
- No sticky header CTA when user scrolls (no fixed "View Menu" button)
- No anchor links in the page (cannot jump to Reviews, Gallery, etc.)
- No "back to top" control for long pages
- Breadcrumb wraps on mobile — could truncate parent names more aggressively

### CRITICAL Issues

---

**C1 — Zero CTAs in Hero**

| | |
|---|---|
| Severity | Critical |
| Problem | HeroSection has no action buttons. CTAs live in a separate Quick Actions bar below the fold on mobile. |
| Evidence | `HeroSection` renders only identity (name, status, hours) — no Link or button |
| UX Impact | Users see the hero and have no next step visible. They must scroll to discover actions. |
| Business Impact | Every 100ms of additional friction before the first click reduces conversion. Industry standard (Booking.com, Google Maps, OpenTable) is to embed the primary action IN the hero. |
| Conversion Impact | High — estimated 15–25% conversion uplift from adding hero CTAs (Booking.com A/B data) |
| Solution | Add "View Menu" (primary, filled) and "Directions" (secondary, ghost) CTAs to the hero overlay, bottom-left alongside the branch name. Mirror what was done for the tenant homepage in P8.8.9 C1. |
| Complexity | Low |
| Expected Improvement | +2.0 conversion score |

**C2 — Address Absent From Hero**

| | |
|---|---|
| Severity | Critical |
| Problem | Branch address is only in the sidebar BranchInfo card — not in the hero. On mobile this is below the fold. |
| Evidence | `HeroSection` shows `branch.name`, `branch.openNow`, `branch.todayHours` but NOT `branch.address` or `branch.city` |

**C3 — Hero Image Uses `<img>` Without Optimization**

| | |
|---|---|
| Severity | Critical |
| Problem | HeroSection uses a raw `<img>` element. The branch hero is the LCP element — the most impactful image on the page for Core Web Vitals. |
| Evidence | Line 45: `<img src={branch.image} alt={branch.name} className="absolute inset-0 w-full h-full object-cover opacity-70" />` |

| Business Impact | Core Web Vitals score (LCP) directly affects Google search ranking. |
| Conversion Impact | Medium — slow LCP increases bounce rate |
| Solution | Replace with `<Image fill priority sizes="100vw" />` from `next/image`. Also fix alt text to `alt="" aria-hidden="true"` (decorative). |
| Complexity | Low |
| Expected Improvement | +1.0 performance score |

**C4 — Gallery Shows Tenant-Wide Images on Every Branch**

| | |
|---|---|
| Severity | Critical |

**C5 — Reserve Table Always Shown (No Feature Flag Check)**

| | |

| Problem | "Reserve Table" appears in Quick Actions for all tenants, regardless of whether reservations are enabled. |

### MEDIUM Issues (backlog)

**M1 — `PublicBranchInfo` Missing `gallery` Field**  
Adding `gallery?: string[]` to `PublicBranchInfo` would enable true branch-specific photo galleries. Requires data model change and admin UI update. Complexity: Medium.

**M2 — Sticky "View Menu" CTA on Scroll**  
As users scroll past Quick Actions, no persistent menu entry exists. A sticky header micro-bar (like Uber Eats) with the branch name and "Order" CTA would maintain conversion intent throughout. Complexity: Medium.

**M3 — Inline Availability Widget in Reservation CTA**  
Instead of a "Reserve Table" link that leads to a separate page, showing next 2–3 available time slots inline (like OpenTable) would dramatically increase reservation conversion. Complexity: High.

**M4 — Popular Times Histogram**  
Showing when a branch is busiest (by hour/day) helps customers plan their visit — a strong Google Maps pattern. Requires operational data. Complexity: High.

**M5 — `branch.image` as Gallery Cover**  
The branch-specific `branch.image` field is only used in the hero. It should also appear as the first image in the gallery / as a "This location" section above the tenant gallery. Complexity: Low.

### LOW Issues (backlog)

`bg-gray-200 dark:bg-gray-700` instead of `var(--card)` / `var(--bg-secondary)` design tokens.

**L5 — `BranchInfo` Panel `h2` Heading Not Font-Display**  
"Branch Information" heading is `font-semibold text-[var(--fg)]` without `font-display` or size upgrade.
