# P8.9.2 — Phone Authentication UX Foundation: Audit

## Current State

### Login page (`/login`)
- Two-column layout (form left, orange hero right). Desktop-first; collapses to single column on mobile.
- Primary flow: email + password via `react-hook-form` + `zod`.
- Demo grid: 10 cards with role label, description, phone number (P8.9.1). One-click mock login.
- No phone number input. No country selector. No OTP flow.
- `AnimatePresence` not used — single fade-in entrance only.
- The hero panel is hidden on mobile, wasting visual weight on small screens.
- Rate limiter (`LOGIN_LIMIT`) is correctly placed but the error UX (toast) is non-standard for auth flows — native inline errors are better.
- "Don't have an account?" link to `/register` — contradicts the "unified auth" goal.

### Register page (`/register`)
- Separate URL and separate form (name, email, phone, password, confirm password) — forces users to know whether they're new.
- Phone field is `<Input type="tel">` with placeholder `"+1 234 567 8900"` — no country selector, no formatting, no validation beyond `min(10)`.
- Separate page for a scenario the system should detect automatically.

### Forgot Password page (`/forgot-password`)
- Email-only; slides to a "check your email" confirmation using `AnimatePresence`.
- No phone recovery option. Out of scope for phone-first auth.

### OTP page (`/verify-otp`)
- 6 raw `<input>` elements — auto-advance, backspace navigation, paste support. Solid mechanics.
- Reads phone from `?phone=` query param — correct pattern.
- 60-second countdown and resend.
- No connection from the current login page — no page navigates to it with a phone.
- Spring animation on shield icon entrance only.
- Missing: invalid code state, expired state, success animation, `inputMode="numeric"`.

### Registration Completion
- Does not exist as a distinct step — all fields collected upfront during register.

## UX Issues

| # | Severity | Issue |
|---|---|---|
| U1 | CRITICAL | Login/Register/Forgot Password are three separate pages — user must choose. |
| U2 | CRITICAL | No international phone input with country code selector. |
| U3 | CRITICAL | No unified phone → OTP → account (login/register) flow. |
| U4 | HIGH | Register phone field has no country code, no validation, no formatting. |
| U5 | HIGH | OTP page exists but no page in the app links to it. |
| U6 | HIGH | No profile completion step for first-time users. |
| U7 | HIGH | Demo cards are functional but their phone numbers are display-only — there's no "enter this phone number" flow. |
| U8 | MEDIUM | Login page hero panel wasted on mobile. |
| U9 | MEDIUM | OTP page missing invalid/expired/success states. |
| U10 | MEDIUM | No `inputMode="numeric"` on OTP digits — native keyboard is wrong on Android. |
| U11 | MEDIUM | No recent countries or locale detection for country selector. |
| U12 | LOW | "Don't have an account?" + "Forgot password?" links encourage wrong mental model. |
| U13 | LOW | Toast for rate limit error is non-standard — inline error is better. |

## Competitor Benchmark

### Uber
- Single phone number field as the entire first screen. No email, no password visible.
- Country picker: flag + country code inline with the input, opens a searchable bottom sheet.
- After entry: 4-digit OTP (different from spec's 6-digit, but same UX pattern).
- OTP screen: headline "Enter the 4-digit code sent to {phone}" — clear, honest about source.
- No registration distinction — Uber decides if it's signup or login.
- Loading: inline on the "Next" button, not a full-page spinner.

### WhatsApp
- Country picker: searchable list, keyboard navigation, flag + name + code. Recent at top.
- Phone input: plain national number, auto-formatted per country.
- After entry: "We will send an SMS" with a `[Next]` button — sets clear expectations.
- OTP screen: "Waiting for SMS" with auto-fill from Android SMS listener.
- 6-digit code with timer and "Resend SMS" link.
- Profile completion (name + avatar) appears only for new users.

### Telegram
- Similar to WhatsApp but with an animated Telegram logo and smooth screen-to-screen transitions.
- OTP can be "delivered via Telegram" if account exists — fallback to SMS otherwise.
- Error state: code box shakes horizontally. Clean, tactile.

### Airbnb
- Offers phone OR email — neither is forced. Tabs clearly labeled.
- Phone: flag selector + national input. E.164 submission.
- OTP: 6-digit, auto-submit on completion. No "Verify" button needed.
- New user after OTP: displays a multi-step profile completion.
- Error: inline below the OTP boxes, red accent.

### Booking.com
- Email-first, then "continue with phone" as secondary option.
- OTP: simple 4-digit with large tap targets. Mobile-first.
- "We sent you a code" with masked phone number for security.

### Stripe Identity
- Step-by-step with progress indicator.
- Phone input: validates and shows green checkmark before submit.
- Loading states are inline — the button transforms into a loader.
- Error copy is specific: "The code you entered doesn't match" not generic "Invalid code."

## Gaps vs. Production Best Practices

| Dimension | Current | Required |
|---|---|---|
| Auth flow | Three pages | Single phone-first unified page |
| Phone input | Raw `type="tel"` | Flag + country code + formatted national + E.164 output |
| Country selection | None | Searchable modal/sheet, recent countries, locale detection |
| OTP mechanics | Basic (/verify-otp) | Full state machine: pending, verifying, invalid, expired, success |
| OTP auto-submit | No | Yes — submit when 6th digit entered |
| New user detection | None | `isNewUser` flag from mock verifyOTP |
| Profile completion | None (all at register) | Dedicated minimal step after OTP |
| Error copy | Generic | Specific: "Wrong code", "Code expired", "Too many attempts" |
| Success animation | None | Checkmark scale-in + brief pause before redirect |
| Keyboard nav | Partial | Full: country picker Arrow/Enter/Esc, OTP backspace navigation |
| RTL | Layout supported | Phone input must support logical properties |
| Reduced motion | Partial | All animations conditional on `useReducedMotion()` |
| Screen reader | Basic | Live regions for countdown, OTP state, error announcements |
| `inputMode` | Missing | `"numeric"` on all OTP inputs and phone input |
| Mobile autofill | None | `autoComplete="one-time-code"` on OTP input |

## Architecture Decision

The new phone auth flow will be:

```
/login (unified phone entry)
  └── sendOTP(phone) → navigate to /verify?phone=<e164>
        ├── verifyOTP success, known phone  → setUser() → getDemoRedirect / getPostLoginRedirect
        ├── verifyOTP success, unknown phone → navigate to /complete-profile?phone=<e164>
        │       └── completeProfile() → setUser() → /dashboard
        └── verifyOTP failure → inline error, countdown, retry
```

The legacy `/verify-otp` page is preserved for backward compatibility. The new `/verify` page replaces it for the phone-first flow.

Demo card one-click login bypasses the OTP step (UX speed for developers). Manual phone entry always goes through the OTP screen.
