## Phase J — Confirmed Defects & Fixes

### D-01 — `branchService.getBranches()` not tenant-scoped (CRITICAL)

**Status:** ✅ FIXED

**Root cause:** `branchService.getBranches()` always returned the global `MOCK_BRANCHES` array — 3 savor branches with numeric IDs ('1', '2', '3') — regardless of which tenant was active. `useBranches()` included `tenantId` in the React Query key but passed no argument to the service function, making the query key scoping ineffective.

**Impact:**
- ALL tenants showed savor's branches (Main Branch, Downtown Branch, Airport Branch) in the reservation form
- brew-cafe customers saw incorrect branch addresses and names
- the-oak-bar, central-food-court, wheels-and-brews, road-bites had no matching branches shown

**Fix:**
1. Added `MOCK_TENANT_BRANCHES: Record<string, Branch[]>` to `src/lib/mock-data.ts` with correct branches for all 6 tenants, using `id = slug` for branch identity
2. Updated `branchService.getBranches(tenantId?: string)` in `src/services/combined.service.ts` to return `MOCK_TENANT_BRANCHES[tenantId]` when tenantId is provided and known, falling back to `MOCK_BRANCHES`
3. Updated `useBranches()` in `src/hooks/index.ts` to pass `tenantId ?? undefined` to the service

---

### D-02 — Branch ID format mismatch between `activeBranch.id` and branch list

**Status:** ✅ FIXED (as part of D-01)

**Root cause:** `publicBranchToLocation` (used by `TenantBranchLayout` since P8.7.7.6.1) sets `id: b.slug` (e.g., `'main'`, `'brooklyn-cafe'`). But `MOCK_BRANCHES` (the old branch source) had numeric string IDs (`'1'`, `'2'`, `'3'`). The form's `selectedBranch === branch.id` comparison always failed: `'main' !== '1'` → no branch was ever highlighted as selected in the UI even when `activeBranch` was correctly set.

Additionally, the success callback `branches?.find(b => b.id === data.branch_id)` with `data.branch_id = 'main'` found no match → `branchName = ''` in the confirmation URL.

**Fix:** `MOCK_TENANT_BRANCHES` uses `id = slug` for all branches — consistent with `publicBranchToLocation`. The comparison now works correctly.

---

### D-03 — Hardcoded fallback `'1'` when no activeBranch

**Status:** ✅ FIXED

**Root cause:** `useState(() => activeBranchId ?? '1')` and `defaultValues: { branch_id: activeBranchId ?? '1' }` — when `activeBranch` was null (e.g., direct root `/reservation` visit), the form silently pre-selected branch id `'1'` (a savor-specific hardcoded value), which would be submitted as `branch_id: '1'` even for other tenants.

**Fix:** Changed fallback to `''` (empty string). Zod schema requires `branch_id: z.string().min(1, 'Branch is required')` — submitting without a branch selection now shows a validation error, forcing the user to explicitly choose.
