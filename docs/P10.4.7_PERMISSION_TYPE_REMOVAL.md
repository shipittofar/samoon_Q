# P10.4.7 — Remove Superseded Legacy `Permission` Type

Removes the obsolete dot-notation `Permission` type from
`src/types/index.ts` per `docs/P10.4.2_REMOVAL_PROOF.md`, leaving
`P7Permission` (`src/types/rbac.ts`) as the single authoritative
permission-string type.

## Discovery (before editing)

`grep -rn "\bPermission\b" src --include="*.ts" --include="*.tsx"`,
excluding `P7Permission`/`LegacyPermission`/`PermissionGuard`/
`PermissionCheckOptions`/`RolePermission`, was run across the entire
`src/` tree. Results:

- **Type declaration/usage**: exactly one — `src/types/index.ts:773`,
  the `export type Permission = ...` block itself. No file imports it,
  no type annotation references it, no generic parameter uses it, no
  component prop is typed with it, no service depends on it.
- **One dead import**: `src/test/phase1b.test.ts:12` — `import type {
  Permission, Tenant, UserRole } from '@/types'`. `Permission` was
  imported but never referenced anywhere in the file (confirmed by
  `grep -n "Permission" src/test/phase1b.test.ts`, which shows only
  `rbacService.hasPermission(...)` calls — a different identifier).
  This was already flagged as a pre-existing `'Permission' is defined
  but never used` ESLint warning, called out (and left untouched, since
  it wasn't yet safe to touch) in the P10.4.5 and P10.4.6 reports.
- **Every other "Permission" match** is either the well-known
  `P7Permission`/`LegacyPermission`/`PermissionGuard`/
  `PermissionCheckOptions` identifiers, a comment/JSDoc word, a UI
  string ("Permission Management", "Permission matrix"), or a
  `describe`/`it` test-suite label — none of these reference the
  `Permission` *type* being removed.

Conclusion: the `Permission` type had zero application/runtime
consumers and exactly one dead (import-only, unused) test reference.
Safe to remove per the SAFE TO DELETE bar established in P10.4.2.

## Removed

**`Permission`** (`src/types/index.ts`, formerly lines 768–797) — the
superseded dot-notation permission-string union type and its preceding
JSDoc block:

```ts
/**
 * P7 permission strings (P7.1 — dot-notation).
 * Authorization formula: Permission AND Capability AND FeatureFlag.
 * This is the canonical Permission type going forward.
 */
export type Permission =
  | 'orders.view'
  | 'orders.manage'
  ... (24 members total)
```

**Reason for removal**: this was a second, independently-maintained
copy of the same dot-notation permission-string set already defined and
actively used as `P7Permission` in `src/types/rbac.ts`. It had no
callers — `permission.service.ts`, `ROLE_PERMISSION_MAP`, all
`usePermission*` hooks, and every application/console page import
`P7Permission` from `@/types/rbac` (or its `@/types` re-export), never
this `Permission` type. Its JSDoc even called out its own successor
("This is the canonical Permission type going forward" — that
forward-looking canonical role has since been fulfilled by
`P7Permission`).

## Replacement

```
Permission (types/index.ts, dot-notation duplicate)
      ↓
P7Permission (types/rbac.ts, canonical — unchanged, already the type
              every real consumer used before this phase)
```

No new type was introduced. `P7Permission` already existed and already
covered every permission string the removed `Permission` type declared;
this phase just deletes the redundant copy.
