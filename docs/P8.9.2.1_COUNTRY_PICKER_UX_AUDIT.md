## 1. Scroll Behavior

### Critical Bug: Background Scroll Not Locked

**Severity: Critical**

When the picker opens, neither `document.body` nor `document.documentElement` receive any scroll-lock treatment. The background page continues to scroll freely under:
- Desktop: mouse wheel
- Desktop: keyboard arrow keys / space
- Mobile: touch scrolling
- Mobile: rubber-band overscroll (iOS)

**Root cause:** No `overflow: hidden` or `touch-action: none` is applied to body/html when the picker mounts. The backdrop `div` has `pointer-events` passthrough for the body scroll container.

**Expected behavior (WhatsApp, Telegram, Stripe, Airbnb):** Body scroll is completely locked while the picker is open. Scroll position is preserved and restored on close.

## 3. Scroll Container

### Issue: The Entire Modal Can Scroll

The `overflow-y-auto` is on the inner list div (`.flex-1.overflow-y-auto`), which is correct in intent. However, because the outer `motion.div` has `overflow-hidden` but no `max-h` enforcement at the flex-level, on some viewports the modal itself scrolls rather than just the list div.

**Correct structure required:**
```
modal (fixed height / max-h, no overflow)
├── header (shrink-0)
├── search (shrink-0)
└── list (flex-1, overflow-y-auto)
```

The header and search already use `shrink-0`, and the list uses `flex-1`. The outer modal container needs `flex flex-col h-full` to constrain properly — currently the `listContent` div has `flex flex-col h-full` but the parent `motion.div` does not enforce `display: flex; flex-direction: column` and does not have `overflow: hidden` explicitly ensuring the list is the only scrollable area.
